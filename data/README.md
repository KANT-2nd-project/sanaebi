# 사내비 요청 처리 분류 데이터 v0.1

직원 300명 이상인 가상의 업무·협업 SaaS 회사 **이음웍스**를 위한 한국어 요청 900건이다. 회사 문서로 안내할 요청, 먼저 되물을 요청, 현재 서비스가 지원하지 않는 요청을 구분한다.

## 파일과 사용법

- [dataset.csv](dataset.csv): 학습·평가용 질문과 단일 정답 라벨. UTF-8 BOM, 900행.
- [dataset-review.csv](dataset-review.csv): 문항별 작성·독립 검수·조정 기록. 모델 입력으로 사용하지 않는다.

```python
import csv

with open("data/dataset.csv", encoding="utf-8-sig", newline="") as f:
    rows = list(csv.DictReader(f))

questions = [row["question"] for row in rows]
labels = [row["label"] for row in rows]
```

| 열 | 용도 |
|---|---|
| `question_id` | 고유 문항 ID. 모델 입력에서 제외 |
| `question` | 현재 사용자 발화 하나. **유일한 모델 입력** |
| `label` | 정답: `SEARCH_KNOWLEDGE`, `CLARIFY`, `UNSUPPORTED` 중 하나 |
| `group_id` | 같은 원형 상황의 표현 변형·대조 질문 묶음. 분할에만 사용 |
| `source` | 합성 데이터 버전과 작성 영역. 모델 입력에서 제외 |
| `review_status` | 전량 `ai_reviewed`. 사람 승인 `approved`와 구분 |

라벨의 기준 문서는 [요청 처리 분류·라벨링 기준 v1.0](../docs/label-taxonomy.md)이다. 서비스 흐름은 [서비스 아키텍처](../docs/service-architecture.md)를 참고한다.

## 라벨 경계

| 라벨 | 건수 | 기준 |
|---|---:|---|
| `SEARCH_KNOWLEDGE` | 300 | 회사 규정·절차·조직·공통 업무도구에 관한 정보 안내 |
| `CLARIFY` | 300 | 현재 발화만으로 대상 또는 원하는 도움을 정하기 어려움 |
| `UNSUPPORTED` | 300 | 개인·조직의 실시간 기록 조회, 실제 실행, 지원 범위와 무관한 요청 |

이전 대화는 입력하지 않는다. 순수 인사와 빈 입력은 제외했고, 인사와 질문이 함께 있으면 실질 요청으로 판단한다. 짧거나 포괄적이어도 유용한 일반 안내가 가능하면 `SEARCH_KNOWLEDGE`다. 낯선 사내 제도명이나 근거 문서의 부재는 `CLARIFY`·`UNSUPPORTED`의 근거가 아니다. 실제 근거의 존재와 답변 가능성은 후속 답변 단계에서 확인한다.

| 대조 | 처리 |
|---|---|
| 연차 신청 방법 / 연차를 신청해 달라는 명령 | `SEARCH_KNOWLEDGE` / `UNSUPPORTED` |
| 잔여 연차를 확인하는 방법 / 실제 잔여 일수 조회 | `SEARCH_KNOWLEDGE` / `UNSUPPORTED` |
| 본인이 제공한 상황에 규정 적용 / 본인의 사내 기록을 찾아 달라는 요청 | `SEARCH_KNOWLEDGE` / `UNSUPPORTED` |
| 낯선 제도 이름을 설명해 달라는 질문 / 선행 맥락 없이 특정 대상을 가리키는 질문 | `SEARCH_KNOWLEDGE` / `CLARIFY` |
| 실제 신청해 달라는 요청 / 신청 방법과 실제 신청을 함께 요구 | `UNSUPPORTED` / `SEARCH_KNOWLEDGE` |

명시적인 정보 요청과 미지원 실행·조회가 섞이면 `SEARCH_KNOWLEDGE`로 보낸다. 이 라벨은 실행을 허용한다는 뜻이 아니며, 답변 단계에서 안내 가능한 부분과 실행할 수 없는 부분을 구분해야 한다. 반대로 순수 실행 명령에 정보 안내 의도를 임의로 덧붙이지 않는다. 실행 의도가 명확하면 인자가 빠져도 `UNSUPPORTED`다. “휴가 신청 도와줘”처럼 설명과 대행 중 원하는 도움이 불명확한 표현은 `CLARIFY`다.

## 작성과 검수

인사·조직, IT·보안, 비용·사무환경을 중심으로 영역을 나누어 GPT-6 Luna 작성 에이전트 3개가 각 300건·라벨별 100건을 작성했다. 인사 영역의 보완 작성자도 GPT-6 Luna다. 전량 신규 합성이며 공개 데이터의 문장 복사·번역·자동 라벨 변환을 하지 않았다. 규정의 내용이나 답변 정답을 확정한 자료가 아니다.

파일럿 90건을 검수·수정한 뒤 810건을 추가했다. 작성에 참여하지 않은 **GPT-6 Luna와 GPT-6 Astra**가 임시 ID와 질문을 무작위 순서로 받아 각각 전체를 검수했다. 후보 라벨·작성자·그룹·상대 검수 결과를 숨겼다. 두 검수의 라벨과 개별 근거, 품질 지적을 그대로 남기고, 불일치·품질 지적은 루트 에이전트가 조정했다. 질문을 바꾼 경우 두 검수자에게 다시 전달했다.

검수 CSV의 `question_sha256`은 최종 `question`의 UTF-8 바이트에 대한 SHA-256이다. `reviewer_1`은 Luna, `reviewer_2`는 Astra이며 각자의 라벨·근거·품질 지적을 보존한다. `decision`·`decision_reason`은 채택·수정·조정 방식과 이유, `final_label`은 최종 정답이다. `writer`에는 보완 작성자와 루트 수정 여부를 표시한다. `revision_history`에는 수정 전후 해시·수정자·이유를 보존한다(수정이 없으면 `[]`). `scenario`, `subtype`, `personal_context`, `mixed`는 구성 점검용으로 학습 입력에서 제외한다. 사람 정답 승인은 **0건**이다.

## 구성과 검증 결과

검증일: 2026-10-13. 900건 전량 합성, 라벨별 300건이다. `UNSUPPORTED`는 개인·조직 실시간 조회 120건, 실제 실행 120건, 무관한 요청 60건이다. `SEARCH_KNOWLEDGE` 중 개인 상황에 규정을 적용하는 문항은 96건, 지원·미지원 혼합 요청은 31건이다. 두 특성은 중복될 수 있다.

원형 상황은 **392개**, 그룹당 최대 **5건**이다. 세 작성 영역의 교차 중복과 같은 상황의 안내·실행·조회 대조를 검토해 그룹을 병합했고 과도한 반복은 새 상황으로 교체했다. 최종 정규화 완전 중복은 **0건**이다. NFKC·대소문자·공백/문장부호를 정규화한 문자열의 `SequenceMatcher` 유사도 0.85 이상 쌍도 최종 **0개**다. 의미 중복은 별도 AI 감사로 검토했으며 자동 점수만으로 판정하지 않았다.

- 900건·라벨별 수량, 6열 계약·필수값·고유 ID·단일 라벨·UTF-8 BOM 확인.
- 모든 최종 질문에 두 독립 검수 기록이 있고, 입력과 검수 질문의 해시가 일치함을 전수 확인.
- 최종 문장 기준 두 검수자의 라벨 일치는 **884/900건**. 의견 차이 또는 품질 지적의 루트 조정은 **21건**이며 양쪽 원판정과 이유를 보존했다. 이는 수정 이후의 검수자 일치 수로, 분류기 정확도가 아니다.
- 수정 후 재검수를 받은 최종 문항 **146건**. 사람 정답 승인 **0건**.
- 아래 비파괴 분할에서 그룹·정규화 질문의 분할 간 중복 **0건**, 세 분할 모두 세 라벨 포함.



## 학습 시 분할

CSV에 `split`은 없다. 학습 코드에서 `question_id` 순으로 정렬한 후 **시드 `20261013`과 `group_id`**로 약 70:15:15를 분할한다. 같은 그룹은 반드시 같은 분할에 배치한다. 행 단위 무작위 분할은 표현 변형·대조 문항이 평가에 섞일 수 있다.

이번 비파괴 시험은 기존 환경의 scikit-learn `GroupShuffleSplit`로 전체 그룹의 15%를 test로 분리한 후, 나머지에서 `0.15 / 0.85`를 dev로 분리했다. 두 단계 모두 시드 `20261013`을 사용했다. 그룹 수를 기준으로 나누므로 행 수와 라벨 비율이 정확히 70:15:15가 되지는 않는다. 분할 파일은 저장하지 않았으며 런타임 분할 코드는 구현하지 않았다.

| 분할 | 전체 | SEARCH_KNOWLEDGE | CLARIFY | UNSUPPORTED | 그룹 |
|---|---:|---:|---:|---:|---:|
| train | 637 | 219 | 208 | 210 | 274 |
| dev | 129 | 37 | 49 | 43 | 59 |
| test | 134 | 44 | 43 | 47 | 59 |

환경: scikit-learn 1.9.1. 실제 학습 시 같은 데이터 버전·입력 순서·분할 알고리즘을 함께 고정한다.

TF-IDF와 BERT 등 비교 모델은 동일한 분할을 사용하고 실제 문항 ID·시드·수량을 실험 결과에 기록해야 한다. 벡터화 등 학습되는 전처리는 train에만 맞춘다. 데이터 버전이나 분할 알고리즘이 달라지면 같은 시드만으로 같은 분할을 보장하지 않는다. 전량 합성 자료이며 학습·검증·테스트 모두에 사용한다. 합성 평가 결과는 실제 직원 질문의 성능과 구분한다.

## 참고 자료와 한계

아래는 상황 구성과 검수 설계를 위한 참고 자료다. 이들 데이터의 라벨을 사내비 세 라벨에 자동 대응시키지 않았고 원문 예시를 이 CSV에 수록하지 않았다.

- [CLINC150](https://github.com/clinc/oos-eval): 지원 의도와 범위 밖 요청을 함께 평가하는 구성, 상황에 따른 발화 작성 방식 참고.
- [MASSIVE](https://huggingface.co/datasets/AmazonScience/massive): 한국어를 포함한 다국어 의도 데이터 참고. 음성 비서의 지원 범위와 사내비의 지원 범위는 다르다.
- [CLAMBER](https://github.com/zt991211/CLAMBER): 모호한 정보 요구와 되묻기 유형 참고. 사내비는 모델이 용어를 모른다는 이유만으로 되묻는 라벨을 부여하지 않는다.
- [Generating Hard-Negative Out-of-Scope Data with ChatGPT for Intent Classification](https://aclanthology.org/2024.lrec-main.674/): 지원 의도와 가까운 미지원 발화를 생성·검토하는 설계 참고. 해당 연구의 결과가 본 데이터의 품질을 입증하지는 않는다.

라벨별 균형은 비교 실험을 위한 구성으로 실제 직원 질문의 발생 비율이 아니다. 작성·검수 모델이 공유하는 편향, 합성 문체, 실제 사내 용어·오타·대화 맥락의 부족이 남아 있다. 그룹 점검은 의미 중복을 완전히 제거했다는 보증이 아니다. 본 데이터의 평가 결과는 **합성 질문에 대한 성능**이며 실제 직원 질문에 대한 서비스 성능과 구분해야 한다.

사람의 정답 검수, 모델 학습, 런타임 분할 구현, 회사 근거 문서 작성, 실제 서비스 성능 평가는 별도 단계다.
