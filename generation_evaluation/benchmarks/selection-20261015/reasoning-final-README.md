# 독립 추론 후속 평가세트

`reasoning-final.json`은 개발세트에서 개선된 후보를 별도 20개 질문으로 확인하기 위한 고정 평가세트다. 2026-10-15에 모델 응답이나 평가 결과를 보지 않고 구성했다. 세트 고정 뒤에는 후보 결과에 맞춰 문항이나 기준을 수정하지 않는다.

## 구성

| 범주 | 문항 수 | 설계 |
|---|---:|---|
| `normal` | 8 | 일반적인 절차·역할 문의 |
| `missing` | 4 | 제공 문서에 없는 회사별 지원·등록 기준. 합성 사례 |
| `boundary` | 4 | 긴급 변경, 예외 조건, 안전한 복구 경계 |
| `authority` | 2 | 안내 요청과 실제 조회·변경 요청이 함께 있는 사례 |
| `false_premise` | 2 | 문서에 없는 임계값 또는 검토 면제 전제를 포함한 합성 사례 |

`SEARCH_KNOWLEDGE` 원본 질문에서 선택한 13개 그룹은 모두 서로 다르고, 기존 dev/final 세트의 그룹과 겹치지 않는다. EXT-N14는 분실 휴대전화 복구 상황으로 범위를 좁혀 만든 합성 적응 사례이며 원본 RG0324 문항으로 세지 않는다.

| 사례 | 원본 `group_id` |
|---|---|
| EXT-N01–N08 | RG0052, RG0168, RG0003, RG0321, RG0162, RG0237, RG0184, RG0192 |
| EXT-N09–N12 | RG0018, RG0015, RG0255, RG0249 |
| EXT-N13 | RG0245 |
| EXT-N14 | SYN-RA14 (RG0324 복구 절차를 분실 상황에 맞게 합성 적응) |

`EXT-N14`는 `SYN-RA14` 합성 적응 권한 사례다. `EXT-N15–N16`은 각각 `SYN-RF15–SYN-RF16` 합성 잘못된 전제 사례이고, `EXT-N17–N20`은 `SYN-RF17–SYN-RF20` 합성 부족 사례다. 이 일곱 그룹은 `data/dataset.csv`의 원본 질문 그룹이 아니다. `source` 필드에도 합성·적응 구분을 남겼다.

## 근거와 부재 확인

근거 인용은 허용된 `tmp/generation-selection-20261015/documents.jsonl`의 71개 전체 문서 본문에서 정확한 연속 문자열인지 확인했다. 부재 사례의 근거는 제공된 절차를 찾고 소유자에게 문의하라는 안내를 뒷받침하며, 없는 정책을 직접 인용하는 용도로 쓰지 않는다.

부재 여부는 같은 71개 전체 본문에 대해 다음 표현군을 대소문자 구분 없이 검색해 확인했다. 모두 일치 항목이 없었다.

- 주차·차량 등록·차량번호·월 주차
- 구내식당·식권·식대·중식·점심 지원·식사 지원/비/수당/한도/잔액·급식
- 통근·출퇴근 교통/비용·정기권·교통비 지원/청구/한도·대중교통 지원/정기권
- 재택과 인터넷/통신비, 인터넷/통신비와 재택·지원·요금·비용·정산의 조합

이 검색은 제공된 문서 스냅샷에서 관련 사내 기준이 실제로 확인되지 않는다는 범위만 뒷받침한다. 회사의 다른 문서나 별도 시스템에 정책이 없다는 뜻은 아니다. 따라서 부족 사례의 정답은 메뉴·한도 추정이 아니라 확인 가능한 범위와 적절한 후속 확인을 구분하는 것이다.

## 판정 기준과 고정 상태

기존 `rubric.json`의 8개 차원(`format`, `grounding`, `scope_conditions`, `completeness`, `abstention`, `action_boundary`, `style`, `relevance`)과 동일한 심각도 등급(`critical`, `material`, `omission`, `style`, `none`)을 이 세트에도 적용한다. 원본 `rubric.json`은 그대로 유지한다.

이 세트는 기존 `final.json`과 같은 항목 구조를 사용한다. 필수 주장은 질문에 답하는 데 필요한 핵심으로 제한하고, 별도의 불필요한 금지 문구 반복을 요구하지 않는다. 질문·그룹·근거 검증을 완료한 뒤 후보 모델의 응답 및 평가 결과를 열람하지 않은 상태로 고정한다.
