## 1. 실제 활성 프롬프트 전체

`generation/prompts.py`의 공통 system 뒤에 다음이 연결된다.

`공통 역할·근거·실행 한계·존댓말·JSON → concise 규칙 → 사용자 표현을 수정한 합성 예시 6개 → scope v1 → 출처 v3 → 사용자 표현 v4 → 서비스 범위 v5`

v5 조립 system은 3,459자, v6는 4,275자이며 v5 뒤에 가독성 블록만 추가한다. 저장된 실험 system과 현재 조립 결과는 일치한다. 현재 DEFAULT_PROMPT_PROFILE 및 실행 프리셋은 v5다.

v2 전체 규칙, coverage/conditions/json 별도 실험 프로필은 현재 v5에 들어가지 않는다. 파일에 존재한다는 이유만으로 활성 지침으로 취급하면 안 된다. 현재 모델은 GPT-6 Luna, xhigh, 출력 16,384, timeout180, prompt_json이다.

문서는 HumanMessage 앞부분, 질문은 마지막에 놓이며 SystemMessage와 분리된다. 대화 이력을 보내는 구조가 아니다. 문서의 ID·개정·제목·본문을 렌더링한다.

## 3. 전체 프롬프트 감사

| 영역 | 현재 평가 | 보완할 점 |
|---|---|---|
| 역할·실행 한계 | 명확함 | 실제 조회·처리 도구 없이 완료를 주장하지 않는 규칙 유지 |
| 범위 밖 / 자료 부족 | v5가 우선순위를 명시함 | 회사 업무용 일반 기술인데 문서 맥락이 없는 경계 추가 검증 |
| 부분 답변 / 재질문 | 두 규칙 모두 존재 | 안전한 부분 답변 후 재질문과 전체 재질문의 선택 경계 구체화 |
| 근거·주체·조건·OR | 명시적 보호 규칙 존재 | 문서 간 조건 연결과 대체 경로를 보여 주는 예시 부족 |
| 완전성 / 간결성 | 직접 모순은 아님 | 필수 행동·성공 확인·실패 시 대안과 선택적 배경의 구분이 추상적 |
| 사용자 말투 | 내부 지침 선언을 막고 직접 답변 유도 | 기존 보호 규칙 유지, 서식과 혼합해 한 번에 재튜닝하지 않기 |
| 예시 | 권한·적용 범위·AND 판단 6개 | 모두 짧은 평문이며 실제 JSON 계약·다문단·복합 절차와 형식 차이 |
| v6 서식 예시 | 준비물 2개와 OR 수령 장소 | 목표인 기능 소개와 조건부 절차를 대표하지 못함 |
| 출처 | 필요 시 실제 제목·항목 허용 | 출처를 숨기라는 규칙 아님. 충돌 시 문서 권위·적용 범위 확인 필요 |
| 문서 내 지시 | 참고 자료로 취급하도록 명시 | 가짜 구분자·역할 변경·정상 직원 규정 구별은 이번 시험 미검증 |

‘간결하게’와 ‘불릿으로’는 함께 지킬 수 있어 논리적 충돌이라고 부르지 않는다. 다만 압축과 구조화 사이 선택이 모델에 남아 있다. 가독성 예시가 준비물이라는 사실은 실패 원인 후보이며 원인 확정은 아니다.

JSON 아닌 기존 예시는 계약과 일관성이 낮지만 실제16회에서 파싱 실패가 없었다. 따라서 현재 누락의 직접 원인으로 주장하지 않는다. v6 JSON 예시를 파싱하면 실제 개행5개이고 문자 그대로의 역슬래시-n은0개다.

규칙을 누적한 것은 과거 실험을 보존하고 변경 변수를 줄이려는 합리적인 선택이었다. 다만 현재는 조립된 전체를 역할·범위·근거 선택·완전성·표현·출력 계약으로 관리할 시점이다. 글자 수가 길다는 이유만으로 실패했다고 주장할 수 없다.

## 5. 평가 결과 해석의 수정

기존 요약: 내용은 양쪽7/8통과, 가독성은 v5 8/8 vs v6 5/8통과다. 이 수치를 순수한 동일 척도의 가독성 우열로 일반화하면 안 된다. R01의 기존 짧은 문단 허용과 신규 목록 기대가 함께 들어 있다. v6가 더 길고 밀집됐다는 관측과 신규 목표 미준수는 유효하지만, 공통 가독성 점수와 지침 준수 점수를 따로 내는 편이 명확하다.

초기 독립 판정은 v6의 ‘보안 > 사고 신고’를 허구 메뉴로 오판했다. 선택된 짧은 근거에는 없었지만 전체snapshot069/071에는 존재했다. 재검토로 중대한 오류 판정을 수정했으며 내용 누락 실패는 유지했다. 따라서 독립 검토자라는 이유만으로 사실 판단을 신뢰하면 안 된다.

일반 사고 문서의 OR 신고 경로와 일부 특수 사고 문서의 AND 신고 경로는 적용 상황을 함께 봐야 한다. 차이가 있다는 것만으로 문서 충돌이라고 단정하거나 한쪽 정책으로 합치지 않는다.

16회 한 번씩의 소규모 비교는 채택 보류 근거는 되지만, 반복 안정성이나 v6의 인과적 퇴행을 입증하지 못한다. 기존 판정 기록은 덮어쓰지 않는다.

## 6. 다음 작업 제안 — 미구현·미실행

1. 현재 v5 의미를 정책별로 목록화한다. 전체 정리 후보를 만들더라도 보존해야 할 규칙을 명시하고 별도 버전으로 둔다.
2. 가독성과 완전성 후보를 분리한다. 가독성은 기능 소개와 조건부 분기 예시, 완전성은 문서가 요구하는 행동·확인·실패 시 후속 경로를 검토한다.
3. 어떤 경우에도 없는 후속 절차를 채우지 않고, 해당하지 않는 예외를 모두 나열하지 않는 경계를 둔다.
4. JSON 예시 통일과 전체 재구성은 별도 변경으로 검증한다. 한 번에 바꾸면 개선 원인을 알 수 없다.
5. 내용 정확성 / 필수 안내 / 공통 가독성 / 지정 구조 준수 / API·JSON을 각각 측정한다. 이미 본 문항은 회귀용으로 표시하고 다른 업무와 표현을 포함한다.
6. 후보당 반복을 확보한다. 필요하면 문서 부분집합·순서만 바꾼 진단을 먼저 수행한다. 검색 도입이나2단계 생성이 필요하다는 결론으로 바로 건너뛰지 않는다.

이번 권고는 추가 실험 승인이 아니며, 현재 v5 기본값을 유지한다. 출력 한도·추론 강도·모델을 올리는 조치는 이번 관측에 대한 우선 해결책이 아니다.

## 7. 독립 AI 감사 결과 반영

별도 읽기 전용 검토자가 전체 조립 동일성, 개행, 활성/비활성 규칙, R01/R03/R08, 평가 척도를 확인했다. 주요 결론은 본문에 반영했다. 추가 미검증 영역은 기술 질문의 회사 맥락 경계, 모호한 요청의 부분 답변, 문서 조작 지시다. 취약점 성공이나 일반 품질 저하가 확인됐다고 표현하지 않는다.

이번에 확인한 것은 코드·저장 응답·공식 문헌이다. 실모델 재실행과 새로운 브라우저 시험은 하지 않았다.
