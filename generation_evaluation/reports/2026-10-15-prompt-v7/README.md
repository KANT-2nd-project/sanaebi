# 전체 프롬프트 v7 보강 비교 — v5 유지

**가독성·완전성 후보를 구현하고 비교했지만 기본값은 `examples_answer_scope_v5`로 유지한다.** 최종 비교에서 v5와 완전성 후보 모두 36응답 중 19개가 내용 기준을 통과했고, 세 번 모두 통과한 문항은 각각 6/12였다. 채택 기준 11/12, 사고 대응의 필수 안내 및 도움 소개 구조 조건에 미달했다.

실제 생성은 개발36 + 최종72 = **108회**다. 두 독립 후보가 모두 유지 조건을 통과하지 않아 결합12회는 생략했다. 추가 튜닝·자동 재시도·재부팅 후 재생성은 하지 않았다. AI가 구현·자료 작성·실행·익명 판정·경계 검토·복구를 수행했으며 사람 검수나 사용자의 독립 구현으로 기록하지 않는다.

## 중요한 보존 한계

사용자가 작업을 잠시 중단한 뒤 컴퓨터를 재부팅했고, 재개 시 `/tmp/sanaebi-prompt-v7-20261015`가 없어져 미커밋 원자료가 소실된 것을 확인했다. 실험 증거를 임시 경로에만 둔 AI의 보존 방식에 문제가 있었다.

- Git에 있던 후보·실행기·사전 자료와 원래72문서 snapshot은 복구했다.
- 지속 저장된 도구 출력에서 **답변 본문108개와 판정 JSON8개**를 복구했다. 각 항목의 세션 파일·줄 번호·추출 경계·해시를 보존했다. 일부 전체 도구 출력은 잘렸지만 선택 답변 구간은 다음 항목 또는 완료 표식까지 확인했다. 직접 JSON 답변 필드와 대조 가능한24개도 일치했다.
- 익명 매핑은 커밋된 실행 순서와 당시 기록된 shuffle seed로 **재구성**했다. 원래 매핑 파일을 되찾았다는 뜻이 아니다. 복구한 문항 ID와108개 모두 일치하며, 개발36·최종72의 정확한 슬롯/판정/필수 인덱스를 별도 감사했다.
- 공급자 원문 JSON 래퍼, 호출별 토큰·시간, 원래 SQLite 원장·이벤트·manifest, 화면 캡처는 완전히 복구하지 못했다. 누락값을0으로 채우거나 새로운 측정값을 원래 값처럼 만들지 않았다. **호출별 측정 자료와 원 실행의 완전한 재현성 확인은 미완료**다.
- 이전 도구 출력에는108회 모두 정상 종료·사용량 존재·총 비용 추정 **$1.63424025**, 원 소스 해시 불일치0, 개발72+최종144 화면 재생의 가로 넘침0이 기록되어 있다. 이는 [복구한 당시 관측 기록](recovery/historical-tool-evidence.json)이며 지금 원장·스크린샷을 다시 검증한 결과와 구분한다. 실제 청구액이 아니다.

[복구 출처·한계](recovery/recovery_manifest.json), [판정 복구 방법](recovery/judgments/README.md), [재구성 매핑](recovery/reconstructed-mapping.json)을 따른다. 새로운 작업 공간은 `/home/jake/workspace/projects/.sanaebi-prompt-v7-recovery-20261015`이며, 아래 요약·답변·판정은 저장소에 게시해 임시 경로에만 남기지 않는다.

## 독립 판정과 정정

개발과 최종 응답은 후보 이름을 가린 독립 AI가 판정했다. 최종은 반복별 독립 판정 후 경계 사례를 같은 기준으로 재검토했다. 초기본과 정정본은 모두 보존한다.

- 개발 R08의24시간 대응·전송 시각·실제 회수 확인을 잘못 충족 표시한 부분을 정정했다. D11의 토큰 금지는 세션 자격 토큰을 포함하는 의미로 인정했다.
- 최종2회차 화재 응답2개의 일부 판정 사유가 서로 뒤섞인 것을 찾아 실제 익명 ID별 답변으로 바로잡았다. 원답변이 뒤바뀐 것은 아니다.
- ‘두 신청의 선후가 정해져 있지 않다’는 문장은 근거 없는 단정으로 남겼다. 다만 계약·결제 전 승인 조건은 보존해 중대한 권한 오류·순서 위반으로 과대 분류하지 않았다.
- 범위 밖 거절의 ‘사내 업무 정보·절차’는 회사 문서에 설명된 업무 도구까지 포괄하는 표현으로 인정했다. 도구라는 단어의 유무만으로 실패시키지 않았다. 반면 본인의 재진입 금지와 타인을 보내 수색하지 말라는 지시는 주체가 달라 구분했다.
- 고정 기준에도 한계가 있다. H04의 계정 발급 경계는 required와 optional에 중복돼 있으며, 이번에는 결과 후 기준을 바꾸지 않고 required를 일관되게 적용했다. 신고·종료 조건, 명시적인 비 SLA 구분 등은 엄격한 기준이며 일반 정확도로 확대 해석하지 않는다.

판정 기준의 의미 경계와 AI 판정 오류 자체도 한계다. 불확실 항목은 정답으로 임의 승격하지 않았다. H09 변경은 기록된 독립 의미 동등성 재검토에 따른 정정이다.

## 검증과 재현

복구 후 생성139·평가189·서버 runtime261·검색 통합39, **총628개 unittest**가 통과했다. 저장소 전체 Ruff 검사·형식 검사도 통과했다. 세부 상태는 [verification.json](verification.json), 원 출력은 같은 폴더의 `*-tests.txt`를 따른다.

집계기에서 mapping/필수 체크 누락을 놓칠 수 있는 부분을 별도 [감사 도구](validate_evidence.py)와 회귀5개로 보완했다. [개발36 감사](development-audit.txt)·[최종72 감사](final-audit.txt)는 복구 자료의 정확한 슬롯과 필수 항목 범위를 확인한다. 원 provider raw JSON이나 소실된 측정 원장을 복원한 검사는 아니다.

복구 요약은 `python generation_evaluation/reports/2026-10-15-prompt-v7/summarize_recovered.py`로 재계산한다. 소실된 run-001을 새 원장으로 만들어 재개하지 않는다. 이미108회 사용한 한도와 성공·실패 슬롯 재호출 금지 조건을 보존한다. 새 실험은 별도 승인·ID·한도가 필요하다.

후보·실행기 구현은 `a6850a6`, `a1c8777`, 감사 보강은 `eda7b99`다. 최신 main의 별도 웹·문서·RAG 작업을 보존했다. 이 실험은 고정72문서 전체 입력이며 별도 RAG 경로의 생성 품질 검증이 아니다. AI 작성 소표본이고 도움 소개2문항은 예시·개발과 상위 의도를 공유한다. snapshot의 비정상적인 배포 실패 정책도 자료 품질 문제로 분리했으며 수정하지 않았다.
