# 독립 AI 검토 기록

별도 reviewer 역할 에이전트가 구현 담당자와 분리해 파일 및 원응답·snapshot을 읽었다. 사람 검수나 모델명이 가려진 블라인드 평가는 아니다. 코드 작성·수정은 구현 담당자 한 명이 수행했다.

## 실행 전 지적과 반영

- v4의 기존 few-shot 답변에 '문서에 없으면 덧붙이지 않습니다' 같은 작성 방식 선언이 남아 새 지침과 충돌했다. v3/v4는 보존하고 v5에만 사용자 직접 답변 예시를 분리했다.
- 공통 자료 부족 규칙과 범위 밖 안내 사이의 우선순위가 불명확했다. 서비스 범위·업무 맥락 확인을 먼저 적용하도록 명시했다.
- U07의 '범위 설명 또는 업무 질문 유도'는 자료 부재로 거절한 뒤 질문만 유도해도 통과할 수 있었다. v5에서는 범위 설명 필수·자료 부재만의 거절 금지로 고정했다.
- v4 U06의 '15분 기다린 뒤'는 당직 인수 목표를 신고자의 대기 의무로 바꿨다. '#security-incident와 보안 > 사고 신고'는 OR를 AND로 바꾸고 정확하지 않은 메뉴 계층을 만들었다. 원문 ieum-035는 '#security-incident 또는 이음 포털의 보안 신고'이며 무응답 시 기다리지 않고 대체 인계하도록 한다. 이 응답은 실패로 보존한다.
- v5에 시간·선택 조건 보존을 명시하고 U06의 금지·필수 판정 기준도 실호출 전에 강화했다.

재검토자는 수정 반영을 확인하고 v5 13건 평가를 막는 추가 중대 문제가 없다고 판단했다. 이는 정적 검토일 뿐 실제 응답의 채택 판정은 아니다. 실행 후 검토는 별도로 남긴다.

## 실행 후 독립 검토

고정13응답과snapshot을 대조했다. 요청한 말투·범위는13개 모두통과다. 전체 품질은U01/U03 부분 충족, 나머지11개 통과이며 실패·불확실0개다. U01의People팀 역할 확대는v3/v4에도 관찰된 기존 문제다. U03의팀장1영업일 회신 누락은 같은 질문의v3/v4에 있어 이번 관측에서는 완전성 회귀다. U09의제도운영 여부 언급은 과잉 유보의 여지가 있지만 명백한 사실 오류로 판정하지 않았다.

검토자는 요청한 표현·범위 개선은 관찰됐으나 전체 품질 회귀 통과로 보고해서는 안 된다고 결론냈다. 구현 담당자는 사용자 요청 범위의 개선으로v5를 기본 연결하되 두부분 충족과단일실행의 한계를 공개한다. 원판정과원응답을 수정하지 않는다. 세부근거는 judgments.json과case-results.md에 보존한다.
