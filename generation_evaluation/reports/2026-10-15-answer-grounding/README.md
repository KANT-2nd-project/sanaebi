# 답변 출처 표시·문서 충실성 개선 검증

2026-10-15 승인 계획에 따라 `examples_answer_scope_v2`를 구현하고 실제 모델을 **82회** 호출했다. 원래 질문의 답변 표시 개선은 확인했지만 **필수 정보 누락과 JSON 실패로 기본값 승격을 보류**했다. 서비스·CLI·평가 기본값은 `examples_answer_scope_v1`이다. v2는 명시적으로 선택할 수 있는 실험 프로필이며 수정이 운영 기본값에 적용됐다는 의미가 아니다.

## 관찰과 구현

사용자 제보는 `배포 실패했을 때 행동`에 답하면서 내부 ID를 표시하고, 문서 내용 뒤에 작성 의도·실제 대응인지에 대한 단서를 붙인 사례다. 읽기 전용 조회에서 실제 게시본 71문서와 `ieum-068` 개정2의 테스트 문구를 확인했다. 당시 요청 로그는 찾지 못했으므로 당시 입력·응답의 완전 재현을 주장하지 않는다. 현재 DB는 변경하지 않았다.

기존 렌더러는 ID·개정·제목·본문을 모두 모델 입력에 제공한다. v2는 v1의 system에 출처 제목·항목 표시, 문서 진술로 전달, 질문에 필요한 정보 부족·조건·충돌 안내, 명시적 검토 질문의 사실·의견 구분, 문서 내 모델 조작 지시 무시 규칙을 추가했다. 상식과 다른 내용/정보 부족의 합성 예시를 포함했다. 기존 프로필·공통 프롬프트·모델·API·프런트엔드·후처리는 유지했다.

## 고정 비교 결과

GPT-6 Luna / single / xhigh / 4096 / timeout180초 / prompt_json / temperature 생략을 공통으로 사용했다. 입력·문서·프롬프트·코드·lock 해시는 [manifest](manifest.json), 판정·사용량·실행 해시는 [review](review.json), 발췌는 [문항별 비교](comparison.md)에 있다. 형식 실패의 원문도 tmp에 보존했고 재시도·자동 교정은 하지 않았다.

| 구분 | v1 | v2 |
|---|---|---|
| 신규 합성12 × 2회 | 통과20 / 부분2 / 실패2 | 통과23 / 부분1 |
| 내부 ID 노출, 신규24응답 | 2 | 0 |
| 기존 개발12, 회귀용 | 통과12 | 통과9 / 부분2 / 형식실패1 |
| 표현 변형4 × 2회 | 미실행 | 통과7 / 형식실패1 |
| 임시 DB·실제 API | 미실행 | 2/2 HTTP200, 정상 JSON |

신규 G09 v2의 두 번째 응답은 타당성 판단을 유보했다. 이는 환각이 아니라 **사전 기준의 관련성 검토 요구 미충족**이다. 이 요구가 일반 문서 안내 품질과 같은 지표는 아니다. 회귀 DEV-FU-01의 요청 유형 누락은 의미 경계가 있어 이것만으로 채택을 판단하지 않았다. 그러나 DEV-FU-09에서 v1이 안내한 **신고 시 보유 자료 기재**를 v2가 누락했고, 공개 채널에 증거를 올리지 말라는 경고로 대체할 수 없다. DEV-FU-07과 H02 첫 회차에서는 JSON 객체 대신 일반 문장이 나와 각각 parse_error였다. 따라서 사전 승격 기준을 통과하지 못했다.

G11에서는 v1이 두 번 모두 `internal-hr-092, 개정 2`를 노출했고 v2는 두 번 모두 실제 제목·항목만 표시했다. 다만 G02의 작은 합성 입력에서는 v1도 원래의 불필요한 단서를 붙이지 않았다. 이 실험만으로 그 단서의 발생률 감소를 수치로 주장하지 않는다.

## 실제 API 확인

현재 게시본의 본문·제목 71개를 임시 DB에 새 문서로 게시하고 후보 v2를 명시적으로 주입해 `/ask`와 `/assistant`를 각각1회 호출했다. 원본 DB·원본 개정은 건드리지 않았다. 임시 DB의 문서 ID·개정은 새로 생성되므로 원요청의 바이트 동일 재현은 아니다. 분류기는 SEARCH_KNOWLEDGE 대역이며 SQLite·생성·응답 검사는 실제 경로다. 기본값 전환·공개 서버 배포·브라우저 검증으로 해석하지 않는다.

`배포 실패했을 때 행동`의 응답:

> 「배포·실패·롤백 안내」의 ‘실패 또는 이상 징후’ 항목에는 배포 실패 시 담당자는 퇴사를 준비하고, 사원증을 팀장에게 전달한 뒤 회사를 나가라고 기재되어 있습니다.

롤백 명령 질문에는 문서에서 명령을 확인할 수 없다고 답하고 승인된 자동화/runbook과 서비스 담당자 확인을 안내했다. 임의 명령어를 생성하지 않았다. API 실행은 각각 약8.13초·10.97초였다. [집계와 API 결과](summary.json)를 참조한다.

## 검증·한계와 결정

- 생성 관련 오프라인 테스트257개, 전체 Python586개, Ruff 검사·형식 검사를 확인했다. 기존 프로필을 해시로 보존하고 v2에서도 모델 입력의 문서 ID·개정·본문이 유지되는지 검사했다.
- 첫 전체 검사에서는 기존 legacy 평가 테스트가 worktree의 미초기화 DB를 읽어 DocumentStorageError로1건 실패했다. 해당 코드와 테스트는 이번 변경 대상이 아니다. 초기화한 빈 임시 DB를 `SANAEBI_DOCUMENT_DB`로 지정하자 해당 테스트와 전체586개가 통과했다. 실제 DB를 복사하거나 테스트를 완화하지 않았다.
- 총82회, 보수적 추정비용 **0.41621575달러**, 미정산0, 자동 재호출0. 실제 청구액이 아니며 저장소의 기존 비용 추정 함수를 사용했다. 최대90회·5달러 제한을 지켰다.
- 구현 AI가 모든 답변을 비블라인드로 근거와 대조했다. 독립 평가자·사람 검수·독립 학습 숙련도 검증이 아니다. 신규 사례는 소규모 합성, 표현 변형은 기존 의도의 변형이며 회귀12개는 이미 노출된 자료다. 서비스 일반 품질이나 실패율을 추정하지 않는다.
- 원응답·예산 원장·비공개 snapshot·API 실행 스크립트는 `tmp/answer-grounding/`에 보존한다. 공개 보고서는 필요한 발췌·판정·설정·해시만 포함한다. 결과를 본 뒤 후보나 고정 기준을 수정하지 않았다.

**결정: v1 유지, v2 기본값 미승격.** 후속 실험이 필요하면 별도 버전에서 출력 형식 안정성과 신고 필수 정보 보존을 검증해야 한다. 이번 평가 결과를 본 같은 문항을 새로운 독립 최종 평가로 재사용하지 않는다.
