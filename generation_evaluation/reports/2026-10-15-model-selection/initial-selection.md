# 1차 20문항 비교: none 추론 구성

두 모델 모두 대조 예시·단일 호출을 고정했다. GPT는 none/temperature0/출력1024, Qwen은 context98304/출력1024/temperature0/seed42다. 최종20문항을 모델별2회씩 총80응답으로 비교했다.

| 지표 | GPT-6 Luna | Qwen3 4B Q4_K_M |
|---|---:|---:|
| 중대한 근거 오류 문항 | 0/20 | 5/20 |
| 두 번 모두 통과 | 5/20 | 4/20 |
| 통과 / 부분 / 실패 / 불확실 | 12 / 12 / 16 / 0 | 8 / 9 / 23 / 0 |
| JSON 파싱 실패 | 16/40 | 2/40 |
| 제공자 호출 실패 | 0/40 | 2/40 |
| 반복 간 판정 변동 문항 | 4/20 | 1/20 |
| 전체 지연 중앙값 | 3.16초 | 10.09초 |
| 전체 지연 최댓값 | 10.63초 | 87.68초 |

사전 선정 순서상 GPT가 잠정 권장이다. 두 모델 모두 안정 통과18/20 기준에 미달해 공통 기본 설정 승격과 서비스 품질 승인은 보류했다. GPT의 중대한 오류0은 유보·누락·형식 실패가 없다는 뜻이 아니다.

## 중요한 실패

- GPT의16개 형식 실패는 실제 평문 출력이다. 원문을 JSON으로 감싸 재채점하지 않았다. 기존 개발 문항에서는 드러나지 않은 형식 실패가 다른 질문 그룹에서 나타났다. 어떤 프롬프트 요소가 원인인지는 이 비교만으로 분리할 수 없다.
- Qwen은 누락된 출근 기록을 정정 대상에서 제외하거나, 모든 개발 패키지 설치에 사전 승인을 요구하거나, 시간 단위 연차·외출을 금지하는 정책을 만들었다. 재택 등록 마감을 전 영업일에서 당일로 늦추고 저장소 생성 업무를 정책상 권한 초과로 단정한 사례도 중대한 오류로 남았다.
- Qwen의 경조사 문항은 두 반복 모두 ResponseError/status_code=-1로 응답이 없었다. 서버 로그와 보존된 메타데이터만으로 원인은 확정하지 못했다. 답변 내용 오류나 정상 유보로 처리하지 않고 호출 실패로 포함했다.
- 필수 누락 판정에는 사전 기준이 넓게 정한 항목도 포함한다. 예를 들어 입력 허용 기준 질문에 출력의 사람 검토 안내, 방문 절차 질문에 내부 기록 관리까지 요구했다. 후속 검토에서 기준의 과도함이 지적됐지만 결과를 본 뒤 required_claims를 지워 통과율을 높이지 않았다. 다음 독립 세트 설계의 한계로 남겼다.

공유드라이브 경고를 처음에는 허구 권한으로 판정했으나 전체 snapshot의 ieum-031에 직접 근거가 있어 정정했다. 반대로 원문에 없는 금지 정책을 단순한 보수적 답변이라는 이유로 통과시키지 않았다. [조정 근거](adjudication-notes.md)와 [변경 전후](adjudications.json)를 보존했다.

## 속도와 비용

Qwen의 순수 decode TPS 중앙값은18.16이다. 과거 최적화 결과 약18.5TPS와 비슷한 수준이지만 이번 질문·출력 길이가 다르므로 별도의 통제 개선 배수로 표현하지 않는다. 첫 요청87.68초에는 적재와 전체 입력 prefill이 포함된다. 후속 요청 중앙값과 첫 입력 시간을 섞지 않는다.

1차 개발+최종 실험의 OpenAI92호출은 표준 단가 사용량 추정0.398043달러, ledger의 보수적 추정0.793374달러다. 최종40호출만의 추정은 각각0.157707/0.313967달러다. 실제 청구서 금액이 아니며 추가 추론 실험의 비용은 이 수치에 포함하지 않는다. Qwen은 API 비용0이고 장비·전력비는 계산하지 않았다.
