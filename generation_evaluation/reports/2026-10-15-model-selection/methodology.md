# 평가 방법과 재현 범위

## 실험 분리

71개 문서를 고정하고 개발8문항에서 기준점→간결 규칙→대조 예시→추론 설정→조건부 근거 추출 순으로 비교했다. 후보별 첫 회8건으로 회귀를 확인하고 최선 후보만 두 번째8건을 실행했다. GPT는 low와 evidence_first가 연속으로 개선에 실패하여 추가 튜닝을 중단했다. Qwen의 evidence_first도 회귀해 탈락시켰다. 모든 실패와 탈락 후보의 응답을 보존했다.

최종20문항은 정상8·자료 부족4·조건/예외4·조회/실행2·잘못된 전제2다. 기존 SEARCH_KNOWLEDGE 질문18개와 부족한 유형을 보충한 합성2개이며 기존 질문 데이터 자체도 합성 자료다. 실제 고객 로그20개라고 해석하지 않는다. 질문 그룹은 개발·예시와 분리했고, 독립 작성자는 모델 응답을 읽기 전에 필수/금지 주장과 정확한 근거75구간을 고정했다. 프롬프트 작성자는 튜닝 중 최종 문항을 읽지 않았다. 이 분리는 업무 개념의 모든 유사성까지 제거했다는 뜻은 아니다.

최종 후보는 `8277908`에서 고정한 뒤 각 모델20문항×2회씩 실행했다. 최종 응답을 본 뒤 프롬프트·추론·전략을 변경하거나 실패를 재호출하지 않는다. 최종20개는 이번 모델 선택 자료이며 일반 정확도나 운영 신뢰성을 입증하지 않는다. 후속 튜닝에 재사용하면 더 이상 새로운 holdout이 아니다.

## 판정과 경계 재검토

[사전 rubric](../../benchmarks/selection-20261015/rubric.json)의 형식·근거성·범위/조건·완전성·유보·실행 한계·말투·관련성8차원을 적용한다. 전체 판정 우선순위는 실패→불확실→부분→통과다. 필수 안내만 빠졌으면 부분, 형식 실패나 중요한 사실 오류는 실패다. 허구 정책/메뉴/권한/처리 완료/지급 보장 및 중요한 조건 반전은 중대한 오류로 따로 센다.

모델명·후보·설정·시간을 제거하고 무작위 식별자로 섞은 응답을 별도 AI 검토자가 판정한다. 같은 문항의 네 응답은 한 검토자에게 배정해 일관성을 점검한다. 경계 판정은 원문에 다시 대조하고 변경 전후와 이유를 보존한다. 원문 근거 목록은 완전한 검색 결과가 아니므로 추가 주장이 틀렸다고 결정하기 전에 전체 snapshot을 확인한다. 동일 답변의 평가 차이는 생성 변동과 구분한다. 사람 승인이나 다수 인간 평가자의 합의로 표현하지 않는다.

형식 실패에도 읽을 수 있는 원문은 의미 차원으로 평가하지만 전체 실패는 유지한다. 응답이 없는 호출에 허구 주장을 만들어 붙이지 않는다. 누락·허구·조건 왜곡·과잉 유보·반복 변동은 중복될 수 있어 항목별 건수의 합이 전체 실패 수와 같지 않을 수 있다.

선정은 중대한 오류가 발생한 고유 문항 수→두 번 모두 통과한 문항 수→전체 통과 수→불확실 수→전체시간 중앙값→API 비용 순이다. 승격 기준은 두 번 모두 통과18/20 이상 및 중대한 오류0이다. 잠정 권장은 이 기준을 충족했다는 의미가 아니다.

## 시간·비용·재현

원래 ledger의 중단 전 활성953.0275초와 모든 호출 정산을 `resumed-budget.json`으로 이월했다. 명시적 사용자 중단 시간만 제외했으며 시간·비용을0으로 재설정하지 않았다. [재개 감사 기록](resume-accounting.json)을 따른다. 총2시간/$5와 개발70분/$3 경계 안에서 실행하며 실패도 호출 수와 비용에 포함한다.

ledger는 시작 전 고정한 긴 문맥 단가의 보수적 사용량 추정, `costs.json`의 표준 단가 추정은 공식272K 경계를 적용한 별도 계산이다. 둘 다 청구서 금액이 아니다. Qwen의 API 비용은0이며 전력·장비·운영비는 계산하지 않았다. 보고된 사용량이 없으면 누락을 표시하며0토큰으로 주장하지 않는다.

전체 요청 시간은 클라이언트 초기화·프롬프트 구성·모델 호출·검증 등을 포함한다. Qwen 순수 decode TPS는 Ollama `eval_count / eval_duration`으로 따로 계산한다. 첫 요청의 모델 적재·긴 입력 prefill, 후속 prefix cache, 토크나이저 차이 때문에 전체시간을 TPS로 읽거나 GPT와 순수 속도 비율로 일반화하지 않는다. 두 모델은 같은 입력이지만 서로 다른 제공자에서 동시에 실행했다.

입력 JSONL 파일 SHA와 로드된 문서 목록의 직렬화 SHA는 서로 다른 대상이다. 질문 파일 원본 SHA와 manifest의 정규화된 문항 SHA 역시 구분한다. `frozen-final.json`, `manifests.json`, 응답별 프롬프트 SHA·사용량·설정을 함께 확인한다. 원본 snapshot·provider metadata·호출 이벤트·예산 ledger는 로컬 `tmp/generation-selection-20261015/`에 보존하고 비밀키는 저장하지 않는다.

재실행은 [평가 실행 안내](../../README.md#예산-제한이-있는-독립-비교)의 selection 진입점에서 고정 설정·문항·snapshot을 사용한다. 같은 실행 폴더는 완료 항목을 건너뛰므로 새로운 반복 실험에는 별도 폴더와 예산 ledger를 사용한다. 기존 CLI 기본값과 과거 기록 읽기는 유지했다. 단위 테스트는 실행·실패 처리·예산·재개·검증을 확인하며 실제 모델의 정답성을 대신하지 않는다.
