# 현재 RAG 기반 v6·v7 가독성 비교 결과

2026-10-16. 구현·실행·판정·기록은 AI가 수행했다. 독립 검토자는 후보명을 가린 응답을 판정했다. 사람 검수 또는 사용자의 독립 구현 기록이 아니다.

## 결정

**실험 24/24회 완료. 두 후보 모두 사전 채택 조건에 미달하여 현재 RAG 기본값 `examples_answer_scope_v5_rag_service_v1`을 유지한다.** v7은 후속 검토 가치가 있지만 이번에는 채택하지 않는다. 현재 기준점도 내용 결함이 있어 기본값 유지를 품질 승인으로 해석하지 않는다.

독립 CLI/full 기본값은 v5 그대로다. 신규 후보는 명시적 실험용 등록만 유지했다. 재시작·배포·커밋·푸시·Notion 게시는 수행하지 않았다. 기존 개발 서버 자동 reload 가능성과 수동 재시작은 구분한다.

모든 응답은 JSON/API 정상 완료했다. 내용 통과와 API 성공은 별개다. 가독성은 0~2 공통 척도로 비교했으며, 도움 소개의 불릿 등 지정 구조는 별도로 판정했다. v7 도움 소개는 구조가 개선됐지만 짧은 기준점도 읽기 쉬워 공통 가독성 점수는 동점이었다. 척도가 작아 미세한 선호 차이를 모두 표현하지 못한다.

### 주요 개선과 남은 문제

- v7 도움 소개: 소개 문장·대표 업무 불릿 4개·직접 조회/실행 한계가 분리됐다. v6은 문단만 나뉘고 대표 업무 불릿은 나오지 않았다.
- v6 출장 절차: 기준점에 있던 예약 확인서·결제 증빙 연결 및 일정/프로젝트 일치 확인이 누락됐다.
- 조건부 예약 질문: v7은 대체 구매 시 팀장·재무팀의 서면 승인 조건을 보존했다. 기준점과 v6은 누락했다.
- 사고 질문: 세 후보 모두 필수 안내를 충족하지 못했다. 특히 v7은 담당자 인수 확인과 미응답 시 대체 인계 경로를 생략했다. 연락 가능한 회사 계정과 연결 시도·인수 기록도 빠졌다.
- 필요한 사고 근거는 실제 입력에 전달됐다. 이번 누락은 검색 실패가 아닌 생성 단계의 안내 누락이다. 신고 채널의 “또는”을 “와”로 바꾼 표현 등 경계 사례는 독립 검토 기록을 따른다.

## 실행·재현 근거

- 고정 게시 문서 71개와 색인 복사본, 실제 서버 검색/문맥 보충/분류 advisory 경로에서 생성한 입력을 사용했다. 실서비스 DB는 변경하지 않았다.
- 기준점·v6·v7에 문항별 동일한 문서/근거 상태/분류 정보를 전달했다. 순서는 문항별 순환했다. R06은 실제 검색 근거 없음 상태였다.
- 고정 모델: GPT-6 Luna / xhigh / 16384 / 180초 / prompt_json / single. temperature·자동 재시도 없음.
- 호출 24회, 입력 179482토큰·출력 14743토큰(추론 포함), 합계 비용 추정 **$0.05592775**. 사용량 누락 없음. 가격은 [공식 가격표](https://developers.openai.com/api/docs/pricing) 확인 후 pricing.json에 고정했다. 보수적으로 전체 입력에 long cache-write 단가를 적용했으며 실제 청구액과 다르다.
- 지연은 GenerationAnswerer 내부 측정값으로 첫 클라이언트 초기화를 포함할 수 있다. 사전 검색/분류 및 HTTP 전체 요청 지연은 포함하지 않는다.
- 완료 후 동일 실행 재개 검증: 완료 24개 건너뜀, 신규 호출 0회. 시작만 남은 요청 자동 재호출도 차단한다.
- manifest: `a731546fb7d0fdf584f297a611e576e2df83bd912ccfc4e1cf66e2843bf991ad`.

## 검증

- 전체 Python unittest **1075개 통과**. Ruff check 및 format check 통과(최종 재검사 619개 Python 파일).
- 기존 활성·보관 프로필 동일성, 정확한 후보 추가 문구, 공통 JSON 지침, 개행 보존, 빈 근거 허용/장애 구분, 명시적 RAG 지원 집합, 호출 상한·재개·변경 탐지 등을 mock으로 검증했다.
- 현재 /chat Markdown 표시 경로에 저장 응답을 주입해 1280px/360px 총48개 화면 상태를 확인했다. 가로 넘침 0, 페이지 오류 0. 첫 스크린샷 실행48회와 계측 실행48회로 브라우저 mock 응답은 총96회이며 모델 추가 호출은 0회다.
- 웹 코드 변경 없음. 화면 테스트는 당시 공유 작업 트리 상태이며 browser-results.json에 소스 해시를 기록했다. 실제 기기/스크린리더 검증은 하지 않았다.

## 한계와 다음 판단

각 질문·후보 1회인 진단이다. 반복 안정성, 일반 정확도, 운영 신뢰성을 입증하지 않는다. 내용 보존과 가독성은 분리해야 하며, 짧아져 읽기 쉬운 답변도 필수 안내가 빠지면 채택하지 않는다. 후속 작업은 사고 대응 인계·기록의 누락을 줄이는 방식부터 별도 계획으로 검증하는 것이 적절하다. 이번에는 추가 튜닝이나 호출을 하지 않았다. 원자료는 저장소 내부 영구 경로에 있으나 Git ignore 대상이므로 Git 백업과 동일하지 않다.

경계 재검토에서는 근거에 없는 메일 회수 기능을 필수로 요구한 감점과 모호한 15분 표현의 중대 오류 확정을 철회했다. 최초 판정은 [초기 판정](blind-judgments.initial.json)에 보존했다. 사전 루브릭이나 채택 조건은 변경하지 않았다. v7 출장 답변의 조건부 대체 구매를 예약 이후 번호 단계로 배치한 점은 구조 미충족으로 정정했다.

## 후속 사용자 채택 결정

위 내용은 실험 종료 시점의 보류 판정이다. 이후 사용자가 알려진 누락을 수용하고 v7 RAG를 선택했다. 이는 사전 게이트 통과로 점수를 바꾸는 결정이 아니다. [채택·배포 기록](../../../docs/worklogs/2026-10-16-rag-v7-adoption.md)을 따른다. 전체 문맥·DB·색인·스크린샷은 로컬 영구 실험 폴더에 보존하고 Git에는 응답·평가 기준·정확한 system 본문·해시·요약을 게시했다.

후속 적용은 로컬·운영 모두 완료했다. 별도 연결 확인은 총2회이며 [실제 응답·비용·표시 측정](adoption-smoke.json)을 따른다. 로컬은 불릿0, 운영은 불릿5로 반복 구조 준수는 보장하지 않는다.
