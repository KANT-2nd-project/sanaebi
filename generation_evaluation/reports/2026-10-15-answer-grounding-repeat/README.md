# v1·v3 반복 비교: 이전 소표본으로 성능 저하를 단정할 수 없음

사용자가 각2회 결과의 우연성을 지적해 동일 신고 질문·71개 합성 문서·모델·추론 설정으로 반복 비교했다. **새 각25회에서는 v1보다 v3의 완전 응답 비율이 높았다. 이전 결과를 v3의 성능 저하 증거로 해석해서는 안 된다.** 다만 이번 결과도 우월성·동등성을 확정하지 않는다. 서비스 기본값은 v1을 유지하며 프롬프트를 수정하거나 승격하지 않았다.

## 결과

| 판정 | v1 | v3 | 차이(v3−v1) | 양측 Fisher p |
|---|---:|---:|---:|---:|
| 기존 엄격 기준: 필수 정보 완전 | 15/25 (60%) | 20/25 (80%) | +20%p | 0.2165 |
| 보호 또는 연락 중 하나 인정 | 17/25 (68%) | 22/25 (88%) | +20%p | 0.1706 |

엄격 기준 완전 응답률의 Wilson95% 구간은 v1 **40.7–76.6%**, v3 **60.9–91.1%**다. 차이가 없다고 단정하거나 비유의성을 동등성·안전성 증거로 해석하지 않는다. 이전처럼 v3가 더 나쁘다는 관측 방향은 재현되지 않았다. 누락 자체는 두 프로필 모두 반복됐다.

엄격 기준에서 연락 방식 누락은 v1 9회/v3 4회, 목격자는 6회/3회, 보유 자료는 6회/1회다. 전체 입력 목록을 생략한 응답은 각1회다. 50개 모두 직접 제출 불가와 올바른 접수 경로를 안내했고 정상 JSON이었다. AI가 각 응답 전체를 근거와 대조한 비블라인드 판정이며 사람 승인이 아니다.

## 중단과 분모

최초 계획은 신고 각40회와 출처 각5회, 총90회였다. 사용자가 실행 도중 적당한 표본에서 중단·보고하도록 변경했다. 프로세스 중단 시 **51개 응답 저장, 1개 호출 취소** 상태였다. 비교표는 양쪽 모두 확보된 반복1–25의 50개다. v3 반복26은 목격자·연락 방식이 빠져 두 기준 모두 불완전하며 원응답과 판정을 그대로 보존한다. 이를 포함해도 v3는 엄격20/26(76.9%), 완화22/26(84.6%)로 관측 방향이 바뀌지 않는다. 취소된 v1 반복26은 모델 실패로 세지 않으며 결과·사용량은 알 수 없다. 유리한 응답만 골라 제외한 것이 아니다.

중간 응답을 보면서 사용자 요청에 따라 멈췄으므로 고정 표본 실험의 확증적 유의성 주장에 사용하지 않는다. 구간·p값은 독립 생성 근사 아래 **기술적 참고값**이다. 모델 백엔드·시간 변화·호출 간 상관은 통제하지 못했다. 같은 한 질문의 반복이므로 질문 모집단의 일반 성능을 나타내지 않는다. 원래 배포 실패 질문의 근거 없는 의심, 출처 노출 반복 안정성, 12문항 전체 회귀, API·브라우저는 이번 실행에서 검증하지 않았다.

확인 가능한51회 추정 비용은 **$0.75131825**다. 취소1회는 사용량 미확인이며 예약 상한 $0.06280425를 유지했다. 원장상 보수적 합계는 **$0.81412250**다. 실제 청구액이 아니다. 자동 재시도는 없고 공개 배포·재시작·실제 DB 접근도 없었다.

## 평가 기준의 한계와 다음 판단

기존 기준은 보호와 연락을 모두 요구했지만 원문은 “원하는 보호나 연락 방식”이다. 이 기준이 과도할 가능성을 발견해 초기5개 응답을 읽은 뒤 완화 분석을 추가했다. 사전 주 분석과 사후 추가 분석을 구분했다. 원질문은 대신 신고를 요청했으므로 목록 전체를 항상 요구하는 평가가 실제 사용자에게 필요한 수준인지도 별도 검토가 필요하다. 이전 게이트 실패는 보수적 채택 기준 미충족이며 인과적 성능 저하의 증명이 아니다.

다음 판단은 v3를 실패작으로 확정하고 다시 수정하는 대신, 후보를 유지한 채 질문별 필수 정보 기준을 정리하고 원래 개선 목표·다른 회귀 문항을 확인하는 것이다. 이 문서는 제안이며 추가 호출이나 기본값 전환을 실행한 기록이 아니다.
