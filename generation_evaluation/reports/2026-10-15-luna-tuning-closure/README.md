# 프롬프트 튜닝 종료와 기록 완전성 점검

사용자는 보강안 `examples_answer_scope_v1`을 최종 채택하고 튜닝을 종료했다. 현재 결정은 [최종 프롬프트 기준](../../../docs/generation-final-prompt.md)과 [decision.json](decision.json)을 따른다. 과거 점수·탈락 판정·일시 중단 기록은 삭제하거나 성공 판정으로 변경하지 않는다.

## 점검 결과와 보완한 누락

점검 전에는 모든 과정이 게시된 상태가 아니었다. 기존 coverage 실험의 최종80응답과 중단 checkpoint는 로컬 미커밋 상태였고, Notion에는 개발48응답까지만 게시되어 있었다. 추가4문항은 tmp에만 있었으며, 사용자 최종 채택 결정은 아직 기록되지 않았다. 조사 자료는 원래 요청대로 tmp에 저장되어 후속 구현과 연결하는 장기 기록이 부족했다.

이번 정리에서는 기존 자료를 재집계해 보존·게시하고 추가4문항의 원응답·검토·manifest, 조사 출처 목록·원자료 해시, 최종 설정·system 프롬프트를 함께 남겼다. 오래된 현재/진행 중 표현은 해당 시점의 역사 기록임을 표시하고 최신 결정으로 연결했다. 코드나 모델 호출을 추가하지 않았다.

## 미완료로 종료한 범위

기존 paused 실험은 총188회(개발48+최종80+회귀60), 원장 추정$2.03041528, 미정산0이다. 회귀 original의 reference20+coverage20은 실행됐지만 마지막10응답의 블라인드 판정과 N01 경계 재검토가 남았다. reasoning coverage20은 실행되어 completed19·parse_error1이었고, reasoning reference20은 시작하지 않았다. 해당 paired40 비교와 회귀 전체 품질 집계는 완료되지 않았다. 원자료·중단 기록을 보존하되 이번 튜닝 종료에 따라 추가 실행·미판정 보충을 하지 않는다.

후속 scope/strict 실험은 사전 게이트에 따라 개발1차에서 종료했다. 반복 확인24회·조건부 조합24회·최종80회는 실행하지 않았다. 이는 사용 가능한 호출166회를 다 채우지 못한 실패가 아니라 조건부 종료 규칙 적용이다. 별도 추가4문항은 새 원장·실행 폴더를 사용했으며 기존 탈락 기록을 재개하거나 덮어쓰지 않았다.

## 추가4문항에서 남은 문제

JSON4/4 정상, 응답 시간 중앙6.00초·최대8.13초, 추정 비용$0.00623765였다. 버그 전달 시 요청 유형과 신고 시 목격자 정보 안내가 누락되어 각각 부분 충족이다. 우편실 문의는 정보 부재·문의 경로를 모두 알려 통과했으나 불필요한 유보 표현이 남았다. 기능 요청의 승인·출시 일정은 근거 범위를 지켰다. 이미 본 개발 문항을 대상으로 한 단회 확인이며 독립 holdout 검증이 아니다.

최종 채택은 이 한계를 확인한 뒤 사용자가 내린 결정이다. 18/20 승격 기준 달성, 일반 운영 정확도, 독립 사람 검수 또는 사용자의 독립 구현 숙련도를 입증하지 않는다.

## 검증과 기록 경계

- 기존 개발48·최종80의 응답/판정을 현재 집계기로 재계산하여 저장 요약과 완전히 일치함을 확인했다.
- 후속36응답과 추가4응답, 호출 원장 수, 선택된 system 프롬프트·설정과 문서 링크를 대조한다.
- 이번 작업은 문서·기록 감사다. 기존 생성 테스트245개 통과는 직전 구현 검증 기록이며 이번 문서 작업의 신규 모델 실험으로 표현하지 않는다.
- 회귀 미판정 항목은 명시적으로 남겼다. “기록 정리 완료”가 “계획한 모든 평가 완료”를 뜻하지 않는다.
- 조사 출처 목록은 당시 조사 결과의 보존본이다. 이번에 외부 사이트를 전부 다시 조회한 것으로 표현하지 않는다.
