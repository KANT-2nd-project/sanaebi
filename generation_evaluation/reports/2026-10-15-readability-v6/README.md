# 답변 가독성 v5/v6 비교 — v5 기본값 유지

사용자는 도움 소개가 한 문단에 밀집한 문제를 제기했다. AI가 공개 레퍼런스를 조사하고 기존 v5에 문단·목록 선택 지침을 덧붙인 v6 후보를 구현했다. 사전 독립 검토 후 고정 8문항을 두 후보에서 각 1회, 총 **16회** 실행했다. 결과를 본 뒤 프롬프트를 수정하거나 재호출하지 않았다.

**결정: v6 후보는 보존하지만 기본값으로 채택하지 않는다.** 공통 기본값과 company-final-v1은 v5를 유지한다. 모델·xhigh·출력16384·180초·prompt_json·temperature 미전달도 유지한다.

총 비용 추정은 **$0.23940425**다. [공식 요금](https://developers.openai.com/api/docs/pricing)을 2026-10-15 확인했고, Standard 장문맥 cache-write 입력 $0.25/M 및 출력 $0.75/M로 모든 토큰을 계산했다. 캐시 할인 없는 보수적 추정이며 실제 청구액이 아니다. 사용량은 16회 모두 확인됐다. 사전 예약 추정 $1.1751695는 UTF-8 바이트 기반 여유 추정이며 실제 청구액·엄밀한 토큰 상한이 아니다.

판정은 후보명을 가린 별도 AI가 수행했고, 경계 사례는 전체 원문으로 재검토했다. 8문항 중 기존 관측 질문을 포함하고 각 후보 1회뿐이므로 우월성·반복 안정성·일반 정확도·서비스 품질 승인을 의미하지 않는다. 명시적 중대 허구가 0이어도 필수 안전 안내 누락은 내용 실패다.

## 개선과 퇴행, 채택 보류 이유

- **도움 소개 R01:** v6는 1문단에서 2문단으로 나뉘었지만 업무 분야가 긴 문장에 나열됐고 불릿은 없었다. 대표 업무 목록을 분리한다는 채택 조건 미충족이며 독립 검토에서도 더 간결한 v5를 선호했다.
- **조건 분기 R04·부분 답변 R05:** v6의 조건별 불릿과 조회 한계의 별도 문단은 훑어보기에 유리했다. 두 후보 모두 내용은 통과했다.
- **출장 절차 R03:** 두 후보 모두 내용 통과. v6는 결제 전 대체 구매와 예약 후 기록을 같은 4번 단계에 넣어 시간 순서의 가독성이 떨어졌다. v5는 조건부 대체 경로를 별도 문단으로 분리했다.
- **사고 대응 R08:** 두 후보 모두 24시간 당직·15분 인수 목표·무응답 시 대체 인계 등 필수 안내를 빠뜨렸다. v6는 v5에 있던 발견 시각과 실제 회수 여부 확인도 명시하지 않아 필수 안내 보존의 퇴행이 있다. 새 가독성 지침이 인과적으로 오류를 만들었다고 단정하지 않지만 이번 응답은 채택 기준을 충족하지 못했다.
- **판정 정정:** 최초 검토는 v6의 ‘보안 > 사고 신고’를 발명된 메뉴로 판단했다. 부모 검토자가 전체 snapshot의 ieum-069·071에서 명칭을 찾아 제시했고, 같은 익명 검토자가 재조회해 이 판정을 철회했다. 직접 근거 문서와의 명칭 연결은 주의할 점이지만 허위 경로로 확정하지 않는다. 관련 문서의 AND 조건을 옮겨오지 않고 직접 근거의 OR는 유지했다. 최초·최종 판정을 모두 보존한다.

추가 튜닝 없이 종료한다. 이후 재개한다면 도움 소개의 실제 목록 예시와 조건부 절차 분리를 시험할 수 있으나, 이번에는 새 후보·추가 호출·후처리 서식 강제를 도입하지 않았다.

## 검증과 화면 확인

- 생성 unittest **117개**, runtime unittest **210개** 통과. v5 저장본 일치, v6 입력 보존, JSON 내부 개행, 공통 기본값·CLI 동일성 포함.
- 저장소 전체 Ruff check 및 format check 통과. 최종 파일 수는 작업 일지에 기록한다.
- 실행기 mock: 16슬롯·교차 순서·실패 1개 보존·사용량 누락 비용 예약·프롬프트 해시 일치·동일 결과 경로 재실행 차단 확인.
- 실제 결과 16개 JSON은 부모가 별도 파싱해 answer 단일 키와 문자열 일치를 확인했다. 모든 실제 프롬프트 해시가 사전 manifest와 일치한다.
- Playwright로 저장 응답 16개를 1280px·360px 채팅 화면에 주입했다. 최종 **32개 표시 검사에서 가로 넘침 0개**이며 문단·목록·번호가 렌더링됐다. R01 v6는 양쪽 화면에서 문단 2개·불릿 0개였다. 최초 화면 캡처와 측정 재생을 합쳐 mock 응답 64개이며 backend/model 호출은 0개다.
- 화면 확인은 당시 미커밋 Markdown 공통 컴포넌트 작업 트리로 수행했다. [소스 해시·DOM 측정](browser-check.json)에 상태를 고정했고, 기존 웹 변경은 수정·커밋하지 않았다. AI의 Chromium 화면 확인이며 실기기·스크린리더·사람 사용성 검증은 아니다. 스크린샷은 tmp에 보존한다.
