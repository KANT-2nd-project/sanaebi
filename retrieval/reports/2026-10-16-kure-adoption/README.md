# KURE 채택·서버 연결과 기본 복원 준비

2026-10-16. 사용자는 필수 근거 유지와 전달량 감소를 우선해 KURE를 채택했다. 앞선 무관 질문 차단 최소 조건은 이번 사용자 결정의 채택 조건으로 사용하지 않는다. 당시 [보류 보고서](../2026-10-16-kure-gate/README.md)의 원점수·판정은 그대로 보존한다.

## 결정 근거와 한계

기존 개발 자료에서 필수 근거 완전 포함은 Tiny C 47/48, KURE 48/48이며, 신규 확인 당시 양쪽25/25였다. 신규 확인의 평균 전달량은35,740자에서6,404자로 감소했다. 관련 질문의 잘못된 차단은0/30, 무관 질문 차단은 양쪽4/10이었다. 회사 맥락의 무관 질문을 충분히 막는다는 뜻이 아니며, 코사인은 정답 존재 확률이 아니다.

이번에는 이 자료로 하한·상위 개수를 재튜닝하지 않았다. 기존108문항은 서버 구현 동등성 확인에만 재사용한다. 새 확인 성능·답변 품질·사람 검수로 표현하지 않는다.

## 적용 계약

- `nlpai-lab/KURE-v1` revision `8b418a58414668e75532ed045c22d9ca018ae2b2`, CPU FP32·CLS·L2·1024차원·접두사 없음.
- 질문 최고 cosine ≥ `0.42882221937179565`이면 병합 전 상위20청크를 선택한다. 개별 청크 하한·추가 문자·전달 토큰 제한은 없다. 동점은 기존 결정적 순서를 따른다.
- 질문512·문서8192토큰을 명시적으로 검사한다. 생성 제공자 한계와 오류 계약은 유지한다.
- 분할은 고정 Tiny tokenizer의360/60·제목·원문 구간을 유지한다. 모델 묶음의 `splitter/`에는 tokenizer만 준비하며 Tiny 가중치는 요구하지 않는다.
- KURE spec `bca3b6b3fc1fb803856881d853a8e7f12fa922310761cd6cb1dc52f862bdfc87`에는 모델과 splitter 식별값을 포함한다. 기존 Tiny spec·색인·복원 묶음은 보존한다.
- API·worker·색인·복원 명령·신규 릴리스 descriptor·Compose는 같은 KURE 계약을 사용한다. 기본 `rag`, 명시적 `full`, 환경변수 우선, 공개 API·분류·생성 설정은 유지한다.
- 게이트 차단은 자료 없음 안내로 끝나며 생성 예약을 하지 않는다. 장애 때 Tiny/full로 자동 전환하지 않는다.

준비·실행은 [RAG 안내](../../../docs/rag-runtime.md), 릴리스·구형 복구는 [배포 안내](../../../deployment/README.md)를 따른다. 현재 이미지에서 Tiny 자료를 KURE로 해석하지 않으며, 이전 Tiny 릴리스는 해당 이미지·descriptor·binding을 사용한다.

## 검증과 자료

고정 원본 SHA `84b44e6592e3a6bd883b7890239aada11382cbef9a369ebb0aca3b15defddfe4`의71개 문서·298청크를 실제 KURE로 계산해 별도 기본 복원 묶음을 생성했다. 기존 pilot 벡터와 최대 차이0, 동일 원문 구간·순서298/298을 확인했다. 기존 개발68·확인40의 전달 근거와 점수108/108이 동일했다. 이는 구현 검증이며 새 품질 실험이 아니다.

CPU affinity `[0,1]`, PyTorch2스레드. 매요청 SQLite snapshot·색인 상태/벡터 조회·질문 인코딩·정렬·병합과 잠금 대기를 포함한다. 질문 임베딩 캐시는 사용하지 않는다. HTTP/분류/LLM·동시 worker 부하는 이 시간에 포함하지 않으며 실제 운영2vCPU 성능으로 확대하지 않는다. 모델 로딩은3.82초로 별도 측정했다.

실제 KURE·격리DB·모의 생성 HTTP에서 snapshot 조회1회, 게이트 차단 예약0회, 전체 삭제·기본 복원 중 문서 임베딩0회와 새 revision 연결을 확인했다. 자정 reset은71개 준비완료이며 mapping-only 복구의 문서DB SHA가 유지됐다. 원본 reference DB도 전후 동일하다. 취소·동시 요청·실패 후 worker 복귀·오래된 개정 제외와 Tiny/full 복구는 회귀 테스트로 검증했다.

[실측 원자료](runtime-verification.json)와 [재현 스크립트](verify-runtime.py.txt)를 제공한다. 저장소 루트에서 스크립트를 별도 `.py`로 복사한 뒤 `PYTHONPATH=. uv run --locked python <복사한파일.py> --model <검증모델경로> --bundle <기본묶음.sqlite3> --output <새로운출력경로>`로 실행한다. 먼저 모델·기본 묶음을 [RAG 준비 명령](../../../docs/rag-runtime.md#준비와-실행)으로 준비하고, 로컬 참조 자료는 아래 대응표 위치에 둔다. 원자료·격리DB는 Git 제외 `artifacts/kure-runtime-verification-20261016/`에 보존한다. 로컬 경로는 공개 다운로드 링크가 아니다.

임시 폴더의 고유 자료는 [경로 대응·정리 기록](workspace-cleanup.md)에 연결한다. 기존 보고서·실험 응답·원점수와 Git 브랜치·커밋은 삭제하지 않는다.

[독립 검토](independent-review.md)의 splitter 식별·pooling 준비·설치 CLI import 지적을 수정하고 재확인했다.

## 운영과 기여 구분

사용자가 KURE 채택·로컬 main 작업·임시 폴더 정리·게시를 결정했다. AI가 구현·검증·독립 코드 검토·자료 보존·문서화를 수행했다. 유료 API·실제 LLM·운영 접속·배포는 수행하지 않았다. 실제 운영2vCPU·host 초기화 원본 동일성·사람 검수·생성 답변 품질은 후속이다.

게시·CI·Notion·일지와 자동 배포 제외 확인은 [작업 기록](../../../docs/worklogs/2026-10-16-kure-adoption.md#게시와-외부-반영)에 남겼다.
