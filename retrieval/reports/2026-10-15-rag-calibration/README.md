# RAG 검색 인자 보정 실험 결과

**결론: 기존 설정을 유지하고, 점수0.35·개수 제한 없음·4k Tiny 대체토큰 후보는 후속 검증 대상으로 남긴다.** 검색 근거와 답변 내용은 개선됐지만 작은 AI 평가 세트의 이점, JSON 전달 실패와 비용 증가를 함께 고려해 기본 교체를 보류했다. 운영 설정은 변경하지 않았다.

고정 Tiny 임베딩과 회사 문서의 검색·답변 비교를 완료했다. 정답과 관련도 판정은 AI 작성·독립 AI 검토이며 사람 검수 또는 실서비스 품질 승인이 아니다.

## 목적과 고정 조건

필수 사실 누락의 원인을 정답 기준, 검색 순위, 후보 선택, 예산 적용으로 구분한다. 기존 회귀18·개발20·답변불가10 문항과 기존 v1 자료를 보존하고, [qrels-v2.json](qrels-v2.json)에 사실 간 AND·대체근거 간 OR 기준을 별도로 고정했다. [신규 확인40](new-confirmation.json)은 실제 답변 실행 전 작성·독립 검토·동결했으며 기존48 및 과거 holdout20의 의도와 대조했다.

모델은 KoEn-E5-Tiny revision `292c09c78c71a3f00ed56ee0d1ed9f0d39182fc9`, 기존 게시 snapshot과 360/60 분할이다. 본문 예산은 8,000자, 근거당 2,000자다. 추가 토큰 예산은 문서ID·제목·개정·본문의 전달 형식 전체를 세며, 1k/2k/4k는 **Tiny 대체 계수**이며 Luna의 실제 생성 입력 토큰이 아니다. 모델에는 512 이내 입력만 전달한다. 긴 전달 문맥을 Tiny tokenizer로 세는 과정의 길이 경고는 임베딩 모델 입력 초과를 뜻하지 않는다.

## 검수와 측정 방법

- 최소 필수 사실, 선택적 정보, 답변 가능 여부 및 대체 근거를 결과·점수 없이 검토했다. [작성·수정 근거](qrel-author-notes.md)를 보존한다.
- 검색 후보5·10·20·40·전체의 필수 사실 재현율과 마지막 필수 근거 순위를 측정했다.
- 최종 근거 충분성과 검색 순위 관련도는 별도 지표다. 관련도0=무관,1=주제 관련,2=직접 부분근거,3=직접 핵심근거, Precision은2이상 기준이다. 관련도 검토자는 qrel의 필수 사실을 볼 수 있고 검색 설정·점수·승패는 보지 않았다(qrel-conditioned AI 판단). 동일 질문의 공통 판정 풀로 IDCG를 고정하며 미판정이 하나라도 남으면 Precision/nDCG는 null로 둔다.
- 답변불가 질문은 필수 사실 recall의 분모에 넣지 않는다. 문의 경로의 관련성과 실제 개인 상태를 답할 수 있는지는 구분한다.
- 토큰 예산 비교는 두 후보 계열과 기준선의 진단 그리드를 함께 기록한다. 설정별 성공 문항을 잃는지 확인하고 충분성→관련도→전달량→지연 순으로 후보를 정한다.

## 실제 답변 실행 계약

Luna·v5·xhigh·출력16,384·기존 JSON 계약을 유지한다. 개발48×최대3설정×2회, 신규40×2설정×2회로 정상 슬롯 최대448, 일시적 명시적 거절/형식 오류의 개별 재시도1회를 포함해 최대896이다. 비용 상한은 없으며 사용량과 추정 비용을 남긴다. 빈 근거는 고정 안내로 처리하고 API 성공 수에 넣지 않되 답변 평가에는 포함한다.

이전 중단5호출 자료는 읽기 전용으로 보존했다. 기존 형식 오류 원응답은 JSON 객체가 아닌 일반 한국어 본문이었다. 파서를 우회하거나 프롬프트를 수정하지 않고 첫 실패와 재시도를 모두 집계한다.

호출 비용은 [공식 가격 안내](https://developers.openai.com/api/docs/pricing)를 참조하여 기존 원장의 보수적 long-tier 입력/cache-write 및 출력 요율로 예약한다. 이는 청구서 확정 금액이 아니다. 인증·설정 오류, 사용량/완료 여부 불명확, 기록·원장 저장 실패는 중단하며 자동 재요청하지 않는다.

## 로컬 검증과 남은 범위

전체 Python859개, Ruff check·format check와 독립 코드·결과 검토를 완료했다. 세부 검증과 상태는 [execution-status.md](execution-status.md)에 기록한다. 전체 삭제·기본 복원·새 개정 필터·미준비503에서 예약0·자정 복원 모델 추론0·worker 정상 종료를 격리 저장소에서 재검증했다. 개발 PC affinity2 결과를 실제 운영2vCPU 결과로 취급하지 않는다.

사람 검수, 실제 운영 서버 측정, RAG 운영 활성화, 커밋·푸시·Notion 반영은 이번 실행에서 하지 않는다.

## 실행 수와 원자료

예정448슬롯을 모두 처리했다. 빈 문맥 고정 안내8개를 제외한 API440슬롯에 재시도16회를 더해 **실제456회** 호출했다. 최초 JSON 성공424/440, 재시도 복구15/16, 최종 JSON 성공439/440이다. 실패 원응답도 보존했으며 더 좋은 답변을 고르기 위한 재실행은 하지 않았다.

입력2,319,674토큰·출력195,560토큰, 사용량 기반 총 추정 비용은 **$0.7265885**다. 청구서 확정 금액이 아니며 이전 중단5호출 비용을 포함한 역사 전체의 비용도 아니다. 원장의456개 요청과 원응답을 일대일 대조해 모두 정산 상태임을 확인했다. [호출·비용 기록](cost-and-calls.json), [확인 답변 집계](confirmation-answers-summary-rechecked.json)에 근거를 남겼다.

실제 Tiny는 CPU에서 실행했고 기존 문서 벡터와 고정 snapshot을 재사용했다. 모델·DB·비밀값은 보고서에 복사하지 않았다. 원본 작업 폴더의 동시 서버 변경을 덮어쓰지 않았으며 실험은 별도 작업 공간의 HEAD `2dbe3f7`에 고정했다.

최종 독립 재대조에서 P05 한 판정이 claim에 없는 부가 사실을 요구한 오류임을 확인해 원 판정자가 정정했다. 질문·정답 기준·응답은 바꾸지 않았으며 최초 판정·최초 집계도 보존했다. 최종 확인 값은 `*-rechecked` 파일을 기준으로 한다.
