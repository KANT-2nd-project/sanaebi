# 누락 원인과 답변 오류의 구분

## 검색 단계

기준선의 실패4문항을 동일 문서·동일 벡터에서 추적했다. [claim-trace.json](claim-trace.json)은 필수 사실 → 허용 원문 구간 → 해당 청크 → 점수·순위 → 후보 포함 → 최종 전달 여부를 연결한다.

| 질문 | 마지막 필수 근거 순위 | 기준선 직접 원인 | 해석 |
|---|---:|---|---|
| R08 | 15 | 후보10 밖 | 임계값을 낮추거나 후보를 늘리면 포함 가능하다. |
| R14 | 25 | 후보10 밖 | 상위5/10만으로 충분하지 않다. |
| R16 | 39 | 후보10 밖, 점수0.3275로0.35에서도 제외 | 해당 청크의 제목·조치 본문은 온전하다. 분할 손상으로 단정하지 않는다. |
| D07 | 후보10 안 | 최대5개 최종 선택에서 제외 | 검색 후보의 포함과 실제 전달 근거의 포함은 다르다. |

후보를 늘리면 모든 필수 근거를 얻는 문항 수는5개34/38 →10개35/38 →20개36/38 →40개38/38이다. 전체298개도38/38이다. 이는 **원문 후보 풀의 상한 진단**이며 후보40개를 그대로 모델에 주면 좋다는 결론이 아니다. 관련 없는 내용·예산·지연을 함께 봐야 한다.

0.35 무제한도 본문8,000자·근거당2,000자 상한은 유지한다. “무제한”은 근거 개수 제한만 없다는 뜻이다. 4k Tiny 대체 토큰 예산을 추가하면 개발 근거 완전 포함은37/38에서36/38로 낮아진다. 최종 답변은 반대로 조금 좋아졌으므로 근거 recall 하나로 답변 품질을 대신 판단할 수 없다.

이 실험은256/448 재분할의 실행 조건인 ‘분할 때문에 필수 사실을 잃은 증거’를 확인하지 못했다. 두 분할 대안은 미실행·후속으로 남겼다. 낮은 순위와 임계값 제외에 대해서는 후보 확대 후 재정렬이 후속 가설이며 새 reranker를 도입하지 않았다.

## 개발 답변 단계

동결 v2의 strict 누락은 [문항별 반복 결과](development-question-outcomes.csv)와 [전체 시도 집계](development-answers-summary.json)에 남겼다.

- 기준선의 실질적인 비정오표 누락은 D07의 “구매 승인이 계정 권한을 자동으로 부여하지 않는다”는 구분이었다. 두 반복에서 빠졌고 두 확장 후보에서는 전달했다.
- 무제한 후보는 R11 첫 반복에서 추가 필수 사실을 빠뜨렸다. 4k 후보는 해당 두 반복을 충족했다. 한 반복의 차이를 안정적인 성능 차이로 단정하지 않는다.
- D02·D04·D14에는 질문이 요구하지 않는 선택 정보를 필수로 결합한 평가 기준 문제가 있었다. [정오표](qrel-errata.md)를 적용해 주 점수를 사후 수정하지 않았다. 이 사례를 모두 서비스 답변 오류라고 부르지 않는다.
- 세 구성 모두 독립 AI 판정에서 개발 최종 답변의 중대한 오류·근거 없는 확정은0건이었다. 합성 질문·원문과 AI 판정 범위에서의 결과이며 사람 승인이나 운영 무오류 보장이 아니다.

개발 API280슬롯 중 최초 JSON 준수는268건이고12건은1회 재시도로 복구됐다. 빈 근거8슬롯은 API를 부르지 않고 고정 안내했다. 최초 일반 텍스트 응답은 그대로 남겼으며, 내용이 맞더라도 첫 정상 전달 성공으로 세지 않았다.

## 확인 단계

신규40문항 결과는 최종 보고서와 확인 집계에 별도로 기록한다. 개발과 확인을 합쳐 하나의 정확도로 만들지 않으며 확인 세트로 임계값·예산·프롬프트를 다시 조정하지 않는다.
