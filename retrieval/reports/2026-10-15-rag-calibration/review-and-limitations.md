# 독립 검토와 해석 한계

## 검토 경계

질문·원문·필수 사실 검토는 설정명·점수·승패를 가렸다. 관련도 검토는 결과 합집합의 원문을 제공하고 설정·점수·승패를 가렸지만, 동결 qrel의 필수 사실은 제공했다. 따라서 qrel-conditioned AI 관련도 판단이며 완전히 독립적인 사람 정답이 아니다.

답변 판정자는 질문별 무작위 A/B/C와 모든 최초·재시도 본문을 받았다. 설정·검색 점수·비용·매핑은 제공하지 않았다. 두 판정자가 문항 묶음을 나누어 검토했으며 모든 답변에 두 명의 중복 판정을 한 것은 아니다. 판정자는 원문 전체와 qrel을 기준으로 사실 정확성을 판단했다. 실제 전달된 검색 근거만으로 그 답변을 만들 수 있었는지는 별도의 span 충분성 지표로 구분한다. 검색이 누락돼도 모델이 우연히 정답을 말할 수 있으므로 정답률을 근거 충실성으로 바꾸어 해석하지 않는다.

dev-1 판정자는 보조 검색 과정에서 원본 attempt 파일명에 포함된 설정명을 보았으나 해당 파일 내용·질문별 매핑·점수·비용은 읽지 않았다. 설정 후보 존재를 전혀 모른 상태의 완전한 블라인드라고 표현하지 않는다. 이후 묶음은 제공된 블라인드 패킷으로만 판정했다.

## 검토에서 수정한 실행기 경계

- 실제 provider 오류 기록과 원장 정산이 모두 확인되어야 재시도할 수 있도록 보호했다. 저장 실패를 일시적 provider 오류로 오인해 재요청하지 않는다.
- 두 번의 JSON 오류로 종료된 슬롯도 판정 패킷에 포함한다. 최초 실패가 사라지지 않는다.
- 빈 검색 결과의 고정 안내는 `attempt=0`으로 판정하며 API 성공으로 집계하지 않는다.
- 개발48과 확인40의 qrel SHA를 각각 검증하여 확인 단계가 개발 질문을 잘못 재사용하지 않게 했다.
- 4k 예산은 본문만이 아니라 제목·ID·개정 등 전달 형식 전체의 Tiny 대체 토큰 수로 계산했다. 실제 Luna 입력 토큰과 구분한다.
- 캐시 모델 revision·차원·정규화·파일 SHA를 확인한다. 관련도 판정의 중복 ID나 풀 외 ID를 거절한다.
- 429가 명시적으로 거절되고 동일 요청의 원장 정산이 0으로 확인된 경우만 0비용을 인정한다. 미확인 비용을 0으로 덮지 않는다. 실제 executor가 저장하는 `retryable_provider_error` 상태로 회귀 검증했다.

실제 개발 실행을 시작한 뒤 provider 호출 실행기와 생성 코드는 변경하지 않았다. 보조 패킷·집계 코드 수정은 원응답을 바꾸지 않고 보존된 기록을 올바르게 읽도록 한 것이다. 최종 독립 코드 검토자는 집중 테스트 27개를 직접 통과시켰으며 실제 API 호출이나 운영 코드 변경을 하지 않았다.

## 개발 결과의 독립 재대조

별도 읽기 전용 검토자가 288개 슬롯과 판정을 매핑에 대조하고 완전성·토큰·호출 수·비용 집계를 확인했다. 동결 v2 완전성은 기준선88/96, 무제한90/96, 4k후보91/96이며 정오표3문항 제외 진단은88/90,89/90,90/90이다.

4k후보의 비정오표 이점은 **D07 한 질문의 두 반복**이다. 무제한 후보와의 차이에는 R11 첫 반복 한 건이 포함된다. 반복별 완전성은 기준선44·44/48, 무제한44·46/48, 4k후보45·46/48이다. 96개의 독립 질문이나 일반 성능의 안정적 개선으로 해석하지 않는다.

## 측정과 보존 한계

- 동결 후 D02·D04·D14의 과잉 필수 요소를 발견했다. [정오표](qrel-errata.md)에 기록하고 주 점수와 동결 JSON은 수정하지 않았다. 새로운 확인 세트로 반복 튜닝하지 않았다.
- 관련도 풀은 비교 범위의 상위40 원문이다. 전체298청크의 관련도를 모두 판정한 것은 아니다. P@5와 nDCG@5는 후보 순위 지표이며 최종 잘린 근거의 관련도를 그대로 뜻하지 않는다.
- 1,920개 풀 항목은 모두 판정됐다. U01·U05는 이상적인 관련도 이득이0이어서 nDCG가 정의되지 않는다. 미판정 때문에 null인 경우와 구분한다.
- Tiny 512토큰 입력 제한과 생성 문맥 1k/2k/4k 대체 토큰은 서로 다른 제한이다. 코사인0.35는 관련 확률35%가 아니다.
- 비용은 provider 사용량에 저장된 요율을 적용한 추정값이며 청구서 확정 금액이 아니다. 재시도 비용을 포함한다.
- 개발 PC CPU affinity2는 실제 운영2vCPU가 아니다. fresh process의 모델 로딩은 측정했으나 OS page cache를 비우지 않았다.
- mapping 복구의 원본 쓰기 보존은 DB SHA·크기 동일성 및 회귀 테스트로 확인했다. 실제 CLI의 모든 write syscall을 계측한 것은 아니다.
- 첫 폐기된 측정 준비에서 원본 index의 SHM 수정시각만 변했다. 파일 내용 SHA·크기는 유지됐고 시간을 인위적으로 복원하지 않았다. 최종 측정은 복사본만 사용했다.
- 기존 원본 작업 폴더는 동시에 갱신됐다. 이번 실험은 명시한 별도 HEAD에 고정했으며 최신 서버 변경을 통합했다는 주장이 아니다.

## 실행 종료 후 기록 필드 수정

확인 실행의 `registered_total_planned_calls`는 필드 이름과 달리 해당 phase의160만 표시했다. 공유 계획 원장에는448이 정확히 저장됐고 호출 상한도 합산448로 검사됐다. 실행 종료 후 반환값을 합산값으로 고치는1줄 수정과 회귀 테스트를 적용했다. 과거 실행 JSON은 수정·재실행하지 않았다. 실행 당시 코드는 `code-snapshot-executed.json`, 최종 수정본은 `code-snapshot-final.json`로 구분한다.

## 확인 결과의 최종 독립 재검토

읽기 전용 결과 검토자가 실제 응답·판정·집계·원장을 대조해 P05 한 건의 판정 오류를 발견했다. 동결 claim이 요구하지 않은 ‘기존 담당자가 떠나는 시점’을 필수로 더한 오류였다. 원 판정자는 원래 블라인드 패킷과 claim만 재검토해 수정에 동의했다. `answer-grades-confirmation-5.json`은 보존하고 `answer-grades-confirmation-5-rechecked.json`에서 해당 한 건만 수정했다. qrel과 실제 응답은 바꾸지 않았다.

최종 확인 집계는 `confirmation-answers-summary-rechecked.json`, 문항별 표는 `confirmation-question-outcomes-rechecked.csv`다. baseline 내용 완전77/80, 후보78/80이고 정상 전달 완전성은77/80 동률이다. P05 개선 주장은 제외했다. 최초 집계와 원 판정도 감사용으로 남겼으며 최종 파일과 혼용하지 않는다.

정정 후 결과 검토자가 재대조해 변경이 P05 첫 반복 한 건뿐이고 원자료·호출·토큰·비용은 동일함을 확인했다. 최종 README·판정·CSV가77/80 동률을 일관되게 설명하며 P05 개선 주장이 제거됐음을 재확인했다. 추가 중대한 지적은 없었다.
