# RAG 문맥 제한 방식 빠른 비교

> 후속 사용자 결정: 검색 근거 누락 최소화를 우선해 **C를 채택**했다. 아래 B 권고·C 보류는 당시 평가 결론으로 보존한다. [최종 선택·적용 상태](../2026-10-15-c-adoption/README.md)를 따른다.

**검색 비교와 개인 API 키 교체 후 실제 답변 비교를 완료했다.** A/B/C 모두 필수 사실 충족11/12로 동률이며 C의 추정 비용은 B의2.38배였다. B를 단순화 후보로 유지하고 C 채택은 보류한다. 서버 설정은 변경하지 않았다. 자세한 최신 결과는 [재개 후 결과](resumed-results.md)와 [답변 비교표](answer-comparison.csv)를 참고한다.

아래 중단·미완료 설명은 키 교체 전의 과거 실행 기록이다. 새 실행과 원장을 분리해 보존했다.

## 조건과 검색 결과

모든 구성은 KoEn-E5-Tiny 고정 revision, 동일 회사 문서 snapshot·벡터, 점수0.35 이상, 근거 개수 제한 없음이다. 비교한 제한은 생성기에 전달하는 검색 문맥이며 임베딩 입력512 제한을 없앤 것이 아니다.

|---|---|---:|---:|---:|---:|
| A: 기존 실험 설정 | 8,000 / 2,000 | 4,000 | 36/38 | 6,094 | 3,629 |
| B: 토큰 예산만 | 없음 / 없음 | 4,000 | 36/38 | 6,094 | 3,629 |
| C: 실험용 무제한 | 없음 / 없음 | 없음 | 37/38 | 25,766 | 15,308 |

근거가 있는38문항 기준이며 답변 정확도가 아니다. 필수 사실은 A/B65/67, C66/67이다. 평균 전달량은 답변 불가10문항을 포함한 전체48 기준이다. 답변 불가의 근거 recall은 null로 두었다.

A는 과거4k 후보의 전달 근거와48문항 전부 일치했다. A/B는45문항에서 완전히 같고 R03·R10·D04에서2~3글자의 토큰 경계 차이가 있다. 기존 문자 예산 이분 탐색의 탐색 범위가 달라 생긴 차이이며 필수 근거 판정은 같았다. 실제 답변 비교로 고정한12문항은 A/B 입력이 모두 동일하다. 추후 응답 차이가 나도 이를 문자 제한 제거의 효과로 해석하면 안 된다.

C는 R14의 독립 PR 검토 근거를 추가 확보했다. R16의 자격정보 폐기·회전 근거는 점수0.3275로0.35 하한에서 이미 탈락해, 문맥 제한을 없애도 복구되지 않는다. C에서 후보 단계와 최종 단계의 필수 사실 포함 수가48문항 모두 같음을 확인했다.

C의 평균 문맥은4.22배, 최대36,852 Tiny 대체토큰이었다. 이는 Luna의 실제 입력 토큰이나 청구 비용 배수가 아니다. C는 최대170개 근거를 전달했고, 테스트에서는 총8,000자·근거당2,000자·개수 제한이 남지 않았는지 따로 확인했다.

## 실제 답변 비교 상태

12문항×3구성×1회36슬롯을 고정했다. U01의 세 구성은 빈 근거여서 원래 API33호출을 계획했고, 재시도 포함 상한은72회로 설정했다. 신규 확인40은 읽어 튜닝하거나 재실행하지 않았다.

첫 R01/A 호출이 `OpenAIRateLimitError`로 거절됐고, 허용된1회 재시도도 같은 오류로 거절돼 실행기가 중단됐다.

- 실제 요청 시도2회, 받은 모델 답변0개.
- 첫 슬롯 실패, 나머지35슬롯은 `not_run_after_stop`. 빈 근거 안내3개도 실행상 성공으로 세지 않는다.
- 원장 두 요청 모두 명시적 거절·0으로 정산됐다. 청구서 확인 금액이라는 뜻은 아니다.
- 사용량·실제 답변 품질·JSON 성공률·모드별 비용 및 지연 비교는 미완료다.
- 오류 클래스·시간·요청 식별값·원장을 보존했다. 최초 실행기는 HTTP 오류 본문을 저장하지 않아 당시에는 제한의 원인을 알 수 없었다. 이후 사용자 승인 재확인에서 크레딧 소진을 확인했다(아래 후속 기록).
- 실행 후 추가 호출, 다른 모델로 대체, 과거 답변을 이번 결과로 재사용하는 처리는 하지 않았다.

[실행 원본](evidence/execution.json)과 [거절 기록](evidence/attempts.jsonl), [원장](evidence/ledger.json)에 중단 근거가 있다. 새 실행이나 재개에는 실패 슬롯의 재시도 한도와 중복 요청 방지를 다시 정해야 하며 기존 폴더를 지우고 재실행해서는 안 된다.

## 판단과 남은 작업

**문자 제한 제거는 이 snapshot의 검색 평가에서 손실 없이 정리할 후보다.** 반면 토큰 예산 제거는 문맥량을 크게 늘려 한 문항의 근거를 추가했을 뿐, 실제 답변 개선은 확인하지 못했다. 따라서 B를 후속 비교의 단순화 후보로 남기고 C의 운영 채택은 보류한다. A/B/C 모두 서버에 적용하지 않았다.

빠른 개발 진단과 독립 AI 검토이며 사람 검수·운영 품질 승인·최적값 확정이 아니다. 다음 단계는 제공자 제한 해소 확인과 별도 실행 계약을 거친 답변 비교다. 이번 범위의 운영 접속·커밋·푸시·Notion 반영은 수행하지 않았다.
