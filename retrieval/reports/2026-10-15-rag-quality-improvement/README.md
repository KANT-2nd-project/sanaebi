# RAG 검색 품질 단계별 비교 — 2026-10-15

## 결과와 결정

세 개선안을 모두 구현하고 같은 Tiny 모델로 순서대로 비교했다. **인접 근거 확장은 기존18문항에서15→17건으로 개선됐으나 신규개발20문항은19건 동률이어서 사전 채택 조건을 통과하지 못했다.** 제목 경계 문맥 보완과 BM25 결합은 기존 성공 문항의 회귀가 있었다. 이번에는 기존 벡터 검색 구성을 유지한다. 서비스 기본 모드도 `full` 그대로다.

이 결과는 합성 문서·AI 작성 질문·독립 AI 검토 기반 검색 실험이다. 사람 검수, 실제 LLM 답변 정확도, 운영 품질 승인으로 해석하지 않는다.

기준 구현은 `6bccda3`이다. [평가 절차](evaluation-protocol.md)와 [고정 질문·정답 구간](cases.json)을 독립 AI 검토한 뒤 실제 모델 실행 전에 동결했다. 동결 SHA는 `d7b26c63df2fce658982770ec5c48c5dfd587447ce5d7ade4931e1ce866c4c3d`다. 필수 조건·예외·장소를 구간으로 지정하고, 중첩 구간은 합쳐 중복 가중을 피했다. 과거18개 문자열 정답은 별도 보존했다.

- 모델: `exp-models/dragonkue-KoEn-E5-Tiny`, revision `292c09c78c71a3f00ed56ee0d1ed9f0d39182fc9`, CPU FP32,384차원, mean pooling·L2.
- 원문:71개, SHA `84b44e6592e3a6bd883b7890239aada11382cbef9a369ebb0aca3b15defddfe4`. 새 SQLite를 만들고 source와 snapshot의 제목·본문 전체 일치를 검사했다.
- 본문360토큰/중첩60, 전체 입력512 이하. 후보10개, 최종최대5개,8,000자/근거당2,000자. 임베딩 문맥 후보만 앞뒤합계60토큰을 추가하고 별도 spec·기본 벡터 묶음을 생성했다.
- 키워드: Tiny tokenizer, 특수 토큰 제외, BM25 k1=1.2/b=0.75, 양쪽상위20개를 동일가중 RRF60으로 결합. 임베딩 전용 인접 문맥은 키워드 입력에서 제외했다.
- CPU affinity2개·torch thread1로 제한한 개발 PC다. 실제2vCPU 배포 서버와 같지 않다. 구체 CPU·메모리·spec·검색 상수·구현 fingerprint는 JSON manifest에 기록했다.

각 단계는 직전 **채택 구성**에 한 가지 방법을 추가했다. 앞 단계 미채택 시에도 다음 방법은 실행했다. 개발20문항의 완전 포함 건수가 증가하고 기존38문항의 성공을 모두 유지해야 채택하며, 동률은 기존 구성을 유지하도록 실행 전에 정했다. 결과를 보고 이 기준을 완화하지 않았다.

## 개발 비교

완전 포함은 질문에 필요한 원문 구간을 **모두** 포함한 문항 수다. 같은 문서를 찾았다는 것만으로 성공 처리하지 않는다.

| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | --- |
| 기존 벡터 검색 | 15 | 19 | 34 | 34 | 35 | 1,842 | 48.4/52.0 | 유지 |
| 제목 경계 문맥 | 16 | 18 | 34 | 34 | 36 | 1,785 | 51.2/55.0 | 회귀로 미채택 |
| 인접 근거 확장 | 17 | 19 | 36 | 34 | 35 | 3,263 | 47.4/52.5 | 신규개발 동률로 미채택 |
| BM25 결합 | 14 | 17 | 31 | 31 | 32 | 2,005 | 104.2/110.3 | 회귀로 미채택 |

인접 확장의 지연이 약간 낮게 관측된 것은 작은 단일 실행의 측정 차이며 속도 개선으로 주장하지 않는다. 전달 문자는 약77% 증가했다. 결합 검색은 이 규모에서 키워드 계산 비용도 늘었다.

- 기준선 누락: R08 지급일, R14 PR 자체 승인, R16 토큰 노출, D07 SaaS 구매 승인과 계정 권한.
- 제목 문맥: R16과 D07은 회복했지만 D13·D19를 새로 놓쳤다.
- 인접 확장: R14·R16을 회복했다. R08 지급일과 D07은 남았다. 검색 순위는 같아도 최종 전달 근거가 좋아질 수 있음을 보여준다.
- 결합 검색: R03·D19·D20 등 추가 회귀가 있었다. 한국어 WordPiece 기반 BM25가 이 고정 설정에서 더 좋다는 근거는 없었다.

이번 회귀18의 과거 문자열 지표도 최종 기준선15/18·문맥16/18·확장17/18·결합14/18로 확인했다. [최초 모델 선정](../2026-10-15-cpu-embedding-comparison/README.md)의 구간형 분할17/18과 현재 런타임 분할을 구분한다. 이번 주 지표는 다중 필수 구간이며 과거 성능을 덮어쓰지 않는다.

## 최종 확인과 한계

개발 기준을 통과한 새 구성이 없으므로 최종확인20문항에서는 기존 구성을 한 번 실행했다. **top5 19/20, 후보10 20/20, 최종근거19/20**이다. JSON의 candidate는 동일 baseline 결과를 참조하며 별도 두 번째 실행이 아니다. 새 후보의 우수성을 입증한 비교가 아니다. 최종 확인 후 설정·질문·정답 구간을 변경하거나 다시 실행하지 않았다.

답변불가10문항은 검색 결과만 별도 기록했다. 후보가 나왔다고 답변 가능으로 판정하지 않았고 거절 품질 점수는 계산하지 않았다. 실제 LLM 호출은0회다. 신규개발 기준선이19/20으로 높아 추가 이득을 구분하기 어려운 점도 한계다. 인접 확장은 후속 검토 후보지만 이번 사전 규칙에 따라 기본 검색에 자동 적용하지 않았다.

## 재현과 원자료

[개발 원자료](development.json), [최종 확인·답변불가 검색](holdout.json), [문항별 비교표](comparison.csv)에 source span·후보 ID·점수·분모·채택 여부를 남겼다. 큰 모델·색인·기본 벡터는 Git에 넣지 않는다.

```bash
uv run --locked python -m retrieval.experiments.quality --phase development \
  --model /absolute/path/to/koen-e5-tiny \
  --artifact-root tmp/rag-quality-reproduction --cpu-cores 2
uv run --locked python -m retrieval.experiments.quality --phase holdout \
  --model /absolute/path/to/koen-e5-tiny \
  --artifact-root tmp/rag-quality-reproduction --cpu-cores 2
```

모델은 [RAG 준비 안내](../../../docs/rag-runtime.md)의 고정 로컬 저장본을 사용한다. 동일 phase 재실행은 거부한다. 위 명령으로 나중에 재현한 결과는 이미 공개된 확인 세트의 재현이며 새 미열람 평가가 아니다.

실제 실행은 모델 경로 `tmp/rag-actual-smoke/model`, artifact-root `/home/jake/.cache/sanaebi-rag-quality-20261015/experiment`를 사용했다. 후자는 개발 머신의 로컬 경로이며 공유 다운로드 주소가 아니다. 명령 로그는 작업 공간의 `tmp/quality-development.log`, `tmp/quality-holdout.log`에 보존했다. 서버·복원·게시 검증은 [작업 기록](../../../docs/worklogs/2026-10-15-rag-quality-improvement.md)을 따른다.
