# RAG 저점수·근거 누락 원인 진단

## 결론

현재 문제를 ‘0.35라서 RAG가 작동하지 않는다’로 설명할 수 없다. 확인된 문제는 **정답 구간의 대체 근거 누락**, **구어체 질문과 정책 표현 사이의 순위 민감도**, **다른 내용과 함께 들어간 세부 조치의 순위 저하**, **선택량을 늘리는 정책에 비해 부족한 관련도 검수**다. 저장/캐시 오류나 입력 초과에 따른 자동 절단은 이번 검사에서 발견하지 못했다.

가장 중요한 정정: 독립 원문 검토가 찾은 대체 근거를 OR로 추가한 사후 민감도 분석에서는 A/B/C가 모두37/38이다. 앞서 C만37/38이라고 설명한 차이는 R14의 지정 구간만 인정한 평가에 의존했다. C의 일반 우위나 최적성을 뒷받침하지 않는다. 원래 qrel v2·실험 결과를 덮어쓰지 않고 별도 진단으로 보존한다. 사용자의 C 채택 의사는 변경하지 않았으며 서버 C 적용·rag 기본값 변경·게시도 이번 진단에서 실행하지 않았다.

## 범위와 방법

- 별도 작업 공간 HEAD `2dbe3f7`, 고정71문서·298청크·개발48문항과 동일 Tiny revision. 신규 확인40은 사용하지 않았다.
- 기존 검색 순위·응답·AI 관련도 판정 원자료를 재분석했다. 소규모 실제 Tiny CPU 재계산은 로컬에서만 수행했다. 유료 LLM 호출0회·운영 접속0회·재학습0회.
- 모델을 바꾸거나 임계값을 다시 튜닝하지 않았다. 질문 재표현과 정답 중심 청크 단축은 결과를 본 뒤 만든 **사후 원인 진단**이며 정답 지식을 활용한다. 일반 성능 개선 실험/배포 후보로 취급하지 않는다.
- 원문 전용 독립 AI 검토자는 최초에 질문·qrel·회사 원문만 읽고 점수·설정·결과를 보지 않았다. 사람 검수 아님.

## 1. 저장·계산·입력 계약

`TinyEmbedder`는 query/passage 접두사, attention-mask mean pooling, L2 정규화 후384차원 벡터를 만든다. 현재 검색은 정규화된 문서 행렬과 질문 벡터를 내적한다. 캐시 일치 검증은 같은 구현으로 재계산한 재현성 확인이며 모든 구현 오류를 독립적으로 배제하는 검사는 아니다.

| 확인 | 결과 |
|---|---:|
| 문제4문항 질문 벡터 재계산 최대 절대 차이 | 9.31e-8 |
| 관련5개 문서 청크 벡터 재계산 최대 절대 차이 | 8.20e-8 |
| 전체298청크 실제 임베딩 입력 토큰 | 최소22·최대374 |
| 512토큰 초과 | 0 |
| unknown 토큰 / 전체 토큰 | 9 / 55,316 |
| 원본 문서DB·벡터DB SHA 전후 변화 | 없음 |

모든 DB 조회는 임시 복사본에서 수행했다. 해당 결과는 캐시 불일치·광범위한 토크나이저 실패·입력 절단을 이번 문제의 주요 원인으로 볼 근거가 없음을 뜻한다. 전용 벡터DB 전환은 이 순위 문제의 직접 해결책이 아니다.

## 2. 평가 기준에서 놓친 동등 근거

독립 AI 원문 검토에서 다음 대체 근거가 발견됐다. 사실 간 AND, 대체근거 간 OR를 유지했다. R14의 대체 설명은 두 구간을 모두 포함해야 인정한다.

| 문항 | 원래 인정 구간 | 누락된 대체 구간 | 전체 필수 사실 확보 순위 변화 |
|---|---|---|---:|
| R08 개인 결제 경비의 지급일 | ieum-019[577:611] | ieum-060[1387:1444], 같은 최종 검토 기준·다음 달15일 | 15 → 5 |
| R14 자기 PR 승인 | ieum-067[821:853] | 같은 문서[1651:1692] 독립 승인1건 AND [1724:1758] 자기 승인 불인정 | 25 → 11 |
| R16 삭제만으로 해결 안 됨 | ieum-071[2194:2275] | ieum-037[1126:1178] 삭제/재작성만으로 안전하지 않음 | 전체는39 유지 |
| D07 구매 승인≠계정 권한 자동발급 | ieum-021[605:647] | 동등한 직접 구간 확인 못함 | 6 유지 |

R16-r02의 ‘권한 있는 담당자 즉시 폐기·회전’은 변경하지 않았다. 다른 문서는 즉시 **신고**와 담당자의 폐기·교체를 설명하지만 폐기의 즉시성을 명시하지 않아 같은 근거로 추가하지 않았다. R16-r01은 캐시·로그 등 위치를 전부 열거해야만 답이 되는 것은 아니라는 판정 경계도 남겼다.

| 구성 | 원 qrel v2 | 대체 근거 추가 민감도 |
|---|---:|---:|
| 기존 서버 후보10·최대5 | 34/38 | 35/38 |
| A: 0.35·문자 제한·4k | 36/38 | 37/38 |
| B: 0.35·4k만 | 36/38 | 37/38 |
| C: 0.35·문맥 제한 없음 | 37/38 | 37/38 |

**C의 A/B 대비 유일한 성공 차이가 사라진다.** 다만 이는 공식 원점수를 사후 수정한 것이 아니라 평가기준 민감도 분석이다. 원문의 동등 근거가 빠졌던 점은 검증된 결함이며, 새 평가 기준을 확정하려면 전체 문항의 대체근거를 일관되게 검토해야 한다. 지정 span과 의미상 충분한 근거의 차이 때문에 ‘검색 실패’로 보인 일부가 실제 실패보다 과장됐다.

## 3. 구어체·업무 표현에 따른 순위 민감도

같은 문서 벡터에서 문제4질문을 수동으로 한 번씩 다시 표현했다. 답인 날짜·승인 수·즉시 폐기 명령을 질문에 삽입하지 않았지만 원인을 본 뒤 작성했으므로 답을 모르는 일반 질의 개선과 같지 않다.

| 문항 | 사후 재표현 | 기존 지정 필수 근거 순위 | 해당 점수 변화 |
|---|---|---:|---:|
| R08 | 개인이 먼저 낸 업무 경비는 언제 정산 지급되나요? | 15 → 3 | .371 → .570 |
| R14 | PR 작성자 본인이 자신의 변경을 승인할 수 있나요? | 25 → 5 | .373 → .500 |
| R16 | Git 저장소에 비밀 토큰이 노출됐을 때 파일 삭제 외에 어떤 대응이 필요한가요? | 폐기·회전39 → 4 | .328 → .524 |
| D07 | SaaS 구매 승인과 서비스 계정 권한 발급은 별도 절차인가요? | 6 → 1 | .406 → .533 |

실제 원질문 R08은 교육비·식비 등 ‘돈을 쓴다’는 주제의 청크를 앞에 놓았고, R14는 승인이라는 표현을 공유하는 외부공개·출장 문서가 앞섰다. D07은 계정·권한 주제의 문서가 핵심 부정 조건보다 앞섰다. 이는 Tiny 단일 벡터 검색이 구어체 의도를 정책의 용어·조건으로 매핑하는 데 민감하다는 관측이다. 모델 크기만이 원인이라는 증거는 아니며 다른 모델 비교는 이번에 하지 않았다.

## 4. 분할은 ‘문장이 잘렸나’만으로 판단하면 안 됨

문제 청크에 필수 문장과 제목이 모두 온전히 있어 **물리적 잘림**은 없었다. 하지만 큰 청크의 다른 문장들이 세부 사실을 희석하거나, 같은 절의 조치가 다른 청크에 있어 **문맥 관계**가 약해질 가능성은 있다.

정답 구간을 알고 해당 문장 중심으로 임베딩 입력을 줄인 오라클 진단:

| 사실 | 원청크 | 제목+필수 사실만 | 해석 |
|---|---:|---:|---|
| R08 지급일 | .371 | .318 | 짧게 만드는 것만으로 개선 안 됨 |
| R14 독립 승인 | .373 | .449 | 관련 없는 다른 내용의 영향 가능성 |
| D07 자동 권한 발급 아님 | .406 | .578 | 세부 사실 중심 표현이 유리한 사례 |
| R16 즉시 폐기·회전 | .328 | .222 | 조치 문장 단독은 Git/토큰 맥락이 더 약해짐 |

따라서 ‘청크를 전부 더 작게 만들자’도 결론이 아니다. R16은 ‘파일 삭제만으로 불충분’ 청크가2위이고 같은 절의 대응 절차 청크는39위다. 이 사례는 **같은 절의 인접 근거 연결** 또는 **질의 의도 보완**을 검증할 이유가 된다. 과거 인접 확장 실험이 채택되지 않았다는 이력을 보존해야 하며 이번4사례로 전체 채택하지 않는다. reranker도 후보에 들어온 문서만 재정렬하므로 R16을 검증하려면 원질문 기준 적어도39위가 포함된 후보풀이 필요하다.

## 5. C의 선별력에 대해 실제로 말할 수 있는 범위

0.35에서 선택되는 청크는 질문당 평균69.625개, 최대170개다. 평균은 전체298개의 약23.4%다. 답변 가능한38문항 평균73.66개, 답변불가10문항도 평균54.3개가 선택된다. 답변불가 질문에도 안내 절차는 관련 있을 수 있으므로 선택된 것 자체가 오류는 아니다.

전체48질문의 선택된 질문–청크 쌍3342개 중, 기존 AI 관련도 판정이 있는 것은1591개이고1751개는 미판정이다. 따라서 **C 전체 precision은 미확정**이다. 검수된 일부만으로 계산하면 선택 편향이 생긴다. 기존 판정은 질문/qrel에 조건부인 AI 판정이므로 대체근거 누락으로 등급이 잘못 매겨진 구간도 다시 확인해야 한다.

전체 후보가 검수된 사례에서는 R08의26개 중 직접 근거(등급2+)2개, D07의38개 중4개, R16의21개 중5개다. 이 수치는 기존 AI 기준의 사례 진단일 뿐 C 전체의 정확도가 아니다. 원문 재검토에서 R08의 대체 근거를 찾았으므로 관련도 등급도 확정 참값처럼 취급할 수 없다.

답변가능 질문의 최고점 .456~.831, 답변불가 .324~.641이 겹친다. .35는 관련 확률35%나 답변 가능성의 경계가 아니다. 점수0.70 실험에서는 답이 있는38문항 중36개가 빈 결과였다. 모델 카드의 일반적인 .7~1 분포를 이 데이터에 그대로 적용할 수 없다.

## 6. 권장 순서와 게시 판단

1. **평가기준부터 정정:** v2 원본 보존, 동등 원문을 OR로 추가한 다음 버전과 변경사유를 별도 작성하고 전체 문항을 검토한다. 검색 근거 완전 포함과 답변 품질을 분리한다.
2. **C 관련도 검수 범위 보완:** 미판정1751쌍의 전수 검수 또는 사전 고정 표본 조사로 목적을 나눈다. 표본 결과를 전체 exact precision이라 부르지 않는다.
3. **순위 개선 비교:** 원질문·새 동결 질문으로 기존 C와 적절한 후보풀+reranker, 같은 절 인접 확장, 질의 재표현을 하나씩 비교한다. 이번 수동4질문을 최종 평가 세트로 쓰지 않는다. 모델 비용·CPU 지연도 기록한다.
4. **그 다음 설정 결정:** 근거 충분성을 유지하며 무관한 문맥을 줄이는 구성을 찾는다. 무제한 C를 그대로 유지하는 사용자 결정은 가능하지만 ‘실험으로 검색 최적성이 입증됐다’고 기록하지 않는다.

이번 진단에서 서버 기능·기본 모드·프롬프트·원 qrel·과거 보고서·Notion·Git 게시를 변경하지 않았다. 기존의 C 적용·일지·main 게시 요청은 취소된 것이 아니며, 이번에 발견된 평가 한계와 정정을 반영해 진행해야 한다. 사람 검수·실제 운영2vCPU 검증은 미완료다.

## 독립 재검토와 민감도 재확인

독립 AI가 AND/OR 구현과 산출물 정합성을 읽기 전용으로 검토했다. C의1문항 우위 소멸은 이번 **필수 사실 완전 포함 지표**에만 한정하는 것이 타당하다고 확인했다. R08 대체 구간에는 휴일 설명, R14 대체 구간에는 자동검사 설명이 섞여 더 엄격한 문자 조건이 될 수 있다고 지적했다. 최초 진단을 보존하고 해당 부가 문구를 뺀 `qrels-minimal-sensitivity.json`으로 다시 계산해도 A/B/C는 모두37/38이었다(`minimal-sensitivity-results.json`).

R14의 대체구간을 포함한11위 청크는 전체 저장 순위에서 계산됐다. 독립 검토자의 첫 `focus.json` 확인 범위는 top10이었으므로11위 원문 직접 대조까지 수행했다고 주장하지 않는다. 부모는 전체 순위에 근거한 span 포함 계산을 수행했다.

스크립트는 출력 경로가 파일 상단에 고정돼 있으므로 재실행하려면 복사본에서 새 출력 경로를 지정해야 한다. 기존 진단 원자료를 덮어쓰지 않는다. 이번 검증은 재계산 일치·원문/offset·판정 AND/OR·DB보존 검증이며 전체 서비스 회귀 테스트 수행을 뜻하지 않는다.
