# RAG 평가 기준 보완과 검색 최적화 비교

> 후속 결정(2026-10-16): 사용자가 근거 유지·전달량 감소를 우선해 [KURE 채택·서버 연결](../2026-10-16-kure-adoption/README.md)을 결정했다. 아래 결과와 당시 판단은 과거 기록으로 보존한다.

**활성 검색 구성은 C를 유지한다.** 인접 확장 상위12개는 개발 세트에서 필수 근거를 더 적은 문맥으로 확보했지만, 신규 확인에서 C가 성공한 한 문항을 놓쳤다. 사전에 정한 손실 금지 조건에 따라 채택을 보류했다. BGE 재정렬은 CPU 지연 기준에 미달했다. C의 최적성이 증명됐다는 뜻은 아니다.

이번 작업은 로컬 검색 평가다. 유료 API·답변 생성 평가·운영 접속·배포는 하지 않았다. AI 작성·독립 검토 자료이며 사람 검수나 실서비스 품질 승인이 아니다.

## 평가 기준 정정

개발48문항의 qrel v3와 신규40문항을 개발 검색 실행 전에 원문 기준으로 독립 검토·수정·동결했다. 사실 간 AND, 대체 근거 간 OR, 대체 근거 안 필요한 구간 간 AND를 적용한다. R08·R14의 동등 근거, R16의 삭제 불충분과 즉시 회전의 경계 등을 구분했다.

기존 v2·원점수·응답은 보존했다. 과거 전달 원문을 v3로 재집계하면 **A/B/C 모두 37/38**이다. 이전 36/38·36/38·37/38에서 달라진 것은 A/B의 R14다. 따라서 “문맥 무제한만이 해당 근거를 확보했다”는 이전 해석은 평가 기준에 민감했다. 실제 답변12문항의 결과·비용은 이 검색 기준 정정으로 변경하지 않는다.

## 조건과 개발 비교

같은 71문서 snapshot·298청크·360/60 분할과 Tiny revision을 유지했다. 질문은 원문 그대로 사용했다. 모델·문서·색인 식별값은 [실행 manifest](raw/development-manifest.json.gz)에 있으며 [재현 안내](reproduction.md)를 따른다.

인접 확장은 벡터 상위5/8/12의 같은 문서·개정·상위 절에서 바로 앞뒤 청크를 최대1개 추가한다. BGE는 Tiny 상위40을 CPU FP32로 재정렬한다. 두 계열은 최고 코사인 점수가0.35 미만일 때만 빈 결과로 처리하며 개별 후보에는 하한을 적용하지 않는다. 추가 문자·4k 제한 없이 겹친 원문을 병합한다. 코사인과 재정렬 점수는 따로 기록하며 어느 쪽도 관련 확률로 해석하지 않는다.

필수 근거 지표는 답변 가능38문항, 직접 관련도·전달량은 불가10개를 포함한48문항 기준이다. 직접 관련도는 질문별 고유 청크 중 독립 AI 등급2이상의 비율을 평균한 값이며 답변 정확도가 아니다. 미판정0으로 공통 문항을 비교했다. 순위별 precision·nDCG, 중복 원문 길이와 문항별 결과는 [집계 JSON](development-summary.json)과 [CSV](development-comparison.csv)에 있다. 낮은 등급까지 두 검토자가 전수 합의한 자료는 아니다.

C의 성공 문항을 유지하며 완전 포함 수가 가장 높은 인접 확장 top12를 개발 후보로 고정했다. C보다 평균 본문이82.3% 작았다. 이전 누락 R14·D07은 후보에서 포함됐고, C가 놓친 R16의 즉시 회전 근거도 포함됐다. 관련도보다 완전 포함을 먼저 비교한다는 사전 규칙을 따랐다. [후보 동결](candidate-freeze.json).

## CPU 측정과 신규 확인

개발 PC CPU2 제한에서 C·인접 확장은 동시1·2 각각240요청을 완료했다. 인접 확장의 warm p95는37.27/70.33ms, 최대 RSS1,009.41MiB로 기준을 통과했다. BGE의 고정48요청 p95 하한은 최소22.51/35.36초로3초 기준을 초과했다. 동일한 필수40쌍 재정렬 단계 때문에 최종5·8·12를 모두 제외했다. 부분 실행을 전체 완료 p95로 표현하지 않는다. [측정 방식·전체 원자료](performance-method.md).

후보를 고정한 뒤 신규40문항에서 C와 한 번 비교했다. 구성은 답변 가능30·부분 가능5·불가5다. 일부 부분답변 문항은 같은 세트의 정책을 재사용하므로40개 독립 정책이라고 해석하지 않는다.

- **C: 필수 근거35/35, 후보:34/35.** 부분답변 가능 문항은 자료가 지원하는 부분만 평가하며 알 수 없는 사실을 정답에 넣지 않았다.
- V14는 “잠금파일 패키지 설치의 일반 절차와 관리자 권한·외부 전송 도구의 별도 검토”를 함께 물었다. 후보는 일반 의존성 근거를 찾았지만 별도 검토 절을 놓쳤다.
- 누락 청크 `0e35480c…`는 코사인0.47475, 순위15였다. top12 밖이고 다른 상위 절이어서 인접 확장에서도 들어오지 않았다. C는 포함했다. 문자·토큰 예산 잘림이나0.35 미달이 원인이 아니다. [문항별 진단](confirmation-regression.json).
- 이 결과를 본 뒤 topK·절 경계·질문을 바꾸어 확인 세트를 재실행하지 않았다. 신규 관련도는 C 3.88%, 후보 20.62%이며 공통40문항·미판정0이다. [집계](confirmation-summary.json)·[비교표](confirmation-comparison.csv)·[최종 결정](final-decision.json)을 보존한다.

## 결정과 코드 적용

신규 확인에서 C 성공 문항을 잃었으므로 후보를 채택하지 않는다. 개발 완전 포함·문맥 축소와 신규 확인 실패를 모두 보존한다. BGE는 지연으로 제외하며 모델 교체나 자동 질문 재작성으로 우회하지 않았다.

**서버 활성 경로는 기존 C 하나, 기본 모드는 rag, 명시적 full 복구는 유지한다.** 이는 이번 비교에서 새로 기본값을 바꾼 것이 아니라, 선행 PR #11에서 게시된 설정을 검증하고 유지한 것이다. 탈락한 인접 확장·BGE는 실험 영역에만 있으며 서버가 import하지 않는다. 벡터 입력·분할·schema가 같아 색인·자정 기본 벡터를 다시 생성하지 않았다. 기존 생성 모델·프롬프트·shadow/gate·공개 API도 유지했다.

0.35라는 숫자 하나만으로 모델이 쓸모없다고 판단할 수는 없다. 이번에는 **관련도 판정 기준의 누락, 낮은 정밀도와 과도한 전달량, 필수 근거의 순위/절 경계 문제**가 각각 확인됐다. C는 필수 근거 보존에 유리하지만 불필요한 문맥이 많다. 후속 개선은 별도 미사용 질문과 사람 검수로 복수 절의 필요한 조건을 함께 확보하는지를 확인해야 한다. 이번 확인 자료로 반복 튜닝하지 않는다.

## 검증·자료·한계

기존 서버 C와 실험 C는 실제 Tiny 질문 추론48건에서 반환 원문·구간·청크 ID가 모두 일치했다. 임시 문서·색인과 실제 Tiny, 모의 생성기로 `/ask` HTTP200·snapshot1회·생성 예약1회를 확인했다. 유료 생성 호출은0이다. [독립 코드 검토](code-review.md)와 최종 검증 기록은 실제 수행과 미검증을 구분한다.

[게시 범위](publication-inventory.md), [압축 원자료](raw/), [로컬 재현](reproduction.md)을 참고한다. 모델·DB·벡터·가상환경·비밀값은 Git에 포함하지 않는다. 사람 검수·실제 LLM 답변 품질·운영2vCPU·운영 활성화는 미완료다.

설계 참고: [Sentence Transformers Retrieve & Re-Rank](https://www.sbert.net/examples/sentence_transformer/applications/retrieve_rerank/README.html), [BAAI/bge-reranker-v2-m3](https://huggingface.co/BAAI/bge-reranker-v2-m3). 다국어 지원과 이 프로젝트의 CPU 적합성은 별개로 실측했다.
