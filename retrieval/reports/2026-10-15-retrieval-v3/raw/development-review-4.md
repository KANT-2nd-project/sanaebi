## 검토 범위와 모호성

- D19는 “전달” 자체와 “인수 수락”을 구분했다. 명시적 수락 전 기존 담당자가 문의를 맡는 문단은 3, 장애·일반 문의 절차에서 연속 책임을 보강하는 문단은 2 이하로 봤다.
- D20은 공개 웹 게시와 지정 외부 수신자 공유를 구분했다. 지정 수신자·최소 권한·7일 회수 규칙을 직접 설명하는 문단은 3, 외부 공유 전반의 승인·권한 원칙은 2로 봤다.
- U01/U05의 출장 식사비·업무상 식사 문단은 메뉴 그 자체는 아니지만 식사 관련 일반 절차라 1로 두었다. 오늘/이번 주 실제 식단은 제시되지 않는다.
- U02는 교육지원 문단의 “성과등급·급여 인상·포상을 약속하지 않는다”는 제한만 보상 질문의 직접적인 주의로 2를 부여했다. 올해 지급률은 자료에 없다.
- U03은 개인 번호를 답하는 내용이 없어 점수를 높이지 않았다. 지정된 회사 연락·비상 연락카드를 직접 대안으로 안내하는 문단은 2, 대표가 신고 당사자인 조건부 독립 신고 경로는 1로 봤다.
- U04/U06은 개인 잔액 확인과 실제 신청 승인 상태를 구분했다. People팀 확인이나 포털 상태 확인을 직접 안내하는 경우 2, 일반 휴가 절차는 1로 두었다. 개인의 실제 기록은 자료에 없다.
- U07은 고객별 현재 영향 목록을 답하는 문단이 없다. 영향 범위 확인·기록·심각도 판단을 직접 돕는 절차는 2, 장애 대응 일반 안내는 1로 두었다.
- U08의 1인 연간 한도·사용액 차감은 팀 잔액과 다른 수치라 2의 부분 근거로만 처리했다. 현재 팀 예산·사용액은 없다.
- U09의 시스템 권한 신청·최소 권한·접근 오류 절차는 요청에 직접 도움이 되어 2, 일반 GitHub 용도·절차는 1로 두었다. 실제 계정의 권한 목록은 제공되지 않는다.
- U10은 국내 출장의 기본 승인 역할·포털 상태 확인 절차는 2로 평가했지만, 이번 출장 요청에 실제 기록된 승인자 이름은 포함되지 않았다.
