# 관련도 판정과 재검수 범위

모든 비교 구성이 선택한 청크와 순위 지표의 상위40 청크 합집합을 질문별로 만들었다. 설정 이름·검색 점수·순위·승패를 제거한 입력에서 독립 AI가 질문과 실제 본문을 대조했다. qrel 위치 일치나 키워드로 관련도 점수를 자동 생성하지 않았다. 동일 청크라도 질문이 다르면 별도 판단이다.

0은 무관, 1은 주제·일반 절차만 관련, 2는 직접 부분 근거·주의 조건, 3은 핵심 답을 직접 지원하는 근거다. 직접 precision은 고유 선택 청크 중 2 이상 비율이며 답변 정확도가 아니다. 문항별 비율을 평균하므로 많은 근거를 보내는 질문이 더 큰 가중치를 갖지 않는다. 완전 판정된 빈 결과는 선정용 macro에서 0, raw precision은 null이다. 필수 사실 AND/OR 포함 지표와 의미 관련도를 별도로 계산한다.

## 개발 48문항

3,684개의 질문·청크 조합을 판정했다. 최초 작업 중 잘못된 ID 연결과 다른 조건의 절차를 직접 근거로 과대평가한 사례를 발견했다. 초안은 보존하고 명시적인 `(case_id, chunk_id)`로 다시 검토했다. D14–D18은 기존 판정을 보지 않은 별도 AI가 548개를 다시 작성했다. 이 과정은 평가 자료의 품질 문제이며 검색 모델의 오류와 합치지 않는다.

추가 읽기 전용 검토는 수정본의 높은 등급 전체와 낮은 등급 표본을 대조했다.

| 대상 | 추가 검토 범위 | 반영한 추가 수정 |
|---|---|---:|
| R01–R12 | 높은 등급60 + 낮은 표본24 | 12 |
| R13–R18·D01–D06 | 높은 등급53 + 수정32 및 낮은 표본 | 8 |
| D07–D13 | 높은 등급74 + 낮은 표본42 | 21 |
| D14–D18 | 높은 등급37 + 낮은 표본30 | 12 |
| D19–D20·U01–U10 | 높은 등급55 + 낮은 표본, 별도 경계 확인 | 9 |

수정은 일반 문의처·다른 휴가/경비 유형을 직접 답으로 전이하지 않도록 낮추고, 제목과 달리 본문이 일반 지급 절차를 설명하는 동등 근거는 올리는 방식이었다. 예를 들어 경비 지급일 본문은 R08·R18·D02의 직접 근거지만 해외 재택 질문 D01의 답은 아니다. 판단 이유에 본문에 없는 문구가 있으면 이유도 좁혔다.

최종 개발 집계의 미판정은 0이다. 모든 원문을 최초 AI가 읽었다는 기록과 추가 검토자의 표본 범위는 구분한다. 낮은 등급까지 두 검토자가 전수 합의한 자료나 사람 검수 정답은 아니다. [원본·수정본과 추가 수정 목록](raw/)에서 `development-judgments*`, `development-qa-corrections*`, `development-review*`를 확인할 수 있다. 압축 JSON은 `gzip -dc 파일명.json.gz`로 읽는다.

## 신규 확인

신규 40문항은 개발 실행 전에 원문 기준으로 검토·동결했고, 개발 후보를 확정한 뒤 C와 한 번만 검색했다. 관련도 판정은 개발 때와 같은 기준으로 설정·점수·순위를 가리고 수행한다. 실제 완료 수와 추가 검토 범위는 최종 확인 결과에 기록한다. 이미 실행한 확인 세트는 다시 튜닝용 미열람 자료로 표현하지 않는다.

최종 신규 판정은5,034쌍이며 미판정0이다. 네 묶음 모두 원문을 읽는 최초 AI 판정 후 높은 등급 전체·낮은 등급 표본의 독립 QA를 거쳤다. V01–10은74+20쌍, V31–40은31+20쌍을 추가 확인했다. 최종 수정은 묶음별31(이유만1 포함)·14·21·6건이며 초안과 수정 목록을 raw에 보존했다. 일반 권한·공유·문의 절차를 특정 조건의 직접 근거로 과대평가하지 않도록 정정했다. 낮은 등급 전수 이중 검토나 사람 검수는 아니다. 최종 파일은 `raw/confirmation-confirmation-judgments.json.gz`다.
