# RAG C 검색 설정 채택

사용자는 **필수 근거 누락 최소화**를 우선해 C를 선택했다. 코드 기본값을 `rag`로 바꾸고 서버 검색을 점수0.35 이상·개수/문자/별도 전달 문맥 토큰 제한 없음으로 고정한다. `full`은 명시적인 수동 복구 경로다. 이번 작업은 운영 접속·배포를 포함하지 않는다.

## 실험 결과와 선택 근거

| 평가 | A: 문자+4k | B: 4k만 | C: 무제한 문맥 |
|---|---:|---:|---:|
| 검색 필수 구간 완전 포함(근거 있는38문항) | 36/38 | 36/38 | 37/38 |
| 실제 답변 필수 사실 충족(고정12문항·1회) | 11/12 | 11/12 | 11/12 |

검색은 개발48문항 중 답변 불가10문항을 제외한 분모이며, 실제 답변 비교는 별도 고정12문항이다. 답변 충족에는 구성별 빈근거 고정 안내1건이 포함된다. AI 작성·독립 AI 검토 자료이며 사람 검수·일반 성능·운영 품질 승인이 아니다.

C의 평균 전달 문맥은 A/B의 약4.22배이고, 실제 답변 비교에서 C 비용은 B의 약2.38배다. 추가 근거 확보가 이번 소규모 답변 개선으로 이어지지는 않았다. 이전 보고서의 B 권고·C 보류는 답변 품질·비용까지 고려한 당시 판단이며 보존한다. **그 뒤 사용자가 검색의 근거 누락 감소를 우선해 C 채택을 결정했다.** 실험 결과 수치나 당시 판정을 소급 변경하지 않는다.

## 검색 계약과 범위

현재 게시 개정의 전체 벡터 점수에서0.35 이상을 선택한다. 같은 문서·개정의 겹친 원문을 병합하고 본문·원문 위치·청크 ID·점수를 함께 전달한다. 점수 동률 순서는 청크 ID로 고정한다. 문서 전체를 무조건 전달하는 설정은 아니다. 점수가 낮아 빠진 근거는 문맥 제한을 없애도 복구되지 않는다.

후보10·근거5·총8,000자·근거당2,000자·4k 전달 제한을 활성 경로에서 제거한다. BM25·인접 확장 및 과거 설정 선택 코드는 실험 전용으로 격리하며 서버는 import하지 않는다. 과거 실험 재현 코드는 유지한다.

Tiny 고정 revision, 본문360/중첩60, 임베딩 입력512, vector spec과 SQLite schema는 유지한다. 검색 설정 식별값만 변경하며 기존 색인·자정 기본 벡터를 재사용한다. 생성 제공자의 실제 입력 한계는 존재한다. 한계 초과 시 자동 축약·full 전환 없이 기존 생성 오류 계약을 따른다.

## 적용·검증 상태

코드 변경·로컬 검증·Git 게시·외부 기록은 [작업 기록](../../../docs/worklogs/2026-10-15-rag-c-adoption.md)에서 구분한다. 과거 운영 기록의 shadow+full은 당시 확인값이며 이번 작업에서 운영 설정을 재조회하거나 바꾸지 않는다. 실제2vCPU 성능·사람 검수·운영 RAG 활성화는 후속이다.

[실제 Tiny48문항 동등성](runtime-equivalence.json)을 확인했으며 전체Python882개·Ruff·독립 코드 검토를 통과했다. [검증 실행기](verify_runtime.py)는 고정 원자료·모델 경로를 인자로 받아 임시 DB에서 비교하며 유료 LLM을 호출하지 않는다.

## 후속 검색 기준 재검토 (2026-10-16)

[평가 기준 보완·검색 최적화](../2026-10-15-retrieval-v3/README.md)는 당시 사용자 채택과 코드 반영 기록을 보존하면서, 누락된 동등 근거를 수정해 별도 재집계한다. v3 기준 과거 A/B/C의 필수 근거 완전 포함은 모두 37/38이다. C 채택 기록 자체가 검색 최적성이나 실제 답변 품질 우위를 입증한 것은 아니다. 후속 최종 구성·검증·운영 미적용 여부는 연결된 보고서에서 관리한다.
