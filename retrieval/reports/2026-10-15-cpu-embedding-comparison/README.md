# 한국어 CPU 임베딩 16종 비교와 KoEn-E5-Tiny 채택

## 목적과 결정

2vCPU·16GB RAM에서 KoELECTRA 분류기와 함께 사용할 한국어 문서 검색 임베딩을 검토했다. 답변 LLM은 외부 API를 사용할 예정이며, 이번 실험은 문서 검색까지다. **2026-10-15 사용자 결정으로 `exp-models/dragonkue-KoEn-E5-Tiny`를 채택했다.** 모델 선정과 서버 RAG 연결은 별개다. 이번 기록 작업은 서버 설정·문서 DB·벡터 저장소를 변경하지 않았다.

상세 계약과 이유는 [선정 기록](selection.md), 실행 과정은 [작업 일지](../../../docs/worklogs/2026-10-15-embedding-selection.md), 결정 전 관측은 [당시 해석](observations.md)에 있다.

## 실험 과정

1. E5-small-ko-v2로 CPU 로딩·원문 길이·분할·검색을 확인했다. 원문 71개 중 57개가 제목·접두사 포함 512토큰을 넘어 분할이 필요했다.
2. 동일 질문·원문 범위로 BGE-M3와 KURE-v1을 비교했다. 사용자가 말한 KLUE는 KURE-v1을 뜻하는 것으로 확인했다. raw KLUE BERT를 검색 임베딩으로 평가한 결과가 아니다.
3. 경량·다국어·한국어 특화 후보 14개를 추가 검토했다. 공개 접근 가능한 13개를 실행했고 EmbeddingGemma는 접근 제한으로 제외했다. 기존 3종과 합쳐 16종이다. 대형 7B·영어 전용 모델까지 망라하지 않는다.
4. 저장 벡터에서 순위·지표를 재계산하고 원문 SHA·질문·원문 span·정규화를 확인했다. 정확 문자열 지표의 동등 근거 누락을 별도로 기록했다.
5. 사용자에게 속도·검색의 균형 후보를 보고했고 사용자가 KoEn-E5-Tiny를 선택했다. AI가 실행·검증·기록을 수행했으며 사람의 독립 구현·평가를 수행했다고 기록하지 않는다.

## 실행 조건

- 원문: [회사 지식 JSONL](../../../data/company-knowledge/documents.jsonl) 71건. SHA256 `84b44e6592e3a6bd883b7890239aada11382cbef9a369ebb0aca3b15defddfe4`.
- [질문](cases.json): AI가 원문을 읽고 추론 전에 고정한 답 가능한 18개와 답 없는 4개. 사람이 검수한 독립 평가 세트가 아니다.
- [청크](chunks.json): E5 토큰 기준 본문 360토큰, 60토큰 중첩의 186개 원문 범위를 모든 후보에 동일하게 사용. 제목을 붙이며 모델별 역할 접두사·pooling·최대 길이는 각 계약을 따른다. 문단·표 경계 최적화 실험은 아니다.
- Intel Core Ultra 9 275HX / WSL2, CPU affinity 0·1, PyTorch intra-op 2 / inter-op 1, FP32·dense 검색. GPU 추론·양자화·ONNX/OpenVINO·reranker·BGE sparse/ColBERT는 사용하지 않았다.
- PyTorch 2.14.1+cu130, Transformers 5.19.0. Potion은 별도 Model2Vec 환경이며 [lockfile](reproduction/embedding-broad-pilot-2026-10-15/static-env/uv.lock)을 보존한다. 루트 의존성은 변경하지 않았다.
- 문서 batch=8, 질문 batch=1. 워밍업 후 22개 질문을 4회 반복한 88개 시간의 p50/p95. 토큰화·임베딩만 포함하며 HTTP·분류기·LLM 전체 응답 시간이 아니다.
- 정규화 벡터의 내적·정렬로 정확 검색했다. Hit@k는 중복 문서를 포함하는 청크 k개 안의 지정 문서·문자열 적중이며, 정답 문서를 모두 라벨링한 Recall이나 답변 정확도가 아니다.
- 실행별 모델 revision·코드 HEAD·환경·입력 계약은 [출처 연결](provenance.json)과 `evidence/`의 JSON에 있다. 실행 당시 다른 작업의 변경이 있었으므로 HEAD만으로 전체 환경을 동일하게 재현한다고 주장하지 않는다.

## 실패 사례와 해석 한계

- Tiny: 지정 근거 @5 17/18, 문서 @5 18/18. PR 자기 승인 질문은 지정 문구가 29위지만 2위에 명시적인 자기 승인 금지 문장이 있다. [동등 근거 확인](pr-evidence-audit.json). 원래 지표를 수정하거나 이를 실서비스 100%로 표현하지 않는다.
- 기존 E5는 비용 지급일과 익명화한 고객자료의 AI 입력 제한 근거가 각각 6위였다. 큰 모델로 바꾸어 개선된 사례와 토큰 폐기·회전 근거가 밀리는 회귀가 함께 있었다.
- 모호한 휴가 질문은 연차로 지정했지만 다른 휴가 해석도 가능하다. 지정 문자열과 동등한 근거를 모두 라벨링한 자료가 아니다.
- 답 없는 질문에도 최근접 문서는 나온다. 개인 잔여 연차 등은 회사 정책 문서만으로 답할 수 없으며 모델별 유사도 점수를 공통 거절 임계값으로 쓰지 않는다.
- MiniLM은 공식 기본 128토큰으로 177/186개 입력이 잘렸다. 모델에 맞춰 짧은 청크로 재평가하지 않았다. Potion은 매우 빨랐지만 지정 근거 @5 13/18이었다.
- 개발 PC CPU 2개 제한은 실제 배포 2vCPU와 동등하지 않다. 다른 프로세스·다운로드·캐시 경합을 완전히 통제하지 않았다. 최대 RSS는 로딩·색인을 포함한 프로세스 최대값이며 모델 자체 상주 메모리가 아니다.
- EmbeddingGemma-300M은 공개 접근에서 GatedRepoError로 미실행이다. 약관 동의·인증 변경·우회 저장본 사용을 하지 않았다.

## 원자료와 재현 접근

Git에는 결과 JSON·질문·공통 청크·모델별 상위 검색 ID/점수·순위·비교표·모델 공개 설정·당시 스크립트를 보존한다. 예측 JSON의 `hits[].body`만 중복을 줄이려고 제외했으며 `chunk_index`로 공통 청크의 본문을 찾을 수 있다. [출처 파일](provenance.json)에 변환과 원본 경로를 명시했다.

벡터 배열·전체 콘솔 로그·모델 캐시·가상환경은 원래 로컬 `tmp/e5-small-ko-v2-pilot-2026-10-15/`, `tmp/embedding-comparison-2026-10-15/`, `tmp/embedding-broad-pilot-2026-10-15/`에 그대로 있다. 공개 다운로드 링크가 아니며 Git clone만으로 제공되지 않는다. [스크립트 보존본 안내](reproduction/README.md)를 따른다. 이번 게시 시 모델 재추론·재학습·LLM 요청은 하지 않았다.
