## 채택 근거

16종 비교에서 지정 근거 @5 17/18, 문서 @5 18/18을 기록하면서 질문 임베딩 p50/p95 10.31/13.24ms, 전체 186개 청크 색인 19.33초였다. 관측 최대 프로세스 RSS는 1141.9MiB다. 이는 2vCPU 환경에서 분류기와 자원을 공유할 후보로 선택한 근거이며 배포에서 측정한 메모리·처리량 보증은 아니다.

Snowflake는 지정 근거 @5 18/18로 더 높았으나 이번 질문 임베딩이 118.64ms였다. Bekko-a8m은 3.91ms로 빠르지만 @5 16/18이었다. Tiny를 절대 최고로 선언하지 않고, 사용자가 검색과 CPU 비용의 균형을 보고 채택한 결정이다. PR 질문의 동등 근거와 작은 AI 작성 평가의 한계를 그대로 남긴다.

## 후속 구현과 검증

선정 계약은 구현 시 기준이며 현재 서버 설정에 자동 적용되지 않는다. 벡터 DB 제품·top-k·청크 정책·답변 거절 임계값은 이번에 확정하지 않았다. 실험의 360/60 토큰 창을 운영용 문단·표 분할로 채택했다고 기록하지 않는다.

후속으로 게시된 개정만 색인·검색하고 초안·사용 중단·미래 시행본을 제외하는 정책, 문서 수정·게시·삭제·시연 reset 시 색인 동기화, 원문·개정·출처 연결을 구현·검증한다. 별도 사람 검수 질문, 실제 배포 CPU에서 분류기와의 동시 부하, 검색 근거 기반 LLM 답변·근거 부족 처리도 확인해야 한다. 모델 다운로드·라이선스 확인과 배포 준비는 연결 작업에서 명시한다.
