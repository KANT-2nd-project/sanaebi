# KURE-v1과 Tiny: 현재 분할·qrel v3 소규모 비교

서버 설정을 바꾸지 않고 기존 개발48문항(답변가능38·불가10)으로 비교했다. 신규 확인40·유료 API·답변 생성·운영 연결·커밋·푸시는 수행하지 않았다. 같은298청크·원문·정답 기준을 사용했고 모델별 입력 계약만 달리했다.

| 선택 | Tiny 완전 포함 | KURE 완전 포함 | Tiny 평균 문자 | KURE 평균 문자 |
|---|---:|---:|---:|---:|
| top5 | 35/38 | 36/38 | 1,815 | 1,865 |
| top12 | 37/38 | 37/38 | 4,452 | 4,375 |
| top20 | 37/38 | 38/38 | 7,467 | 7,439 |
| threshold035 | 37/38 | 38/38 | 25,766 | 84,202 |

완전 포함은 qrel v3의 필수 사실 간 AND·동등 근거 간 OR를 원문 구간으로 판정한다. 평균 문자 수는 불가 질문을 포함한48개 기준이다. topK는 임계값 gate 없이 순위만 비교하며 문자·별도 토큰 제한은 없다. 0.35는 모델 간 같은 관련도를 뜻하지 않으므로 threshold035는 그대로 대입했을 때의 진단이다.

- top12: Tiny 누락 ['R16']; KURE 누락 ['R16']. KURE 개선 []; 회귀 [].

## CPU 측정

| 모델 | warm p50 / p95 | 모델 로딩 | 새 색인 | 최대 RSS |
|---|---:|---:|---:|---:|
| tiny | 9.23 / 15.82ms | 0.29초 | 기존 벡터 재사용 | 1014.0MiB |
| kure | 95.77 / 122.29ms | 1.83초 | 231.83초 | 2705.3MiB |

CPU affinity0·1, threads2, FP32, 단건192회(48×4). warm 시간은 질문 임베딩+벡터 검색·정렬이며 근거 병합·HTTP·LLM을 포함하지 않는다. 모델 로딩은 라이브러리 시작 시간을 제외한다. RSS는 로딩·색인을 포함한 프로세스 최고값이다. 개발 PC CPU2 제한이며 실제 운영2vCPU·동시 요청 검증이 아니다.

KURE 최대 문서 입력은 371토큰으로8192 이내이며 truncation=False다. Tiny는 기존 검증된 벡터를 재사용했다.

## 검증·한계

- tiny source SHA, 192 metric recomputations, 48 full rankings OK
- kure source SHA, 192 metric recomputations, 48 full rankings OK
- Tiny C 재현은 기존37/38·평균25,765.54자와 일치했다.
- 관련도 합집합의 새 독립 검수는 수행하지 않았다. 직접 관련도 precision·답변 정확도 향상을 주장하지 않는다.
- 기존에 여러 번 사용한 개발 세트다. 모델 채택·실서비스 품질·운영 승인은 별도 새 질문과 검수가 필요하다.

원자료: `tiny/results.json`, `kure/results.json`; 전체 순위·코사인·원문 근거·질문별 지표·SHA 포함. `first-complete-ranks.json`은 각 질문의 필수 근거를 처음 모두 확보하는 순위다. 실행기 `run.py`, 조건 `protocol.md`, 고정 모델 카드 `model-card.md`. 모델·DB·벡터는 로컬 tmp에만 존재한다.

## 판단

KURE top20은 개발 필수 근거38/38·평균7,439자로 Tiny C37/38·25,766자보다 유망했다. 그러나 top5에서는 D20 회귀가 있어 모든 질문의 순위가 개선된 것은 아니다. KURE의0.35는 평균246.27/298청크를 선택해84,202자를 전달했다. 모델별 임계값 보정 없이 현재 C 설정에 바로 교체하지 않는다. KURE top20은 후속 새 질문 검증 후보이며 이번 실행만으로 채택하지 않는다.
