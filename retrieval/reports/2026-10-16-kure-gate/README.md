# KURE 상위20·질문 게이트 검증: 서버 전환 보류

> 후속 결정(2026-10-16): 사용자가 근거 유지·전달량 감소를 우선해 [KURE 채택·서버 연결](../2026-10-16-kure-adoption/README.md)을 결정했다. 아래 결과와 당시 판단은 과거 기록으로 보존한다.

2026-10-16. **KURE는 근거를 유지하면서 전달량을 줄였지만 신규 무관 질문 차단4/10으로 사전 최소5/10에 미달했다. 서버는 Tiny C를 유지한다.** 이번 결과를 보고 하한을 재조정하지 않았다. 검색 평가이며 답변 품질·사람 검수·운영 승인 결과가 아니다.

## 질문과 고정 조건

KURE-v1의 최고 코사인이 하한 이상이면 상위20청크를 선택한다. 개별 청크에는 하한을 다시 적용하지 않는다. 상위20은 병합 전 수량이며 원문 중복 병합 후 근거 묶음 수와 다르다. 추가 문자·전달 토큰 상한은 없다. 제공자의 입력 한계는 그대로이며 이번에는 생성기를 호출하지 않았다.

## 결과와 결정

| 단계·구성 | 필수 근거 완전 포함 | 관련 질문 잘못 차단 | 신규 무관 차단 | 문항당 평균 전달 문자 |
|---|---:|---:|---:|---:|
| 개발 Tiny C | 47/48 | 0/55 | 3/10 | 25,007 |
| 개발 KURE + 동결 게이트 | 48/48 | 0/55 | 5/10 | 6,894 |
| 신규 확인 Tiny C | 25/25 | 0/30 | 4/10 | 35,740 |
| 신규 확인 KURE + 동결 게이트 | 25/25 | 0/30 | **4/10** | 6,404 |

개발 원자료의 KURE는 게이트를 적용하지 않은 상위20으로 저장돼 있다(평균7,446자). 표의 개발 게이트 전달량6,894자는 동결 하한 적용 후 재집계다. 개발 CSV의 KURE `gate_rejected`도 하한 적용 전 원자료이며, summary의 차단 목록은 하한을 재적용한 값이다. 필수 사실 간 AND·동등 근거 OR·한 대체 근거 내 구간 AND로 계산했다. 답없음 문항은 근거 완전 포함 분모에서 제외한다.

개발 관련 질문을 하나도 막지 않는 하한 중 신규 무관 차단을 최대화하고 동률이면 낮은 값을 택해 **0.42882221937179565**를 고정했다. 모든 후보는 [threshold-selection.json](threshold-selection.json), 확인 전 후보 동결은 [candidate-freeze.json](candidate-freeze.json)에 있다. 확인에서 C 성공 손실0, 관련 질문 차단0이나 무관 차단 최소 조건 실패로 [summary.json](summary.json)의 `adopted=false`다. 상위20 자체와 게이트를 함께 승인하는 계획이므로 게이트만 빼거나 새 숫자로 바꾸지 않았다.

개발의 차단5개는 모두 일반 질문이고 회사 맥락 무관5개는 통과했다. 확인에서도 회사 맥락 무관5개는 모두 통과했고 일반 질문 중 개인 노트북 배터리 관리(H40, 최고0.481334)가 추가 통과했다. 셔틀(H34,0.699000), 지정 검진병원(H36,0.679901)은 문서에 정답 제도가 없어도 높은 점수였다. **유사한 회사·업무 표현을 찾는 점수는 정답 존재 확률이 아니다.** 이 관측은 원문 답변 가능성 판별이 별도 문제임을 보여주며 KURE 전체가 검색에 부적합하다는 결론은 아니다.

신규 확인에서 전달량은 약82% 감소했지만 직접 관련도 precision/nDCG를 전수 검수하지 않았으므로 같은 비율의 품질 향상이라고 말할 수 없다. 기존 R16 근거 누락은 개발에서 해소됐다. 신규40은 이미 사용했으므로 후속 튜닝에는 새 확인 자료가 필요하다.

개발 PC CPU affinity2·PyTorch2스레드, 고정48×3회. 질문 인코딩·정렬·근거 병합과 잠금 대기를 포함하며 질문 임베딩 캐시를 쓰지 않았다. 준비된 snapshot·색인을 사용하는 실험 검색 경로다. HTTP·매요청 DB 조회·색인 worker의 부하는 포함하지 않으므로 실제 서버/운영2vCPU 성능으로 확대하지 않는다. KURE 로딩+워밍업은 개발6.45초/확인6.03초, 이번 벡터 준비는 기존 pilot 재사용이다. pilot의 새 색인 계산231.83초와 구분한다. 상세 [benchmark.json](benchmark.json).

## 구현·운영 상태

평가 실행기와 회귀 테스트를 추가했다. 독립 코드 검토에서 기존48의 관련성 강제 오류와 벡터 행 순서 검증 누락을 발견하고 RED/GREEN 테스트로 수정했다. 기존 pilot 질의 벡터와 문서 벡터 내적을 기록된 청크별 순위·점수 전체와 대조하며, 이 질의 벡터는 신규 평가에 사용하지 않는다.

**KURE 서버 전환·KURE 별도 색인/기본 복원 묶음·배포 descriptor 변경은 채택 실패에 따라 진행하지 않았다.** 기존 Tiny/full 복구 경로와 자정 복원 코드는 유지한다. 전체 삭제·복원·worker·HTTP 등 기존 회귀의 실행 결과와 게시·외부 반영은 [작업 기록](../../../docs/worklogs/2026-10-16-kure-gate.md)에 남긴다. 실제 KURE 서버 HTTP/자정 통합을 검증했다고 표현하지 않는다.

유료 API·LLM 답변 평가·운영 접속·배포·사람 검수는 수행하지 않았다. 후속 실험은 회사 맥락의 답없음 판별을 별도 검토하고 새 확인 자료를 준비해야 한다.
