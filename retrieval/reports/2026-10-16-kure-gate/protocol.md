# KURE 질문 게이트 사전 평가 절차

2026-10-16 승인된 계획. 기존 Tiny C를 기준선으로 유지하고 KURE 최고 코사인 >=하한일 때 상위20청크를 선택한다. 개별 청크 하한·추가 문자/문맥 토큰 제한 없음. 관련 질의에 자료 없음 안내를 잘못 내는 것과 실제 답을 모르는 것을 구분한다.

## 자료와 동결

기존 개발48(qrel v3) + 새 관련10·무관10으로 개발68. 기존 U 문항은 원문 기준 관련성 메타데이터를 별도 검토하며 answerability 정답은 보존한다. 무관10 최소5 차단의 분모는 신규 개발 무관10만이며 기존 무관문항은 별도 진단이다.

신규확인40은 답가능20·부분5·관련이나현재답없음5·무관10. 기존 모든 질문과 의도를 비교하고 신규 자료의 의도 차이를 기록한다. 개발 실행 전 독립 AI 원문 검토 후 두 자료·관련성 메타데이터·이 절차 SHA를 동결한다. 사람 검수로 표현하지 않는다.

개발 최고점의 정렬된 고유 값 사이 중간값 및 양끝 외측 인접 부동소수점을 후보로 둔다. 관련 질문 차단0을 만족하면서 신규 무관 거절 수 최대, 동률이면 낮은 하한을 선택한다. 신규 무관을5/10 이상 차단하지 못하면 개발 부적격이다. 결과를 보고 문항·조건·하한 선정 규칙을 바꾸지 않는다.

개발 부적격이면 서버 전환과 신규 확인 실행을 보류하고 자료를 미사용으로 보존한다. 개발 적격이면 후보 하한·top20·개발 결과SHA·확인 문항SHA를 동결한 후 C와 신규40을 한 번 비교한다. C가 성공한 필수 근거 문항의 손실0, 관련 질문의 잘못된 게이트 차단0, 무관10개 중5개 이상 차단이 모두 필요하다. 실패 후 재튜닝·재실행하지 않는다.

## 실행과 채택

고정된 같은 snapshot·298청크(360/60, Tiny 분할 tokenizer)의 원문을 사용한다. KURE revision8b418a58414668e75532ed045c22d9ca018ae2b2, CLS/L2·1024차원·접두사 없음, 로컬 CPU FP32. 기존 pilot의 문서 벡터는 source/index SHA·모델 revision·차원·정규화·행 순서를 확인하고 파일SHA를 남겨 재사용한다. 원본 자료는 복사본만 읽으며 변경하지 않는다. Tiny는 기존 C 계약을 유지한다.

질문 모델 입력512토큰 초과는 오류로 남기고 조용히 절단하지 않는다. 기본 벡터 입력의 native 한계는8192이며 서비스 분할은360/60 유지다. 문항/정답을 모델 출력에 맞춰 수정하지 않는다.

필수 근거는 사실간AND·대체근거간OR·대체내구간AND로 평가한다. 답없음 문항은 필수근거 완전포함 분모에서 제외하며 관련성·게이트 검사는 별도다. 새 청크합집합의 직접 관련도 등급을 전수 검수하지 않으므로 precision/nDCG 개선을 주장하지 않는다.

자원은 개발 PC CPU2, 동시1/2 각각 고정 개발48×3회, 질문벡터 캐시 없이 모델호출+검색+병합 전체를 측정한다. 동시성만큼만 제출하고 잠금 대기를 포함한다. warm p95 각각<=3000ms, 최대 RSS<=6144MiB 필요. 실제운영2vCPU가 아니다.

개발·확인·자원 중 어느 하나라도 실패하면 Tiny C 유지. 통과할 때만 KURE runtime·별도 index/baseline·release 계약을 구현하고 회귀 검증 후 기본값 전환. 자동 Tiny/full fallback은 없음. 유료 API·LLM 평가·운영 접속/배포 없음.
