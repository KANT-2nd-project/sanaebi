# 생성 모델 평가 기준

- 상태: **초안** (팀 리더 가이드라인 기준. 세부 기준은 테스트하면서 추가한다)
- 갱신일: 2026-10-15

## 새 생성 모듈과 평가의 경계

[generation 모듈](../generation/README.md)의 상태·원문·답변 계약과 역할별 프롬프트를 별도로 구현 중이다. 현재 단위 테스트는 가짜 모델 호출을 통한 구조·실패 처리를 확인하며 모델 품질 평가가 아니다. COMPLETED는 비어 있지 않은 문자열 답변을 얻었다는 뜻으로, 근거 충분성이나 정답 여부를 보장하지 않는다. 기존 `answer_pipeline/`는 아직 이 모듈을 사용하지 않는다. 새 평가기는 생성 실행 상태와 품질 판정을 분리하고 서비스와 같은 생성 경로·고정 snapshot을 사용하는 방향으로 구현한다. 현재 최소 answer 출력에는 근거 ID가 없으므로 아래 인용 평가 기준까지 구현된 상태가 아니다.

## 새 평가 실행·집계 구현

[generation_evaluation 안내](../generation_evaluation/README.md)를 기준으로 GenerationRun과 run_case를 구현했다. run_case는 질문·문서를 받아 공통 generate_from_documents 경로를 실행한다. 시간은 프롬프트 구성·모델 호출·파싱 구간이며 문서 읽기와 클라이언트 초기화는 제외한다. 이전의 호출·파싱만 측정한 기록과 직접 혼합하지 않는다. 처리된 TIMEOUT은 결과로, 그 밖에 전파된 Exception은 result=None과 오류 클래스 이름으로 기록한다. 사용자 중단은 전파한다.

상태별 개수, 전체 시도를 분모로 한 완료 비율, 전체/완료 실행의 평균 시간, 제공자·모델·timeout·문맥/출력 한도 설정별 그룹화를 구현했다. 빈 집계의 비율·평균은 None이며 0과 구분한다. COMPLETED 비율은 정답률이 아니다. 설정별 그룹화만으로 같은 데이터·문서·프롬프트 비교가 보장되지는 않는다. 설정별 GenerationSummary, 기록 JSONL 저장·읽기·객체 복원과 결과 일관성 검증까지 구현했다. 문서 목록·프롬프트 SHA-256과 문서 수를 기록하며, 비교 집계는 같은 문항·입력인지 검사한다. 의미 기반 품질 판정은 별도 검토다. 독립 생성 CLI와 새 평가 실행기는 같은 generate_from_documents를 사용하며 서버는 아직 기존 경로다. [학습·검증 기록](worklogs/2026-10-15-generation-presets-usage-policy.md)을 따른다.

## 현재 관측과 프롬프트 변경

로컬 Ollama의 문서 한 건 smoke 저장 결과에서 명시 사실 안내, 개인 잔여 일수 추측 회피, 신청 완료 허위 주장 회피를 확인했다. 이는 소수 사례의 AI 검토이며 정식 품질 평가·사람 승인·전체 문서 처리 성능이 아니다. 사용량을 보존하고 length 종료는 TRUNCATED로 성공 집계에서 제외한다.

업무 처리 요청에 대한 기존 응답은 직접 처리할 수 없다고 올바르게 안내했다. 실패를 고쳤다는 의미가 아니라, 모델의 자발적 판단에 의존하던 실행 한계를 시스템 규칙으로 명시했다. 자료 부족 안내도 유지한다. 당시에는 변경 후 재실행이 미확인이었다. 이후 전체 71문서와 5문항 실행·속도 실험·주장별 검토를 진행했으며 최신 근거는 [속도·품질 작업 기록](worklogs/2026-10-15-generation-tps-quality.md)을 따른다. 이전 단계의 상세 값은 [설정·사용량 작업 기록](worklogs/2026-10-15-generation-presets-usage-policy.md)에 보존한다.

## 전체 문서 표본에서 보완할 판정

전체 문서를 넣어 completed/stop으로 끝나도 허구 메뉴·필수사항·문서 섹션, 목표를 보장으로 바꾸는 오류가 관찰됐다. 질문의 SEARCH_KNOWLEDGE 라벨은 현재 문서의 답변 가능성을 보장하지 않는다. 질문별 충분/부분/미확인 근거와 필수 조건을 정답 기준으로 따로 기록해야 한다.

주장별 근거, 조건·주체 보존, 핵심 누락, 실행 한계, 유용성을 나누어 판정한다. 실제 존재하는 메뉴와 일반 표현을 잘못 환각으로 판정하지 않도록 전체 snapshot을 확인한다. AI 검토 판정은 사람 승인과 구분한다. 수동 관련문서 subset은 검색기 성능이 아니라 원인 확인 실험이다.

속도는 요청 전체시간과 `eval_count / (eval_duration / 1e9)` 생성 TPS를 구분한다. 입력 처리·모델 적재·prefix cache 조건을 함께 남기고 다른 지표끼리 개선 배수를 계산하지 않는다. 출력128 속도 실험에서 잘린 응답은 품질 성공으로 세지 않는다.

## 평가 목표

로컬 모델(Ollama `qwen3:4b-instruct-2507-q4_K_M`)과 상용 모델(OpenAI `gpt-6-luna`)에 같은 질문과 같은 회사 지식을 주고, 아래 기준으로 서비스에 쓸 모델을 고른다.

## 1. 지침 준수 (정량 평가)

답변마다 아래 지침을 지켰는지 확인하고, 모델별로 지침마다 지킨 비율을 비교한다.

| 지침 | 확인할 것 | 판정 |
|---|---|---|
| 출력 형식을 JSON으로 준다 | 모델 답변이 실제로 JSON 형식이었는가 | 코드 |
| 답은 회사 데이터 안에서 알 수 있는 정보로만 준다 | 준 정보 외에 다른 정보를 유추하거나, 모델이 원래 알던 정보로 안내하지 않았는가 | 심판 LLM |
| 응대 말투와 상황별 안내 템플릿 가이드라인을 따른다 | 말투와 상황별 안내를 가이드라인대로 했는가 | 심판 LLM |
| 질문에 답한다 | 질문에 필요한 핵심 정보를 빠짐없이 답했는가 | 심판 LLM |
| 근거 문서의 제목을 밝힌다 | 답변에 밝힌 문서 제목이 실제 근거 문서와 맞는가 | 코드 |
| 신청·변경·조회를 처리한 것처럼 말하지 않는다 | 처리하지 않은 일을 처리했다고 말하지 않았는가 | 심판 LLM |
| 한국어로만 답한다 | 중국어·영어 등 다른 언어 문장이 섞이지 않았는가 | 코드 |
| 문서를 길게 베끼지 않고 질문에 맞게 요약한다 | 문서 문장을 그대로 길게 옮기지 않았는가 | 코드 |

- 코드: 평가 코드가 실행 기록으로 자동 판정한다. 근거 문서는 질문마다 적어 둔 정답 문서와 비교한다. 베끼기는 답변과 문서가 그대로 겹치는 길이로 판정하고, 기준 길이는 테스트하면서 정한다.
- 심판 LLM: 지침마다 통과·실패와 이유를 받는다. 모델 이름은 가리고 판정한다.
- 사람 확인: 심판이 실패로 본 답변은 전부, 통과로 본 답변은 일부를 사람이 다시 본다. 사람과 심판의 판정이 같은 비율을 결과에 함께 적는다.

## 2. 추가 비교

1장의 지침을 두 모델 모두 잘 지켰다면 다음을 추가로 비교한다.

- 응답 시간: 평균과 최대
- 호출 실패율: 오류, 시간 초과, 빈 답변의 비율
- 비용: 상용 모델의 호출 비용
- 반복 일관성: 같은 질문을 두 번 했을 때 판정이 갈린 비율
- 답변 길이: 평균 글자 수

모두 평가 코드가 실행 기록으로 잰다.

## 문서 snapshot 고정

서비스의 기본 문서 저장소는 SQLite다. 평가 실행은 라이브 DB를 질문마다 읽지 않으며 명시적 `--documents` JSONL과 대응 평가 세트를 사용한다. 현재 게시본 평가에는 `scripts/export_company_knowledge.py --output tmp/evaluation-documents.jsonl`로 고정 문서와 manifest를 생성한다. 원본 ID·개정·본문 hash·snapshot fingerprint를 함께 보관한다. 과거 기본 평가 세트와 문서 파일 쌍은 유지하며 현재 지식의 품질로 해석하지 않는다. 이관·내보내기 상세는 [문서 관리](document-management.md)를 따른다.

2026-10-14 SQLite 전환 smoke에서 71건 전체 입력은 Ollama 기준 66,652토큰으로 현재 문맥 설정 40,960을 초과해 실패했다. 기존 약 31,000토큰 기록은 현재 입력의 적합성을 보장하지 않는다. 본문 절단·모델 설정 변경 없이 실패를 보존했으며 답변 품질 측정으로 취급하지 않는다. [실행 기록](worklogs/2026-10-14-sqlite-documents.md)을 따른다.

## 독립 생성 경로의 최신 진단

2026-10-15 별도96k 실행 프로필에서 전체71문서 생성과 TPS 개선을 확인했다. GPT-6 Luna와 동일 입력13회(고유5질문)를 비교하니 기존 프롬프트에서도 급여계좌 유보·영수증 분실 절차가 개선되었다. 프롬프트 단독 원인으로 설명할 수 없지만 GPT에도 업무 범위·조회 권한·조건 보존 문제가 남았다. 정식 전체 품질 승인과 구분한다. [실행 설정](generation-runtime.md), [TPS 실측](worklogs/2026-10-15-generation-tps-quality.md), [GPT 비교와 한계](worklogs/2026-10-15-generation-openai-comparison.md)를 따른다. 위 평가 항목의 자동화 완료를 의미하지 않는다.
