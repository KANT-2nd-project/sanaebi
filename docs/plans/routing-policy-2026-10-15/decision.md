# 결정: 문서 기반 Luna 중심 처리와 분류 관찰 비교

결정일: 2026-10-15. 사용자가 방향에 동의했고 **문서화·구현 계획·검수·게시까지만** 요청했다. 구현은 다음 단계에서 사용자가 직접 한다.

## 채택한 방향과 아직 하지 않은 일

- 목표: 질문과 회사 문서를 함께 보는 Luna가 근거 있는 안내, 부분 답변, 필요한 재질문, 지원 범위·조회/실행 한계를 설명한다.
- KoELECTRA는 삭제·재학습·교체하지 않는다. 우선 기존 분류 결과를 기록만 하는 관찰 경로와 기존 강제 차단 경로를 비교한다.
- ‘LLM에 전달’은 일반 지식 답변 허용이 아니다. 회사 업무와 게시 문서의 범위를 유지한다. 실제 권한 통제는 서버 책임이다.
- 최종 프롬프트 `examples_answer_scope_v1`과 Luna 실행 설정은 고정한다. 새 프롬프트 튜닝, 검색 통합, 다중 턴, 실행 도구는 이번 계획에서 제외한다.
- 현재 서비스의 v1 3분류 차단과 API 계약은 아직 그대로다. 방향 채택, 비교 구현 완료, 실험 통과, 기본값 전환을 별도 상태로 기록한다.
- 기존 학습의 승격 보류와 v1 점수는 보존한다. 김치 질문의 SEARCH 전환은 v1 라우팅 퇴행이며 실제 레시피 생성이 확인된 것은 아니다.

## 근거와 이견

기존 8개 회사 조사에서 현재 3분류 사전 차단을 필수로 정한 근거는 확인되지 않았다. 문서 기반 답변과 별도 주제 통제 모두 가능한 선택이다. 현재 정상 업무 질문 차단과 문서 추가 가능성을 고려하여 관찰 비교를 우선한다. 비용 증가와 최종 LLM의 근거·범위 위반 가능성 때문에 검증 전 기본 전환은 하지 않는다.

[공식 출처 요약](references.md), [조사 시점 현재 감사](current-design-audit.md), [구현·비교 계획](implementation-plan.md)를 근거로 삼는다. 공개 샘플과 API 문서는 각 회사의 비공개 전체 운영 구조를 입증하지 않는다.
