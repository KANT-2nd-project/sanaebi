# 상대 개선을 근거로 shadow 기본 경로 채택

## 결정과 근거

사용자는 사전 품질 기준에 미달하더라도 gate보다 개선된 shadow로 교체하기로 결정했다. AI가 설정 변경·회귀 검증·문서 및 Notion 기록을 수행한다. 사용자 독립 구현 성취나 사람의 문항별 품질 승인으로 기록하지 않는다.

고정 v1 실험에서 응답 통과는 gate 50/80 → shadow 63/80, 두 반복 모두 통과는 25/40 → 30/40, 실패 응답은 10/80 → 1/80이었다. 중대한 근거·권한·실행 오류는 양쪽 0건이었다. 불필요한 업무 질문 차단 감소를 이유로 채택하되, 사전 36/40 및 업무·혼합 17/18 기준 미달과 안내 누락은 그대로 남긴다. 요청당 지연 중앙값은 3.1665초 → 3.93초, 동일 80요청 보수 비용 추정은 $0.73862575 → $1.18173425였다.

[원래 비교와 판정](../../generation_evaluation/reports/2026-10-15-routing-shadow/README.md)은 당시 승격 보류 결론을 보존한다. 이번 결정은 그 이후의 사용자 선택이며 점수·루브릭을 소급 변경하지 않는다.

## 적용 범위와 원복

feat/routing-shadow-20261015에서 앱 시작 설정의 미설정 기본값을 shadow로 바꾼다. /ask와 /assistant는 앱 설정을 명시적으로 서비스에 전달한다. 분류 라벨은 관찰하며 유효 게시 문서로 답변을 시도한다. 회사 밖 사실 답변·실제 조회·실행을 허용하지 않는다. 기존 서비스 함수의 직접 호출 기본 인자 gate는 호환성을 위해 유지한다.

원복은 SANAEBI_ROUTING_MODE=gate 지정 후 앱 재시작이다. 기존 환경에 gate가 명시돼 있으면 기본값 변경으로 덮어쓰지 않는다. 프롬프트 본문·생성 설정·라벨 정의·기존 결과는 이번에 수정하지 않는다.

확인한 origin/main은 94eca80이며 별도의 v3 채택·코드 정리가 반영돼 있다. 이번 변경은 기존 실험 브랜치에서만 게시한다. main 병합·실행 중인 서버 재시작·공개 배포·실제 DB 변경은 수행하지 않는다. 실험 v1 결과를 최신 main v3의 측정치로 해석하지 않는다. 원래 작업 공간의 사용자 웹 변경을 보존한다.

## 검증과 게시

미설정 상태의 실제 앱 lifespan 및 /ask·/assistant mock 회귀, 명시 gate 원복·차단, 오류·trace 계약을 검사한다. 유료 모델 호출은 추가하지 않는다. 최종 실행 결과와 게시 확인은 아래에 기록한다.

- 설정/API/문서 런타임 대상 44개 통과. 기존 gate 전제 테스트는 모드를 명시해 보존했다.
- 격리 문서 DB로 전체 Python 633개 통과(53.350초). 최종 로그: tmp/routing-shadow-20261015/python-tests-shadow-adoption-verified.log.
- Ruff check·format 통과, 변경 문서의 로컬 링크 113개 대상 존재 확인, git diff --check 통과.
- 최초 검사에서 기존 문서 런타임의 gate 전제 1건을 발견·수정했다. 중간 두 실행의 로그 경로가 겹쳐 최종 증거로 사용하지 않고, 종료 후 별도 로그로 전체 검사를 다시 실행했다.
- 웹 코드 변경·추가 유료 API 호출 없음. 기존 실모델 비교를 새 기본값 채택 근거로 사용하며 새 품질 실험을 주장하지 않는다.
- 코드 커밋: 40df113. 문서 게시 후 Notion 서비스·라벨·분류 일지에 후속 결정과 링크를 반영하고 재조회한다.
