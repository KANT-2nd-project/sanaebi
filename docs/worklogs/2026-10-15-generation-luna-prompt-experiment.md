# GPT-6 Luna 프롬프트 강화 실험

사용자가 선택한 GPT-6 Luna의 프롬프트 강화 구현·실행·비교·기록을 AI에 위임했다. 사용자 독립 구현이나 사람의 품질 승인으로 기록하지 않는다. 앞선 두 모델 중 더 좋은 모델을 고른다는 결정은 유지하며, 이번에는 같은 GPT의 프롬프트만 비교한다.

## 변경 계기와 구현

이전 GPT 응답에서 허구 정책보다 필수 안내 누락이 주된 잔여 문제였다. 규칙을 계속 늘리는 대신 세 요소를 독립적으로 비교했다. `examples_coverage`는 필요한 담당자·기한·조건·증빙의 누락 점검, `examples_conditions`는 여러 문서의 조건 연결, `examples_json`은 대조 예시를 JSON 응답 계약에 맞춘 후보다. 기준 examples와 공통 `generation/prompts.py`는 그대로 보존했다.

실행기에 전체·개발 비용/시간 인자를 추가했다. 독립 검토에서 출력 폴더를 바꾸면 공용 원장의 한도를 다르게 지정할 수 있는 문제가 발견돼 한도를 원장에도 결합했다. 재개 시 이력·식별자·시작 시각과 설정을 검증한다. 사용자 최초 승인2시간·3달러 이후 비용 제한 철회를 별도 기록했고, 기존 실험 원장은 수정하지 않았다.

## 평가 기준을 먼저 검토한 이유

JSON 성공은 정확한 답변의 충분조건이 아니다. 형식, 근거, 적용 범위·조건, 필수 안내, 유보, 실제 실행 경계, 존댓말, 관련성의8차원을 판정했다. 의미가 같은 표현을 인정하고 선택적 배경을 필수로 요구하지 않는다. 개발 RQ0007의 기준이 문서보다 강한 점과 RQ0009의 목표/해결 보장 구분을 독립 재검토하고 판단 전후를 보존했다.

새20문항은 문항 작성자와 검토자를 분리했다. 질문 그룹 ID가 달라도 의미가 비슷한 경비·구매 사례는 제거했다. 내부 게시 질문에 외부 공개 절차를 필수로 요구하던 기준, 외부 공유 보호 조건·후속 담당/기한 기록 누락을 실제 호출 전에 수정했다. 같은71문서를 쓰므로 새로운 정책에 대한 일반화 검증은 아니며 직무교육 정책의 인접 사례도 남는다.

## 개발 결과와 중단 판단

기준은8문항×2회에서 통과11·부분5, 필수 안내 점검은 통과13·부분3이었다. 두 반복 모두 통과는5/8→6/8이다. 조건 연결은1회 통과6·부분2, JSON 예시는통과5·부분3으로 최선 후보보다 개선되지 않았다. 두 후보 연속 무개선 규칙에 따라 추가 튜닝을 종료했다. 필수 안내 점검도 경비 입력 항목을 두 번째에는 누락하여 안정적 해결로 단정하지 않았다.

## 최종 비교와 채택

고정20문항×2구성×2회, ABBA순서 비교와 블라인드 판정을 완료했다. 기존은 통과29·부분11·두 반복 통과14/20, coverage는통과27·부분13·두 반복 통과13/20이며 양쪽 중대 오류·실패0이다. 기준 examples를 유지하고 coverage를 채택하지 않는다. 사용자가 회귀 실행 중 일시 중단을 요청해 현재 후보까지만 완료한다. 회귀 전체 판정과 최종 게시·Notion 갱신은 재개 후 남은 작업이다. [상세 보고서](../../generation_evaluation/reports/2026-10-15-luna-prompt-improvement/README.md)에 원응답·근거·판정·비용과 한계를 남긴다.

## 검증과 게시

공용 원장 한도 고정까지 생성 관련213개 테스트를 통과했다. 전체 Ruff check와240파일 format check를 확인했다. 기존 main 작업 트리와 다른 작성자의 변경은 보존하고 생성 전용 브랜치에서 기능별로 커밋한다. main 병합과 서버 연결은 이번 범위에 포함하지 않는다. 최종 보고서 게시 후 Notion 개인 일지·프로젝트 문서 안내에 결과와 링크를 반영하고 재조회한다.

## 후속 종료 결정

이 일지는 당시 실험 경과를 보존한다. 이후 사용자는 `examples_answer_scope_v1`을 최종 선택하고 튜닝을 종료했다. [종료·기록 점검 일지](2026-10-15-generation-prompt-tuning-closure.md)에서 추가4문항, 사용자 채택, 미완료 회귀 범위와 게시 보완을 확인한다.
