# 분류 실험 관리 단순화와 로컬 MLflow

## 범위와 기준

기준 커밋은 `d36c4b8`이다. 계획에 있던 `8c12050` 결과 merge는 이미 별도 커밋으로 완료되어 있었으며, 이번에는 다시 병합하거나 결과를 재생성하지 않았다. 당시 작성자 확인과 보존·정합성 검사는 [이전 병합 기록](2026-10-14-classification-results-merge.md)을 따른다.

학습·모델 선택 코드와 분할 알고리즘은 유지하고, 실험 실행·저장·기록 계층을 변경했다. 실제 Transformer 재학습, 외부 Jev 요청, 모델 선정과 서버 변경은 수행하지 않았다.

## 변경 전후

| 항목 | 이전 | 현재 |
|---|---|---|
| 기존 모델에서 train | 조건 fingerprint와 파일 해시 검사 후 재사용 | 폴더가 있으면 조건 검사·학습·run 생성 없이 안내 종료. `--force` 또는 다른 저장소로 명시 |
| 모델 기록 | 파일별 해시·환경·소스에 연결된 manifest | v2 최소 manifest와 UUID model_id, 학습 run ID. v1은 수정 없이 읽기 |
| 저장 보호 | 잠금·임시 저장·복원·journal 자동 복구 | 잠금·재로딩 검증·예외 복원·직전 백업 유지. 강제 종료 흔적은 보존하고 수동 확인 |
| 결과 확인 | 새 HTML·비교 페이지 생성 | 로컬 MLflow SQLite의 run·지표·JSON·trial CSV. 기존 HTML·재출력 경로 보존 |
| 추적 의존성 | 자체 관리 코드 | CLI의 `tracking.py`로 분리. 모델 계산·workflow에는 MLflow 의존성 없음 |
| 평가 의미 | 기본 validation, 명시적 test | 같은 계약 유지. 학습과 기본 eval은 test 예측 없음 |

MLflow 3.17.1을 `uv add mlflow`로 추가했다. 추적 DB·산출물은 각 artifact-root 아래에 두고 가중치는 중복 업로드하지 않는다. 과거 결과는 이관하지 않는다. 실행 설정·코드 버전·라이브러리는 해석용 기록이며 재사용 차단 조건이 아니다. 학습 완료 후 후보별 epoch 지표를 기록하며 nested run은 만들지 않는다.

현재 로컬 모델의 평가 run은 model_id와 학습 run ID로 연결한다. 학습 ID가 없는 구형 모델은 추정하지 않는다. 구형 문서 모델의 새 평가는 `eval_legacy/both`, Jev는 기존 평가 범위 그대로 `eval/both`로 기록하므로 현행 validation 비교 필터에서 제외된다. 저장된 구형 API 결과의 HTML 재출력은 새 API 요청·run을 만들지 않는다.

초기화 실패 시 실제 학습·API 요청 전에 중단한다. 로컬 저장 이후 추적 기록이 실패하면 저장 자료를 보존하고 실패로 종료한다. 자동 재학습·재요청은 하지 않는다. UI 실행 방법과 수동 복구는 [분류 안내](../../classification/README.md)에 둔다.

## 검증

- 기존 폴더에서 데이터 준비조차 호출하지 않는 집중 테스트를 먼저 작성해 실패를 확인한 후 구현했다.
- 최종 전체 Python 테스트: **281개 실행, OK (skipped=1), 47.848초**. 제외한 항목은 실제 Ollama 연동이다.
- 작은 60문항 TF-IDF로 학습 → 기존 폴더 안내 → validation → test → 명시적 재학습을 실행했다. 분할별 결과 공존, 새 model_id와 직전 백업, 구형 manifest의 변경 없는 평가를 확인했다.
- 임시 SQLite를 직접 조회해 run 상태·설정·지표·후보별 epoch 곡선·trial CSV·예측 산출물·학습/평가 연결과 validation 필터를 검사했다.
- Transformer는 기존 작은 텐서·대체 모델 계약 테스트, Jev는 모의 요청으로 검사했다. 저장 실패 복원, 추적 실패 시 자료 보존, preview 무부작용과 test 경계를 검사했다.
- Ruff check 통과, format check 135파일 통과, 데이터 검증 900문항·라벨별 300·392그룹·검수 900행 통과, `git diff --check` 통과.
- localhost MLflow UI의 `Model training`에서 학습·validation run 목록, validation 지표, 산출물 목록과 `metrics.json` 본문을 열었다. 확인 후 브라우저·서버를 종료했다. UI의 사용자 정보 조회 404와 라이브러리 사용 중단 예정 경고는 있었지만 확인한 기능은 정상 작동했다.
- 시작 전에 기록한 데이터·과거 결과 **9,059개 파일은 모두 바이트가 동일**했다. 기존 가중치는 재학습·교체하지 않았다. 새 실험은 임시 저장소에서 실행했다.

검증 로그·UI 캡처·임시 DB는 Git 제외 `tmp/mlflow-simplification-2026-10-14/`에 있다. 초기 모의 테스트가 기본 루트에 만든 run 1개는 이 폴더의 `first-test-tracking/`에 보존했고, 이후 테스트는 모두 임시 루트를 지정한다. 해당 보관 DB의 산출물 절대 경로는 원래 위치를 가리키므로 정상 사용 DB로 취급하지 않는다.

이 검증은 관리 계층의 계약 확인이며 실제 모델 정확도 개선이나 새로운 최종 평가를 의미하지 않는다. 현재 test는 이미 열람한 개발 자료다. MLflow에는 과거 run 기록이 남아도 모든 run의 가중치가 영구 보존되지는 않는다.

## 문서 반영

README·분류 안내·서버 규약·문서 대응표를 갱신했다. 구현 `1e569ed`, 사용 안내·검증 기록 `4260443`을 main에 게시했다. 원격 게시 후 대응표의 프로젝트 문서 안내·서비스 처리 기준·데이터 작성·검수·실험 절차에 새 관리 정책과 게시된 기준 링크를 반영하고 세 페이지 모두 재조회했다. 과거 검증 수치는 과거 기록으로 구분해 보존했다. 담당자·기한·업무 상태는 변경하지 않았다.

게시 후 확인 중 웹·배포 문서와 패키지 관련 별도 작업 변경이 생겼다. 해당 변경은 이번 커밋에 추가하지 않고 보존한다. 원격 일치와 작업 트리의 전체 무변경 상태는 구분한다.
