# 채팅 사용 안내 모달·안내 통합 — 2026-10-15

## 문제와 사용자 결정

헤더에서 연 안내가 대화 안에 나타나고 안내 내부에 닫기 동작이 없어 흐름을 혼동시켰다. 사용자는 모달 분리 방향을 선택하고 구현·검증을 위임했다. 후속으로 입력창 하단의 이전 메시지·입력 보존 설명도 모달로 통합하고 배경 클릭으로 닫도록 결정했다. AI가 코드·문서 수정과 브라우저 검증을 수행했다. 사용자 독립 구현이나 사람 접근성 검수를 의미하지 않는다.

## 최종 동작

- 헤더의 정보 아이콘·사용 안내 버튼이 대화 영역 밖의 네이티브 dialog를 연다. 안내용 scrollIntoView를 제거했다.
- 제목 초기 포커스, 닫기·본문 사이 Tab/Shift+Tab 이동, 본문 키보드 스크롤, 닫은 뒤 호출 버튼 포커스 복원을 제공한다.
- 닫기 버튼·Esc·모달 바깥 배경 클릭으로 닫는다. 내부 클릭과 내부에서 시작한 드래그는 닫지 않는다. 배경의 채팅 컨트롤은 조작되지 않는다.
- 안내 개폐는 대화·입력·진행 요청을 유지한다. 안내 중 도착한 성공/오류는 기존 상태·스크롤 정책대로 반영한다.
- 최대520px·좌우16px·최대90dvh, 제목과 닫기는 고정하고 본문만 스크롤한다. 기존18px 표면·10px 컨트롤·44px 클릭 영역을 사용한다.
- 질문 범위·방법·기억할 점에 안내를 모았다. 입력창 하단 중복 설명과 해당 aria-describedby 참조·미사용 CSS를 제거했다.

현재 기준은 [프런트엔드 설계](../frontend-architecture.md#요청-흐름과-계약)와 [웹 안내](../../web/README.md#질문-요청과-테스트)에서 관리한다. 서버·모델·공개 API·대화 저장 정책·의존성은 변경하지 않았다.

## 검증 결과와 한계

기존 웹 테스트64개, lint·typecheck·정적 build·git diff --check가 통과했다. 최종 모달 정책으로 브라우저42개와 진행 요청6개, 하단 통합·배경 닫기9개 확인을 실행했다. 모든 API 요청은 대체했으며 실제 LLM·문서 쓰기는 호출하지 않았다.
