# 문서 관리 UI·UX 개선과 실제 쓰기 검증 — 2026-10-15

## 결정과 구현

사용자는 버튼의 부피감·간격·레이아웃을 지적하고 독립 검수 후 개선을 위임했다. 제목·상태를 함께 검색하고 게시 제목을 우선 표시하는 방식을 선택했다. 이어 실제 쓰기 검증, 개발용 문구의 내부 문서화, 기능별 게시와 Notion·개인 일지 반영을 요청했다. AI가 구현·실행·검수 조율·문서·게시를 수행했다. 사용자 독립 구현·숙련도나 사람 품질 승인으로 기록하지 않는다.

- 제목과 상태는 검색 버튼/Enter로 함께 적용한다. 입력 조건과 적용 조건을 구분하고 초기화·뒤로/앞으로 이동에서 복원한다. 검색은 기존 서버 계약대로 초안 제목을 대상으로 한다.
- 목록 주 제목·부서는 상세 기본 개정과 같은 게시본 우선이며 변경 초안 제목은 보조 표시한다. 중단 문서는 마지막 게시본임을 표시한다. 상단 결과 요약과 하단 페이지 이동을 분리하고 한 페이지면 이동 버튼을 생략한다.
- 공통 모서리 토큰과 상태 규칙, 최소44px·문서 버튼 기본 좌우padding12px, 내용너비 액션을 적용했다. 편집 설명→폼24px·필드20px·내부8px를 사용한다. 중단은 별도 테두리 위험 동작으로 구분한다.
- 개발 연결·모델 준비·인증 미구현·내부 ID·해시 설명은 사용자 화면에서 제거하고 내부 문서/API에 남겼다. 저장·게시·중단·미저장 입력·출처·검수 상태 등 사용 판단에 필요한 안내는 유지한다.
- 서버/API·데이터 계약은 변경하지 않았다. capabilities API는 유지하고 화면 조회만 제거했다.

## 실제 쓰기와 보존

정적 웹 → 검증용 HTTP 중계 → 실제 FastAPI → 격리 SQLite에서 생성·조회·수정·검색·게시·사용 중단을 실행했다. 기존 시연 DB는 사용하지 않았다. 수정 초안 저장 후 기존 게시본 snapshot 유지, 게시 교체 후 새 개정 공급, 중단 후 snapshot0건을 확인했다. 동일 UUID 멱등키 재요청은 같은 개정을 반환했고 오래된 버전 저장은409로 거부하면서 브라우저 입력을 보존했다. 최신 초안을 선택해 수정·재게시했다. API 프로세스를 재시작한 뒤에도 개정6과 중단 상태가 유지됐고 SQLite integrity_check=ok였다. 테스트 문서 한 건과 개정 기록은 로컬 검증 DB에 남겼고 임시 서버·중계·브라우저는 종료했다.

첫 병행 수정 스크립트의 비UUID 키는400으로 거부됐다. 검증 스크립트를 계약에 맞췄으며 제품 오류로 분류하지 않았다. 네이티브 확인창 때문에 CLI 결과 출력이 누락된 흐름은 실제 DB 상태를 조회한 뒤 반복했다. 반복 검사는 확인창 응답만 대체했고 HTTP/DB는 실제였다.

실모델·실기기 가상 키보드·스크린리더·운영 인증은 미검증이다. 실제 쓰기 성공은 LLM 답변 품질을 뜻하지 않는다. 세부 캡처·재현 스크립트·원로그는 Git 제외 `tmp/documents-product-audit-2026-10-15/`의 implementation·real-write에 보존하며 공개 다운로드 자료로 연결하지 않는다.

## 게시 경계

검색·목록 흐름, 공통 스타일·제품 문구, 관련 안내·검증 기록을 구분해 게시한다. 기존 dialog 위치·스크롤 보정은 검증된 화면의 선행 조건으로 함께 포함한다. 홈페이지의 오래된 연결 확인 설명도 현재 게시문서 기반 안내로 맞췄다. 생성·서버·자정 초기화 구현 및 초기화 전용 화면 안내·문서는 이번 커밋에서 제외한다. 작업 트리에서는 해당 변경을 보존하며 가중치·DB·환경 파일은 게시하지 않는다.
