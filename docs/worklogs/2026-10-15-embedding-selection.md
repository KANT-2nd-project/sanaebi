# 한국어 CPU 임베딩 16종 비교와 KoEn-E5-Tiny 채택 기록

## 요청·기여·범위

2026-10-15 사용자는 2vCPU·16GB RAM, 외부 답변 LLM 조건에서 로컬 한국어 임베딩을 조사·실험하도록 요청했다. E5 → BGE-M3/KURE → 추가 실행 가능한 후보 순서로 범위를 넓힌 뒤 KoEn-E5-Tiny 채택과 기록·Notion·커밋·푸시를 지시했다. 사용자는 요구·범위·최종 모델 선택을 결정했고 AI가 조사·스크립트 작성·실험·검증·게시를 수행했다. 사람의 독립 구현·검수 또는 운영 품질 검증으로 기록하지 않는다.

## 실험과 판단

[공식 보고서](../../retrieval/reports/2026-10-15-cpu-embedding-comparison/README.md)에 질문·청크·측정 조건·16종 비교·한계·원자료를 정리했다. 초기 E5 1종, BGE-M3/KURE 2종, 추가 13종 실행을 합쳤으며 접근 제한 EmbeddingGemma는 미실행이다. 실험의 전체 모델·소스 revision·실행 Git HEAD는 보고서 provenance와 results에 보존했다.

KoEn-E5-Tiny는 지정 근거 @5 17/18, 문서 @5 18/18, 질문 p50/p95 10.31/13.24ms였다. PR 자기 승인 질문에는 다른 표현의 명시적인 금지 근거가 2위에 있었다. 원래 점수는 유지했다. 사용자가 속도·검색 균형을 보고 채택했으며 단독 최고·실서비스 100%를 주장하지 않는다.

## 보존과 검증

- 원래 tmp 3개 폴더의 결과·벡터·로그를 이동·삭제하지 않았다. Git에는 작은 비교표·질문별 순위·모델별 측정 JSON·공통 청크·당시 스크립트를 복사했다. 예측 JSON은 중복 hits 본문만 제외했으며 출처 변환을 명시했다.
- 신규 13종은 저장 벡터에서 순위·Hit@k·MRR, 단위 벡터·질문·원문 span과 SHA를 재검증했다. 이전 3종은 앞 실험 결과를 보존했다. 이번 게시 단계는 모델 재추론 없이 산출물을 대조한다.
- 16종 비교 CSV, 질문별 352행, 모델별 22개 예측·상위5개 chunk index·지정 문서/근거 순위, 원문 SHA·선정 revision·보존 스크립트 11개 원본 일치를 확인했다.
- 상대 링크 111개, Markdown 표의 16개 결과 행, Git diff, 보존 스크립트 11개 Ruff check·format check를 확인했다. 새 모델 호출 없이 저장 벡터 13종 검증도 재실행해 통과했다. 서버·웹의 다른 작업을 분리하기 위해 origin/main b21d4ef 기준의 별도 worktree와 docs/embedding-selection-20261015 브랜치를 사용한다.

## 현재 상태와 후속

모델 선정은 완료했다. 이 변경은 서버 RAG·벡터 DB·색인 동기화·라이브 DB·런타임 환경 설정을 구현하지 않는다. 배포 CPU에서 분류기와 동시 부하, 새 사람 검수 질문, 게시·개정·사용 중단·reset 일관성, 검색 근거 기반 LLM 답변은 후속이다. 이전 실험·일지와 다른 작업 변경은 보존한다.

## 게시·외부 반영

### 후속: main 병합 완료

사용자의 추가 요청으로 최신 origin/main b21d4ef가 선정 브랜치 a946b6f의 조상임을 확인하고, 충돌 없이 fast-forward로 원격 main에 게시했다. 원격 main이 a946b6f를 가리키는 것을 확인했다. 앞선 main 미병합 설명은 최초 게시 당시 기록이다.

변경 범위는 임베딩 보고서·증거·문서 연결이며 diff 검사가 통과했다. 기존 검증된 커밋 그대로의 병합이므로 모델 재추론·학습·전체 서버 테스트는 재실행하지 않았다. 별도 worktree에서 수행해 현재 서버 통합 브랜치와 미커밋 문서 변경을 건드리지 않았다. Notion 프로젝트 문서 안내와 새 개인 일지의 게시 상태도 main 병합 완료로 갱신하고 재조회했다.
