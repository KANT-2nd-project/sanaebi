# 개발 통합 실행 검증

## 결정과 구현

사용자가 개발용 통합 실행, 문서·Notion·개인 일지 갱신과 커밋·푸시를 요청했고 AI가 구현·검증했다. 루트 private npm 패키지의 concurrently 10.0.6으로 FastAPI와 기존 웹 개발 실행기를 묶었다. `npm run dev`, `dev:api`, `dev:web`을 제공하며 Python·웹 의존성과 잠금 파일은 각각 유지한다. 최초 설치와 모델 준비는 실행에서 분리했다.

루트 잠금 파일 추가 후 Next의 루트 추론 경고가 발생했다. 설치된 Next 16.4.0 문서에 따라 `turbopack.root`를 웹 디렉터리로 명시해 기존 모듈 탐색 범위를 유지했고 이후 개발·빌드에서 해당 경고가 사라졌다. API 계약·운영 배포 방식은 변경하지 않았다.

## 실제 검증

WSL/Linux, Node 22.22.1에서 확인했다.

- 루트 `npm ci`: 성공, audit 취약점 0개.
- 웹 lint·typecheck·기존 테스트 50개·정적 build: 성공. 소개·chat·admin/documents 정적 경로 생성 확인.
- `uv run --locked ruff check .`, `uv run --locked ruff format --check .`: 성공(최종 137개 파일).
- 임시 SQLite를 지정한 `npm run dev`: API와 웹 기동, API 루트와 `/api` 중계 200, 빈 `/api/ask` 입력 422 및 `Cache-Control: no-store` 확인. 실제 모델 호출은 하지 않았다.
- Playwright CLI와 설치된 Chromium으로 `/chat` 렌더링 확인. CSS 임시 속성 추가·원복이 브라우저에서 새로고침 없이 반영됐다. 검증용 CSS는 원복했다.
- API 소스 파일 변경 감지 후 reloader가 서버 PID를 교체하고 startup 완료. 소스 내용은 변경하지 않았다.
- PTY에서 Ctrl+C로 통합 실행을 두 차례 종료한 뒤 3000·8000 포트 해제 확인. 인터럽트 시 concurrently 종료 코드는 1이었다.
- 8000·3000 각각을 임시 소켓으로 선점한 상태에서 통합 실행은 비정상 종료했고 다른 자식의 포트를 정리했다. 선점 소켓은 유지됐다.
- `dev:api`·`dev:web` 개별 실행 각각 HTTP 200 및 SIGINT 종료 후 포트 해제 확인.

기존 3000·8000 서버는 사용자 허용 후 종료했다. 검증 서버 역시 종료했으며 기존 문서 DB는 사용하지 않았다. Windows 실제 실행·실모델 답변 품질·외부 배포는 검증하지 않았다. 정적 빌드 성공은 nginx 종단 재검증을 뜻하지 않는다.

## 문서와 게시 범위

README·웹 안내·프런트 설계·배포 안내를 갱신했다. 과거 echo 검증 기록은 유지하고 배포 안내의 현재 동작만 분류 후 LangChain 답변으로 정정했다.

시작 시 있던 분류·MLflow 미커밋 변경은 이번 작업에 포함하지 않았다. 작업 중 별도 작업이 해당 변경을 `1e569ed`·`4260443`·`b4ebec3`으로 게시한 것을 확인했다. 이번 변경은 그 위에서 별도로 커밋한다.

Notion 반영 대상은 프로젝트 문서 안내의 프런트 구역, 운영·개발 규칙의 실행 안내, 서비스 처리 기준의 프런트·배포 구역과 최재선 개인 작업 일지다. 원격 게시 후 커밋 링크와 검증 범위를 연결하고 재조회한다. 실제 반영 결과는 후속 게시 기록에 남긴다.
