# 2026-10-15 프롬프트 최종 선택·튜닝 종료·기록 점검

## 사용자 결정

사용자는 추가4문항 결과까지 확인한 뒤 답변 범위 보강안 `examples_answer_scope_v1`을 최종 선택하고 프롬프트 튜닝을 여기서 끝내기로 했다. GPT-6 Luna / single / xhigh / 4096 / timeout180 / prompt_json / temperature 생략을 채택 구성으로 기록한다. strict 출력은 채택하지 않는다.

사전 회귀 게이트에서는 탈락했지만 사용자가 알려진 누락을 감수하고 선택한 후속 결정이다. 과거 점수와 판정을 바꾸지 않고 결정의 시점·주체를 구분한다. 서비스 품질 승인이 아니며 이번에는 실행 코드·기본 설정을 바꾸거나 모델을 재호출하지 않는다.

## 기록 점검에서 발견한 누락

1. 이전 coverage 개선 실험의 최종80응답은 로컬에 있으나 커밋·Notion에는 개발48응답 이후 결과가 빠져 있었다. 저장된48·80응답/판정을 재집계해 기존 요약과 일치함을 확인하고 역사 기록으로 보완한다.
2. 당시 보고서 하단의 “최종 결과 없음/진행 중”은 최초 게시 시점 기록이었다. 현재 결론과 혼동하지 않도록 역사 구역으로 표시하고 최신 결정으로 연결한다.
3. 사용자 중단 때 회귀60회는 실행됐지만 판정이 일부 남았다. 이를 완료로 꾸미지 않고 미판정·미실행 항목을 목록화하여 종료한다.
4. 레퍼런스 조사는 tmp에만 있었다. 당시30개 출처 목록과 원자료 해시, 최소 문단 채택/전체 교체안 미사용 경위를 영구 기록으로 연결한다.
5. 짧은 추가4문항 결과도 tmp에만 있어 원응답·검토·manifest를 보고서에 보존한다.
6. “기존 examples 유지”라는 이전 결론 뒤에 이번 사용자의 최종 scope 채택·튜닝 종료를 명시한다.

## 실험에서 확인한 점

coverage는 개발에서11/16→13/16으로 개선됐지만 최종20문항각2회에서는29/40→27/40으로 낮아 채택하지 않았다. 이후 공개 자료를 조사해 문구를 계속 늘리는 대신 질문에 필요한 범위와 부분 답변을 명확히 하는 최소 보강안을 만들었다.

scope와 strict는 개발12문항에서 기준9통과 대비11통과였지만 신고 필수 정보 누락이 새로 생겨 회귀 게이트에서 제외됐다. 추가4문항은 통과2·부분2였고 목격자 정보 누락이 재현됐다. JSON은 정상이더라도 내용의 완전성이 보장되지 않았으며, 평가 기준 자체의 과잉 요구·평가자 적용 오류도 별도로 검토해야 했다.

이 과정은 사용자 요청에 따라 AI가 구현·실행·독립 검토·문서화한 작업이다. 사용자의 독립 학습 성취로 기록하지 않는다. 사용자 기여는 목표·평가 항목·예산/호출 한도·중단/재개·최종 채택 결정이다.

## 기준 위치와 게시

현재 구성은 [최종 프롬프트 기준](../generation-final-prompt.md), 과정·수치·미완료 범위는 [기록 점검 보고서](../../generation_evaluation/reports/2026-10-15-luna-tuning-closure/README.md)가 기준이다. 원응답과 이전 판단은 각 당시 보고서에 보존한다. Notion에는 요약·선택 이유·미완료 범위와 게시 링크를 동기화하고 재조회한다.
