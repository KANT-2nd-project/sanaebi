# 공용 시연 문서 자정 초기화 — 2026-10-15

## 결정과 구현

사용자 요청으로 공용 시연 DB를 저장소 원본 JSONL의 게시 상태로 매일 한국 시간 자정에 복원하는 명령과 systemd 서비스·타이머 템플릿을 구현했다. 실제 별도 서버 설치·예약 활성화와 현재 시연 DB 초기화는 범위 밖이며 수행하지 않았다. 기존 사용자 변경은 보존했고 커밋·푸시는 하지 않았다. 시작 시 로컬 main과 원격 main은 `cf6bf0481e285e2f6f05ac7d207418e1e4a57748`로 일치했다.

초기화 모듈은 메모리 기준본 검증, 대상 DB별 비차단 프로세스 잠금, SQLite 쓰기 잠금 아래 backup API 백업, 단일 트랜잭션 복원·검증·롤백을 담당한다. 실행 중 DB 파일 교체는 없다. 관리 ID 유지·버전 증가와 기존 멱등 키 무효화로 오래된 요청을 거부한다. 멱등 키 생성 시각과 기존 24시간 TTL을 보존한다. 불변 개정의 삭제 방지 trigger는 복원 트랜잭션 안에서만 해제·복구한다. 레거시 이관 추적도 백업 후 비우며 관련 없는 테이블은 삭제하지 않는다.

CLI 기본은 dry-run이며 적용은 --apply로 명시한다. 실패 시 문서가 들어갈 수 있는 예외 원문 대신 오류 종류를 출력한다. 초기화 백업과 실행 manifest는 Git 제외 경로에 보관한다. systemd는 `Asia/Seoul` 자정, `Persistent=false`, 자동 재시도 없음이다. 문서 관리·채팅 등록 UI에 안내를 추가했다.

기준 정책은 [문서 관리](../document-management.md#공용-시연-문서-자정-초기화), 설치는 [배포 안내](../../deployment/README.md#시연-문서-자정-초기화-systemd)에 정리했다. 서버 규약·서비스 설계에는 요약과 링크를 반영했다.

## 검증

- focused-tdd: 초기 모듈 stub에서 복원 버전 증가·잘못된 원본 거부 assertion의 실패를 확인한 뒤 구현했다. import 누락 실패와 실제 assertion 실패를 구분했다.
- 전체 Python: `uv run --locked python -m unittest discover -s tests -v` — 471개 실행, 1개 skip, 나머지 통과. 이 실행에는 당시 초기화 테스트 9개가 포함됐다.
- 후속 초기화 전용 테스트: 12개 통과. 추가 3개는 원본 JSONL 전체·레거시 이관 추적 복원, 실제 HTTP 409/404 및 레거시 신규 등록, 잘못된 행·중복 원본 거부다. 동시 쓰기는 초기화 잠금 중 완료되지 않고 커밋 뒤 수행됨을 확인했다.
- 복원·백업 보존·실패 롤백·trigger 복구·WAL 읽기 일관성·중복 프로세스·반복 초기화 버전 증가·멱등 키 TTL·CLI 정보 노출 방지를 임시 DB로 확인했다. 실제 로컬 시연 DB를 초기화하지 않았다.
- 웹 테스트 54개, lint, 정적 build, typecheck 통과. 실제 브라우저 조작·실기기 화면은 별도 검증하지 않았다.
- 전체 Ruff check·format check, `git diff --check` 통과.
- 템플릿을 `tmp/demo-reset-systemd-check/`에서 로컬 경로·계정으로 치환해 `systemd-analyze verify` 통과. 서비스를 설치하거나 실행하지 않았다.
- `systemd-analyze calendar --iterations=2 '*-*-* 00:00:00 Asia/Seoul'`: 다음 두 실행은 2026-10-16 00:00 KST, 2026-10-17 00:00 KST. 실제 서버 예약은 미활성화·미검증이다.

전체 Python 로그는 이번 환경의 `/tmp/sanaebi-reset-python-tests.log`, 후속 초기화 로그는 `/tmp/sanaebi-reset-focused-tests.log`에 남겼다. 임시 로그는 공유 산출물·영구 보존 자료가 아니다. 실모델 호출·성능 평가는 이번 검증 범위가 아니다.
