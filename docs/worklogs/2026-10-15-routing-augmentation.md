기준 main은 `0a95cab`, 기능 브랜치는 `feat/classifier-augmentation-20261015`다. main과 원격 일치를 확인하고 브랜치를 만들었다. main 병합·공개 배포는 수행하지 않는다.

## 진행과 결정

1. 진단 48문항 29개 정답, 표현 24문항 18개 정답을 확인했다. 안내 요청과 모호한 도움 요청이 과도하게 차단됐다. 생성 프롬프트는 변경하지 않았다.
2. 원본 900행을 보존하고 기존 train 17그룹에 90문항을 추가했다. 새 평가 30문항과 승격 기준을 학습 전에 고정했다. 같은 AI가 라벨을 검수했으며 독립 검수로 표시하지 않았다.
3. `--split-manifest`와 외부 진단 평가기를 구현했다. 고정 분할 테스트가 함수 부재로 실패하는 것을 확인한 뒤 구현하여 통과시켰다. 기존 CLI·기록 경로는 유지했다.
4. CSV의 Git 줄바꿈 정규화와 로컬 해시 불일치를 발견해 LF로 맞추고 학습 전에 manifest 해시를 다시 고정했다. 원본 CSV 바이트와 기존 평가 분할은 변경하지 않았다.
5. 고정 pretrained revision에서 1회·3epoch를 실행했다. 48.29초, validation 최고인 1epoch를 복원했다. 저장 전후 validation 4문항 예측 일치를 확인했다.
6. 후보 고정 후 기존 validation/test와 회귀·새 평가·표현 비교를 실행했다. 회귀 40/48, 새 평가 29/30, 표현 24/24. 회귀 정답 수와 CLARIFY 기준 미달, 업무 무관 질문과 기존 validation의 순수 조회 질문에서 퇴행하여 **서버 승격을 보류**했다.
7. 이후 추가 학습·epoch 재선정은 하지 않았다. 서비스 모델 경로·프로세스는 유지하고 실제 생성 호출은 0회다. 사용자 환경 수정은 새 프로세스에서 키 존재 여부만 확인했다.

[전체 비교·문항별 예측·원자료](../../classification/reports/2026-10-15-routing-augmentation/README.md)에서 수치의 기준을 관리한다. 이 실험의 새 평가는 이제 노출된 개발 자료이며 다음 실험의 미열람 평가로 취급하지 않는다.
