# 프롬프트 강화 적용과 두 모델 재비교

2026-10-15. 사용자가 [후속 검토안](2026-10-15-generation-prompt-followup.md)의 적용·재비교·일지 갱신을 AI에 위임했다. `generation/prompts.py`에 업무 적용 범위, 주체·순서·시간 시작점·목표/의무·예외 조건 보존, 기록/조회 권한과 문의/처리 메뉴 구분, 부분 답변과 유보 규칙을 적용했다. 역할·실행 미지원·문서 속 지시 무시·한국어·JSON 계약은 유지한다.

## 실험 설계와 검증

전체71문서 snapshot을 고정했다. 기존 급여계좌/VPN/거래처 지급/영수증/보안신고5문항에 경비 제출 기한·메뉴, 두 신고 경로 모두 불가, 최초MFA·동료계정 금지3문항을 추가했다.8문항 × baseline/강화 ×2회 ×2모델=64회다. 신규3문항은 답이 있는 정상 사례의 과잉 유보 점검이며 미사용 holdout이 아니다.

Qwen은 기존 q4_0 KV·FA·96k·출력1024·temperature0·seed42, GPT는 기존 gpt-6-luna none·temperature0·출력1024 설정이다. 실험 순서는 baseline1→강화1→강화2→baseline2로 고정했다. 반복은 독립 질문이 아니며, 모든 변수를 엄격히 무작위화한 인과 실험도 아니다. 프롬프트 변경 시 입력 캐시가 달라져 전체시간 차이를 단순한 프롬프트 속도 효과로 해석하지 않는다.

baseline 첫5문항의 문서·prompt hash는 이전 GPT 실험과 실행 전에 일치 검사했다. 이번 문서·프롬프트 원본, 모델 설정, 실행 계획과 각 응답을 `tmp/generation-prompt-ab-20261015/`에 보존했다. 독립 검토자는 결과를 읽기 전에 원문 정책과8문항을 대조해 사전 rubric을 제시했다. 이후 AI 독립·통합 검토를 수행한다. 사람 품질 승인은 아니다.

강화 적용 후 생성 테스트149개, 전체 Ruff check,201파일 format check 통과. Qwen backend 로그에서 전체37/37 GPU층, FA 활성, KV3888MiB를 확인했다. 테스트 통과는 실제 답변 정확성과 별개다.

## GPT 결과

32회 모두 completed/stop. 호출 단위 사전 기준의 AI 판정은 baseline 통과11·실패5, 강화 통과11·실패3·불확실2다. 고유 질문은8개이므로16개 독립 표본의 정확도로 해석하지 않는다.

- 거래처 지급(RQ0006): baseline2회 모두 개인 경비의 신청번호 문의 절차를 전용했다. 강화2회 모두 이를 제거하고 일반 재무 문의와 실제 처리 경로를 구분했다.
- 보안 신고(RQ0009): baseline/강화 모두2회 실패. 강화는 구체 화면 미확인을 쓰면서도 앞에서 “신고 기록에서 확인하도록 되어 있다” 등 조회 가능성을 여전히 추정했다. 기록의 주어는 담당자이며 신고자 조회 경로는 명시되지 않았다.
- 영수증(RQ0007): 각 조건의 첫 반복에서 “제출한 뒤 대체 증빙 문의”라는 미명시 순서를 추가했다. 두 번째 반복은 이 오류 없이 핵심을 안내했다. 기존 검토보다 추가한 선후관계까지 엄격히 평가했으므로 과거 평가 숫자와 단순 비교하지 않는다.
- 강화 VPN 반복2는 존재 미확인 신청번호 전달을 제안했고, 강화 비상연락 반복1은 카드 분실의 재배부 대신 무응답 시의 대체 인계를 연결했다. 일반 문의 조언으로 읽을 여지도 있어 두 건은 불확실로 보존하며 통과에 넣지 않는다.
- 정상3문항×2회에서 과잉 유보는 양 조건 모두0/6. 이는 추가 문장의 사실성까지 모두 통과했다는 뜻이 아니다.

전체 통과 수는 늘지 않았고 특정 업무 범위 오류만 줄었다. 강화 후 GPT 전체 답변 품질이 입증됐다고 결론내리지 않는다. 자세한 판정은 로컬 `gpt-quality-review.md`와 원응답에 보존한다.

## Qwen 결과

32회 모두 completed/stop. baseline 통과6·부분 충족2·실패8, 강화 통과4·실패12였다. 조건별 반복에서 RQ0001을 제외한7문항은 응답 문자열도 같았다.

- 급여계좌: 강화에서 메뉴·마감 미확인 안내는 생겼지만, 퇴사 정산의 People팀 책임을 일반화하거나 구매·경비 경로를 후보로 제시하는 오류가 남았다.
- 거래처 지급: baseline의 직접 변경 불가 누락에서, 강화의 허구 `인사 > 문의` 메뉴와 People·팀장 담당 추가로 악화됐다.
- 영수증: 강화가 가짜 반려 메시지, 금액 차이 작성 의무, 휴가·이동·고객대응 기록을 허용 증빙으로 제시하고 보안 담당자 검토까지 추가했다. 재무팀의 대체 증빙 안내와 다르다.
- 보안 신고: 강화가15분 인수 목표를 기록 완료 의무로 바꾸고 반려·보완·고객 안내를 섞었다.
- 정상 경비 제출(POS01): 기본 기한·메뉴는 맞았지만, 강화에서 기한후 재무팀 연장 승인이라는 추가 문장이 생겼다. 원문은 기한전 연장과 기한후 팀장·재무팀 예외 승인을 구분한다.
- 정상 MFA(POS03): 양 조건 모두 첫 로그인 때 등록을 첫 로그인 전에 등록으로 바꿨다. 질문에 들어 있는 잘못된 전제를 교정하지 못한 사례다.

정상3문항×2회 과잉유보는 양 조건 모두0/6이지만, 정상문항 통과는4/6→2/6으로 줄었다. 즉 문제는 답변 거부가 아니라 추가한 정책의 왜곡이었다. 자세한 판정은 로컬 `qwen-quality-review.md`와 원응답을 따른다.

각 행은8문항의2회 반복16응답이다. 모두64회 구조상 정상 완료였으며 이 표는 사전 기준에 따른 소수 사례 AI 판정이다. 두 불확실은 임의 통과 처리하지 않았다. 모든 문항에 대한 통계적 우월성이나 서비스 품질 보장은 아니다.

**강화 후보는 실제 적용해 비교했지만, 최종 공통 기본 프롬프트는 baseline으로 원복했다.** Qwen의 회귀와 GPT 전체 통과 수 미개선 때문에 공통 채택 근거가 부족하다. 원복 전 현재 파일이 실험 후보와 정확히 같은지 검사하여 동시 변경을 덮어쓰지 않았다. 후보는 `tmp/generation-prompt-ab-20261015/prompt-strengthened.py`에 보존하고 기존값은 `prompt-baseline.py`에 보존한다. 모델별 운영 프롬프트 분기나 서버 연결은 새로 구현하지 않았다.

다음 실험은 규칙을 더 길게 추가하기보다 짧은 대조 예시로 기록 주체와 조회 권한, 문서가 정하지 않은 선후관계·허용 증빙을 구분하는 방향을 권한다. 규칙만/규칙+예시 효과를 분리하고 정상 질문의 추가 오류도 검사한다. 필요하면 근거 문장·적용 대상·조건 추출과 최종 답변을 나누는 후보를 별도 비교한다. 이번 관측만으로 그 후보의 성공을 보장하지 않는다. 실제 정책이 없는 메뉴·마감·권한은 담당자 확인 후 원문과 평가 기대값을 함께 갱신한다.

## 실행 지표와 산출물

전체 호출 평균은 GPT 기존2.48초/강화2.42초, Qwen 기존16.62초/강화18.16초다. 평균 출력토큰은 GPT103.1→133.9, Qwen195.8→236.3이었다. 긴 입력 최초 처리·캐시·출력 길이 영향을 포함하므로 프롬프트의 순수 TPS 인과 효과로 해석하지 않는다. GPT 총32회 약78.44초, Qwen 총32회 약556.59초이며 병렬 실행으로 합계가 벽시계 시간과 같지 않다.

로컬 `tmp/generation-prompt-ab-20261015/`에 `run.py`, 모델별 manifest/runs/progress, `documents.jsonl`, 두 prompt 원본, `rubric.md`, 모델별 quality-review 및 comparison, `summary.json`, 테스트·Ollama 로그를 저장했다. 생성 테스트149개와 전체 Ruff 검사·형식 검사, 관련 상대 링크44개를 확인했다. 이번 별도11435 서버의 모델을 내리고 프로세스를 종료했으며 GPU0MiB 반환을 확인했다. 시스템11434는 건드리지 않았다.

원복 후 프롬프트 경계4개 테스트도 통과했다. [Notion 개인 일지](https://www.notion.so/3f905a3cdadc8146a9bbedb690ab5ecf)의 현재 다음 단계·64회 결과·원복 판단·요약 속성을 갱신하고 재조회하여 저장을 확인했다. 이전 게시 기록과 진행 중 상태는 유지했다. 이번 추가 기록은 아직 커밋·푸시하지 않았다.
