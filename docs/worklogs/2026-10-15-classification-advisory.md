# 분류 라벨 보조 전달 구현·평가 기록

## 결과와 범위

요청한 조건부 평가를 수행하고 탐색 단계에서 미채택으로 종료했다. [평가 보고서](../../generation_evaluation/reports/2026-10-15-classification-advisory/README.md)가 결과·원응답·판정의 기준 위치다. 64회, 보수 비용 $0.96850775. A/B/C 안정 통과 7/8·6/8·6/8. 확인 120회·API 통합·기본값 전환은 조건 미충족으로 미착수다. 현재 shadow와 v5를 유지한다.

## 변경과 기여

사용자가 실험 범위·예산·채택 기준을 승인했고 AI가 순수 프롬프트 조합, 타입 context, 평가 실행기, 합성 문항, 테스트, 의미 판정과 문서를 작성했다. 모든 라벨의 system은 같으며 enum만 다르다. 분류 실패/client/없음은 원본 객체로 복귀한다. 답변기 연결은 채택 조건 미달로 구현하지 않았다. AI 판정은 비독립·비블라인드이며 사람 승인으로 기록하지 않는다.

기준 main 389e936, 구현 56099f5. 원래 사용자 폴더를 수정하지 않고 별도 worktree에서 작업했다. 사용자 파일 해시·690개 기존 테스트 ID·채택 프롬프트 및 설정을 tmp에 기록했다. 실제 저장 분류기로 28문항 예측을 고정했다. 모델 파일 해시·예측·문항·문서·메시지·코드는 manifest에 보존했다. 첫 호출 전 포맷 변경을 반영한 재고정은 이전 manifest를 로컬에 남겼으며 예측 재생성은 없었다.

## 검증

- RED: 조합을 생략한 stub에서 null 대조군 검사가 실패하는 것을 확인한 뒤 구현해 GREEN 확인.
- 신규 모의 검사 13개: 라벨별 공통 지침·정확한 fallback·잘못된 enum·동시 context 분리, 예산·실패 상태·미확정 예약·동일 코드 resume·helper 해시 변경 거부·확인 진입 조건·판정 해시.
- 변경 전 전체 690개 통과, 구현 후 703개 통과. 기존 ID 손실 0, 신규 13개. 초기화한 임시 SQLite 사용.
- 실제 생성 64회: 원응답과 근거 대조 완료. timeout/refusal/truncation은 모의 검증, 실제 parse_error 1회도 재시도 없이 보존.
- 기존 전체 테스트의 작은 합성 모델 fixture 학습은 실행했다. 서비스 모델 재학습·운영 DB 접근·공개 서버 재시작은 하지 않았다.
- 최신 main의 v6 실험·프런트 변경을 평가 종료 후 통합했다. 과거 실험 manifest는 새 코드에 맞춰 고치지 않았다.

## 게시와 후속 상태

전용 브랜치 `feat/classification-advisory-20261015`에서 구현 → 평가 결과 → 현재 안내를 구분해 게시한다. main push의 자동 배포를 피하기 위해 게시 tip에 `[skip ci]`를 사용하며 로컬 검증 결과와 CI 미실행을 구분한다. Notion은 원격 게시 후 프로젝트 문서 안내·서비스 처리 기준·라벨 기준·기존 생성/분류 일지에 결과를 덧붙이고 저장 내용을 재조회한다. 최종 통합 검사·게시·Notion 확인 결과는 아래 후속 항목에 기록한다.
