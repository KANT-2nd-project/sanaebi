# 문서 전체 삭제·기본 문서 복원

## 사용자 결정과 구현

사용자가 공개 시연 기능으로 두 작업을 제공하고 관리자 키를 추가하지 않기로 결정했다. 전체 삭제는 새 백업 없이 수행하고, 기본 복원은 기존 초기화와 같이 백업 후 수행한다. AI가 서버·화면·회귀 테스트·문서 작성과 게시를 수행했다. 사용자 독립 구현이나 사람 검수 완료를 의미하지 않는다.

- 목록의 문서 전체 관리 구역에서 정확한 확인 문구를 입력해야 실행한다. 검색 결과가 아닌 전체 문서 수를 확인하며, 자정 예약 복원 가능성을 안내한다.
- 상태 확인 API와 UUID 멱등 키로 확인 이후 변경·중복 실행을 구분한다. 응답 유실에는 자동 재실행 없이 같은 요청을 수동 재확인한다.
- CLI·예약 초기화와 DB별 잠금·교체 코드를 공유한다. 자료·백업 실패는 적용 전에 중단하고 교체 중 실패는 롤백한다. 완료 후 manifest 기록만 실패한 경우에도 저장된 완료 결과를 재조회한다.
- schema v3는 작은 버전 하한 상태를 추가한다. 기존 데이터를 보존해 마이그레이션하고 삭제→복원 뒤 과거 버전 요청과 일반 쓰기 키가 다시 유효해지지 않도록 한다. 완료된 전체 관리 키는 남은 24시간 동안 결과 재확인용으로 남긴다.
- 원본 JSONL·기존 백업·모델·생성 사용량·실험 자료를 보존한다. 임베딩은 호출·삭제·초기화하지 않는다.

사용 방법·HTTP 계약은 [문서 관리 안내](../document-management.md#문서-전체-관리), 책임 분리는 [서버 규약](../server-conventions.md), 화면 안내는 [웹 README](../../web/README.md)에 둔다.

## 검증

초기 집중 테스트는 새 서비스 함수가 없어 실패한 것을 확인한 뒤 구현했다. 최종 집중 검사 27개는 빈 DB, 초안·게시본·중단·다중 개정 삭제, 기본 복원, 백업 유무·원본/기존 백업 보존, 상태 변경409, 동시 요청·예약 잠금, 오래된 버전·멱등 키, 롤백·마이그레이션·완료 이후 오류 재확인을 검증한다. 모든 DB 쓰기는 임시 디렉터리에서 실행했다.

- 전체 Python 회귀: 707개 통과.
- Ruff check·format check: 통과.
- 웹 단위 테스트: 83개 통과. lint·typecheck·정적 build 통과.
- Chromium 모의 API: 30개 조건 확인. 취소 우선 포커스·Esc·포커스 복원, 정확한 문구, 전체 건수, 처리 중 취소 차단, 응답 유실 뒤 동일 키/본문 재확인, 409 뒤 재확인, 성공 후 URL 조건 제거를 검사했다.
- 320·390·768·1440px에서 페이지·dialog 가로 넘침이 없고 캡처를 확인했다. 320×480px의 낮은 화면과 Tab·Shift+Tab 모달 포커스도 확인했다. 브라우저 콘솔 오류 2건은 의도한 요청 실패와409다.
- git diff --check 및 변경 문서의 상대 파일 링크 확인.

전체 회귀의 최초 실패 3건은 새 API 경로·schema 버전의 기존 기대값과 v1 마이그레이션 테스트 픽스처였다. 기대값을 새 계약으로 갱신하고 v1 픽스처에서 v3 관리 테이블도 제거해 실제 이전 스키마를 재현한 뒤 통과했다.

실제 사용자 DB 삭제·복원, 임베딩·실제 LLM 요청, 실기기·스크린리더 검증은 수행하지 않았다. 브라우저 쓰기 4회는 모두 모의 응답이며 서버 저장 보장은 임시 SQLite 검사로 확인했다. 자정 예약의 실제 시간 도달이나 이번 버전의 운영 배포 완료를 주장하지 않는다.

로컬 근거는 `tmp/document-maintenance-2026-10-15/`의 실행 로그·브라우저 스크립트·캡처에 보존한다. Git에는 코드·테스트·안내와 이 작업 기록만 게시한다.

일반 이관 CLI의 삭제 후 재생성 경로도 추가로 검사했다. 최초에는 버전2가 다시 사용되는 실패를 재현했고, 신규 문서 생성에도 버전 하한을 적용하고 이관 게시가 실제 버전을 사용하도록 수정해 통과했다.
