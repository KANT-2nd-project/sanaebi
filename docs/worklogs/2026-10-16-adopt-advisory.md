# 공통 지침과 분류 라벨 C의 후속 채택

## 결정과 적용 범위

사용자는 분류 결과를 생성에 참고시키는 프로젝트 의도를 근거로 C 채택과 구현·검증·커밋·푸시·Notion 갱신을 요청했다. **효과 기준 미충족 이후 사용자의 설계 결정으로 채택**한다. 과거 미채택 판단·원점수는 변경하지 않는다. AI가 구현·검증·기록을 수행했으며 사람의 문항별 품질 승인이나 독립 AI 검토로 표현하지 않는다.

기준 main은 `94bafaa47444ea87a50b54994288850c64ea33b6`, 작업 브랜치는 `feat/advisory-adoption-20261016`이다. 원본 작업 폴더의 로컬 실행·프런트 관련 미커밋 변경은 별도 worktree로 보존한다.

## 실제 계약

- 미설정 `SANAEBI_ROUTING_MODE`는 advisory. 명시적 shadow/gate는 유지한다.
- `/ask`의 정상 서버 모델 예측만 `ClassificationContext` keyword 인자로 질문 서비스 → 답변 어댑터 → 생성 함수에 전달한다. trace·전역 상태에서 라벨을 읽지 않는다.
- 평가에서 사용한 기존 `compose_advisory`를 그대로 사용한다. 모든 라벨에 같은 공통 지침과 의미 설명을 제공하고 값만 바꾼다. 라벨별 프롬프트·모델·검색 분기는 없다.
- 질문·문서를 우선한다. SEARCH는 근거 존재를 보장하지 않고 CLARIFY는 무조건 재질문하지 않으며 UNSUPPORTED는 전체 거절·일반 지식 허용을 뜻하지 않는다.
- 라벨 없음·알려진 분류 장애·`/assistant` client 라벨은 기존 프롬프트로 복귀한다. `/assistant`는 재분류하지 않으며 앞 단계 실패도 기존대로 종료한다. 미등록 라벨·예상 밖 오류는 기존 500 계약을 유지한다.
- KURE 검색·snapshot·근거 순서·근거 없음 생성 생략·HTTP 구조·모델·v5 프로필 본문·timeout·재시도·예산 예약·클라이언트 종료는 유지한다. CLI는 분류를 실행하지 않으므로 원본 프롬프트를 사용한다.

라벨 미전달 원복은 `SANAEBI_ROUTING_MODE=shadow`, 분류 사전 차단은 `gate` 지정 후 앱 재시작이다. 이번 작업에서 운영 서버·실제 DB·배포·재시작은 다루지 않는다. main 게시에는 자동 배포를 제외하는 `[skip ci]`를 사용한다.

첫 KURE 비교에는 팀장 회신 기한 누락과 C의 잘못된 오늘 날짜가 있었다. 다른 주제 비교의 개인정보 사고에서 증거 임의 삭제 금지 안내가 양쪽 모두 누락됐으며 해당 항목이 검색 발췌에 없었다. 마지막 해외 숙박 질문은 실행하지 않았다. JSON 실패·검색 누락·생성 누락은 해결됐다고 주장하지 않는다.

KURE 비교는 A와 공통 지침+라벨 C만 비교했으므로 라벨 자체의 독립 효과를 분리하지 못한다. 작은 합성 자료, AI 비독립·비블라인드 판정이며 통계적 우월성이나 실서비스 품질 보증이 아니다. 이번 채택 구현 중 추가 유료 호출은 0회다.

기존 공개 [전체 문서 보고서](../../generation_evaluation/reports/2026-10-15-classification-advisory/README.md)는 당시 기록으로 보존한다. KURE 원자료는 원본 작업 폴더의 `tmp/rag-label-minimal-20261016/kure-8cba784/`와 `kure-newcases-94bafaa/`에 있다. 이번 게시용 [KURE 결과 근거](../../generation_evaluation/reports/2026-10-16-advisory-adoption/README.md)에 공개 합성 응답·판정·요약을 보존한다. DB·인증 정보·tmp 전체는 게시하지 않는다.

검증 결과와 원격 게시·Notion 재조회 결과는 아래 후속 기록에 확정한다.

### 로컬 검증 완료

- 신규 서버 라벨 전달 테스트는 advisory 미지원 ValueError로 먼저 실패했고 구현 후 통과했다. trace의 advisory 누락도 실패를 확인한 뒤 허용 목록과 회귀 검사를 보완했다.
- 관련47개, 전체 Python976개 통과. 마지막 trace 허용 목록 변경 후 runtime314개 추가 통과. 임시 SQLite와 모의 생성 provider를 사용했다. 전체 검사에 포함된 작은 합성 학습 fixture는 서비스 분류 재학습과 다르다.
- 최초 전체 실행의3개 legacy CLI 실패는 재사용 가상환경이 삭제된 과거 editable 경로를 가리켜 발생했다. 원래 환경을 재설치하지 않고 `PYTHONPATH=$PWD`로 현재 소스 checkout을 지정해 해결했다. 별도 설치 환경 검증으로 주장하지 않는다. trace 테스트의 새 keyword 인자 미수용1개는 테스트 대역을 수정했다.
- Ruff check·format(568파일), `git diff --check`, 변경 문서 상대 링크·앵커296개 통과. 문서 제목을 유지했고 현재 안내의 역참조를 검색해 함께 갱신했다. 웹 코드 변경은 없으며 브라우저 검사는 하지 않았다.
- 변경 전후 OpenAPI 전체 동일: SHA-256 `a2c89fa4e042dfdb2b1d2bb3be13fbbca65bdc9fad68b16b1b4cc1e626c0d8fb`.

- full/rag의 기존 조합 함수 재사용, 무라벨/client/분류 실패의 정확한 원본 프롬프트 복귀, 세 라벨 동일 snapshot, 검색 입력 미변경, 무근거 생성/예약 생략, 동시 요청3개의 라벨 분리, 실제 API·어댑터·파서와 모의 provider를 확인했다. 실제 유료 생성·운영 DB 접근·공개 서버 재시작은 하지 않았다.
