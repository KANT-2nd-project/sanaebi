# JSON 출력 형식 고정과 자동 배포

## 원인과 결정

2026-10-21 `ssh sanaebi`로 운영 컨테이너의 생성 기록 47건을 확인했다. 성공42건·실패5건이며 실패는 모두 `parse_error`였다. 「휴가 절차에 대해 궁금해요」의 문서·분류·검색 입력을 다시 조립하니 오늘 실패와 재시도 성공의 프롬프트 해시가 일치했다. 같은 입력의 실제 추가 호출1회에서도 모델은 정상 종료했지만 JSON 첫 글자부터 파싱에 실패했다. 과거 실패 응답의 원문은 보관되지 않아 5건 각각의 세부 문법·키·타입 위반은 복원하지 않는다.

사용자는 strict 스키마 적용·검증·커밋·푸시·CI/CD 자동 배포와 운영 확인까지 요청했다. AI가 구현·실행·검증·기록하며 사람의 문항별 품질 승인이나 사용자 독립 구현으로 표현하지 않는다.

## 변경과 계약

활성 Luna 설정만 `strict_json_schema`로 전환한다. 기존 SDK 어댑터와 `answer` 문자열 한 키의 스키마를 재사용한다. 서버·CLI·평가기는 같은 모델 설정을 읽고, 구형 설정과 `GenerationConfig`의 `prompt_json` 기본 해석은 보존한다. 모델·프로필 본문·검색·xhigh·16384토큰·180초·temperature 생략·생성 한도는 유지한다.

공개 `{ok,text,reason}` 응답과 거절·잘림·timeout 구분, 실패의 안전한502 안내는 유지한다. 자동 재시도나 일반 모드 fallback은 추가하지 않는다. 운영 문서·색인은 읽기 전용으로 검증하며 초기화하지 않는다.

## 검증·게시·배포 상태

기존 설정에서 활성 프리셋의 strict 전송 회귀 테스트가 실패하는 것을 먼저 확인했다. 설정 변경 후 실제 프리셋의 요청 스키마·Markdown 줄바꿈·거절·잘림·provider 장애·예산 예약1회·클라이언트 종료를 검증한다.

전체 Python·Ruff, 실제 모델6회, PR CI와 main 자동 배포·공개 API3회·Notion 저장 후 재조회 결과는 실행이 끝난 항목만 아래에 기록한다. 배포 후 기록 전용 커밋은 `[skip ci]`로 게시하며 기능 배포 SHA와 구분한다.

### 과거 실험의 호환 경계

최초 전체 회귀에서 과거 고정 실험을 활성 설정으로 검사하던 fixture가 실패했다. 과거 실행기의 설정 변경 차단은 그대로 두고 해당 테스트에만 당시 `prompt_json` 설정을 주입했다. 현재 strict 설정으로 과거 실험을 실행하면 여전히 사전 거부함을 별도 회귀로 확인한다. 과거 보고서·평가 결과·manifest와 실행기는 수정하지 않았다.
