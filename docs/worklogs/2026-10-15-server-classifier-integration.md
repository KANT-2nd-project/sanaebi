# 서버 분류기 연결과 질문 서비스 활성화 — 2026-10-15

## 결정·구현

사용자가 KoELECTRA base 채택 후 재사용 가능한 분류기와 서버 규약 적용을 요청했다. 추가 결정은 `/ask`의 목표 라벨 정책 적용, 기존 LangChain 유지다. AI가 구현·테스트·문서 반영을 수행했다. 별도 생성 모듈 변경, 학습·실험 원자료·가중치·비밀키는 보존했다.

- `360aabb`: 경로 주입 가능한 Transformer 추론기, 새 metadata 검증, 라벨 매핑, CPU·로컬 전용 로딩, 앱에서 재사용할 잠금 기반 추론, 과거 단독 호출 호환 함수.
- `7eba06b`: 앱별 객체·Depends 조립, 질문 서비스·snapshot·답변 어댑터 연결. CLARIFY·UNSUPPORTED는 문서·LLM 미호출, 검색 문서가 없으면 정상 안내. 기존 `/assistant`는 유지.
- HTTP URL·필드는 보존하고 모델 형식·추론 실패를 안전한 503으로 처리했다. 분류 모델 부재 문구는 `분류 모델을 사용할 수 없습니다.`로 통일했다. 문서 503·생성 502·입력 422를 유지했다.

현재 동작·설정·내부 계약은 [서버 규약](../server-conventions.md), 선정 근거는 [7종 보고서](../../classification/reports/2026-10-15-seven-model-comparison/README.md)가 기준이다. 기존 [선정 시점 기록](2026-10-15-classifier-selection.md)의 연결 미완료는 당시 상태다.

## 검증 근거

- 먼저 비검색 `/ask`에서 생성기를 호출하지 않는 테스트를 작성했다. 기존 코드에서는 CLARIFY가 생성기를 1회 호출해 예상대로 실패했다. 수정 후 같은 계약이 통과했다.
- 단위·API 검증: 세 라벨, 빈 snapshot, DB 장애, snapshot 동일 객체 전달, 경로 교체, 저장 라벨 순서, 잘못된 metadata·매핑, 로컬 전용 로딩, 병렬 요청의 단일 초기화, 추론 실패, 공통 분류 의존성과 오류 응답.
- 선정본 model_id `9f51682d82d4455d8296077c339afd58`: 저장 validation 133건과 서버 추론 133건 모두 일치했다. 새 성능 실험이 아니라 연결 회귀 검사다.
- 실제 분류기 + 임시 DB + 모의 생성기로 `/classify/koelectra-base`·`/ask`를 세 라벨씩 총 6회 확인했다. snapshot과 모의 생성은 검색 라벨에서만 각각 1회, 실제 LLM 요청은 0회다.
- 원자료: 로컬 `tmp/server-classifier-integration-2026-10-15/verification.log`, `tests.log`. 이 경로는 공개 다운로드 링크가 아니다.

## 상태와 남은 범위

**선정 checkpoint 서버 연결 검증 완료**다. CPU 환경이며 모델 로딩·추론을 직렬화한다. worker별 가중치 메모리가 별도 필요하고 교체 후 재시작해야 한다. 실제 LLM을 포함한 종단 답변 품질·실사용 정확도·동시 부하·GPU 최적화는 이번 검증 범위가 아니다. 합성 개발 test를 독립 최종 평가로 표현하지 않는다.

문서·Notion의 기존 과거 기록은 보존하고 이번 결과를 후속 기록으로 연결한다. 다른 작업의 담당·기한·상태는 변경하지 않는다.
