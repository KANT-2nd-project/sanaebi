# 사용자용 말투·지원 범위 안내 보완

## 요청과 계기

사용자는 채팅에서 '연봉 정보'에 '제공된 문서에는…', '뭘 도와줄 수 있어?'에 '확인되지 않는 내용은 확인할 수 없다고 안내하겠습니다'라는 답변을 보고 내부 작성 규칙이 사용자에게 보이는 느낌을 지적했다. 이어 '세그먼트 트리에 대해 설명해줘'에 자료 부족 대신 이음웍스 서비스 범위를 알리도록 공식 레퍼런스 조사·독립 검토를 요청했다.

기준은 main 4d4c0f4다. 사용자가 앞서 직접 커밋한 .env 로딩 수정과 운영 DB·웹 변경을 보존한다. 모델·shadow 정책·출력16384·xhigh·180초·prompt_json을 유지하고 자동 재시도·fallback·학습·검색 도입은 하지 않는다. 서비스 프로세스를 직접 종료하거나 재시작하지 않는다. 개발 서버의 파일 감시가 변경을 감지하는 동작과 명시적 서버 재시작은 구분한다.

## 구현·비교 경위

v3 본문을 보존하고 사용자용 표현 규칙을 추가한 v4를9문항 각1회 v3와 비교했다. 총18회 모두 생성 정상 완료였고, 연봉·도움 범위 질문의 표현은 개선했다. 하지만 v4 사고 대응 응답은15분 인수 목표를15분 대기로 바꾸고 OR 경로를 AND로 바꾸었다. 독립 AI 검토자가 원문과 대조해 실패를 확인했다. 이 중간 후보는 채택하지 않는다.

추가 요청에 따라 별도 연구자가 Intercom·Google·AWS·Microsoft 공식 자료를 조사했고, 별도 reviewer가 프롬프트·고정 기준·원응답을 읽었다. v5는 작성 지침을 선언하던 few-shot 답변을 직접 답변으로 바꾸고, 서비스 범위/업무 맥락→근거 확인→직접 답변 순서와 시간·선택 조건 보존을 명시했다. 범위 안의 자료 부족, 범위 밖, 모호한 질문, 혼합 질문을 구분한다. 문서 제목·출처 설명 자체는 금지하지 않는다.

v5 기준13문항을 호출 전에 고정하고 각1회 실행했다. U01~U09는 알려진 비교 문항, U10은 사용자의 추가 사례, U11은 같은 기술어에 합성 사내 문서1개를 더한 사례, U12는 업무·범위 밖 혼합, U13은 모호한 대상이다. 미열람 평가나 일반 정확도라고 표현하지 않는다.

현재 게시71문서를 읽기 전용으로 한 번 snapshot으로 만들었다. 저장소 지식과 비교하면 ieum-068의 기존 게시 내용이 달라 이 파일로 재현해야 한다. 사용자 문서를 최신 파일로 덮어쓰지 않았다. U11 overlay는 평가 입력에만 추가하고 DB에는 쓰지 않았다. snapshot은 tmp/user-facing-v4-20261015/snapshot.json에 보존한다.

## 근거와 한계

[공식 레퍼런스와 적용 구분](../../generation_evaluation/reports/2026-10-15-user-facing-v5/references.md), [실행·후보별 결과](../../generation_evaluation/reports/2026-10-15-user-facing-v5/README.md), [독립 AI 검수](../../generation_evaluation/reports/2026-10-15-user-facing-v5/independent-review.md)에 상세 근거를 둔다. AI가 구현·실행·판정·조사·기록했으며 사용자 독립 구현 성취 또는 사람 검수로 기록하지 않는다.

실호출은 v3/v4 비교18회와 v5 검증13회, 합계31회다. 비용은 공식 Standard long-context 요율 상한의 보수 추정으로 합계 $0.45948775이며 청구서 금액이 아니다. HTTP·브라우저·실제 분류기 재검증은 아니며 공통 생성 경로와 frozen snapshot의 테스트다. 기본값 연결은 별도 mock 회귀로 검증한다. 작은 문항 수·각1회·비블라인드 AI 판정·기존 필수 안내 누락 등의 한계를 남긴다.

## 최종 연결·검증

v5를 DEFAULT_PROMPT_PROFILE과 company-final-v1 프리셋에 연결했다. 실제 검증한 system 원문과 기본값의 일치, 과거 v3 system 불변, 질문·문서 입력 보존, 두 CLI·서버 로더·평가기 프로필 일치를 검증했다. 관련22개와 전체 Python690개(51.497초), Ruff check·format 검사를 통과했다. 전체 테스트에는 격리된 기존 테스트용 문서DB를 지정했으며 실제 서비스 DB에는 쓰지 않았다. 실행 로그는 tmp/user-facing-v5-20261015/adoption-tests.log와 full-tests.log에 보존한다.

별도 독립AI검토 결과는 요청한 말투·범위13/13충족, 전체 품질11통과·2부분충족이다. U01의People팀 일반 연봉 담당 범위 확대와 U03의팀장 회신 기한 누락을 남긴다. 사용자 요청에 따른 UX 보완 채택이며 서비스 전체 승인·반복 안정성 확보로 표현하지 않는다.

작업 중 별도로 바뀐 docs/frontend-architecture.md와 web/app/globals.css는 이번 수정에 포함하지 않았다. 웹코드 변경·브라우저 재검증·명시적 서버 재시작은 하지 않았다. 이번 요청은 구현·검증·문서/Notion 기록이며 새 커밋·원격 푸시는 수행하지 않는다. 새 보고서가 원격 게시됐다고 주장하거나 아직 없는 원격 링크를 만들지 않는다.
