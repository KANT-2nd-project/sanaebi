# RAG 구현 게시와 검색 품질 단계별 개선

## 범위와 기여

사용자는 기존 RAG 구현과 세 개선안의 순차 비교, main 게시와 Notion 기록을 요청했다. AI가 구현·자료 작성·독립 AI 검토·실행·기록을 수행한다. 사람 검수나 사용자 독립 구현 성취로 표현하지 않는다.

기존 `/tmp/sanaebi-rag-implementation-20261015` 작업 공간을 사용했다. 중단된 로컬 가상환경은 작업 공간의 tmp에 보존했다가 용량 문제 확인 후 `/home/jake/.cache/sanaebi-rag-quality-20261015/interrupted-venv`로 옮기고 기존 환경을 연결했다. 원래 작업 공간의 미커밋 수정은 건드리지 않았다. 기존 RAG 검색·복원을 `00eb0ef`, 배포 지원을 `e65e463`, 문서·당시 로컬 검증을 `8cb702f`로 구분했다. 최신 main의 문서 전체 관리·웹·생성 실험 변경은 `3742efd`에 함께 보존했다. 문서 충돌은 독립된 추가 구역을 모두 유지했다.

실제 LLM API 호출·운영 전환은 제외한다. `full` 기본값과 현재 생성 설정을 유지한다. main 자동 배포가 활성화되어 있으므로 사용자 결정에 따라 최종 main 병합에 `[skip ci]`를 사용하며 자동 배포 설정은 바꾸지 않는다.

## 실험 기준

기존18문항·신규개발20문항·최종확인20문항·답변불가10문항을 모델 실행 전에 검수·동결했다. 질문의 장소·기한·예외가 빠진 qrel, 공유드라이브와 개인 휴지통 혼동, 최종확인의 유사 질문을 독립 검토 지적에 따라 수정했다. 과거18개 문자열 정답은 그대로 보존했다.

주 지표는 필요한 원문 구간의 완전 포함이다. 개발20문항의 성공 수가 증가하고 기존38문항의 성공을 모두 보존한 후보만 다음 단계의 기준으로 삼는다. 세 방법은 모두 실행하며, 직전 후보가 탈락해도 직전 채택 구성에서 다음 방법을 평가한다. 최종확인 자료를 보고 튜닝하지 않는다.

[고정 절차·질문·결과](../../retrieval/reports/2026-10-15-rag-quality-improvement/README.md)에 실행 근거를 모은다. 최종 결과와 게시 확인은 아래에 기록한다.
