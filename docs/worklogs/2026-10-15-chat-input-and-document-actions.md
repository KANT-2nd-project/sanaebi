# 채팅 전송·대기 입력 개선과 문서 관리 버튼 정리

## 결정과 구현

사용자가 문서 작업 버튼을 한곳에 모으고 크기를 줄이도록 요청했다. 채팅에서는 전송 즉시 입력 초기화, 대기 상태 표시, 대기 중 다음 질문 작성 허용과 실패 시 새 초안 보호를 결정했다. AI가 구현·모의 브라우저 검사·회귀 테스트·문서 작성과 게시를 수행했다. 사용자 독립 구현이나 사람 검수 완료를 의미하지 않는다.

- 문서 제목 아래에 새 문서 초안·기본 문서 복원·모든 문서 삭제를 함께 배치했다. 복원은 보조, 삭제는 위험 테두리로 구분하며 모바일은 두 행으로 배치한다.
- 문서 버튼은 기본 높이36px·글자13px·좌우10px 여백, 터치 포인터에서는 높이44px다. 채팅 복귀 링크는 상단에 화살표와 보조 테두리로 표시한다.
- 채팅 전송 시 입력과 보존 초안을 즉시 비우고 요청 하나만 허용한다. 대기 중 다음 질문을 작성할 수 있지만 버튼·Enter·폼·재시도 전송은 차단하고 자동 예약 전송하지 않는다.
- 실패 시 이번 요청에서 입력을 비웠고 현재 입력이 정확히 빈 문자열일 때만 원문을 복원한다. 새 초안·공백·줄바꿈을 덮어쓰지 않는다. 새 초안에는 이전422 입력 오류와 강제 포커스를 적용하지 않는다.
- 성공 후 다음 초안을 유지하고 명시적으로 전송해야 새 턴을 만든다. 이동 후 대기 중 작성한 초안은 복원하지만 전송한 질문 자체는 복원하지 않는다. 취소된 요청의 늦은 응답은 무시한다.

사용 방법은 [웹 안내](../../web/README.md), 상태 정책은 [프런트엔드 설계](../frontend-architecture.md), 전체 문서 작업은 [문서 관리](../document-management.md#문서-전체-관리)를 따른다. 서버 API·모델·동시 요청 제한은 이번 변경에서 수정하지 않았다.

## 검증 근거

입력이 대기 중 남는 현상은 재현했다. 기존 코드에서도 disabled와 active 가드가 있어 Enter·폼 반복 제출은 요청1회였다. 버튼의 대기 문구를 명확하게 바꿨다. '대기 중 입력 비우기', 후속 '대기 중 새 초안 편집'은 각각 실패하는 회귀 테스트를 먼저 확인했다.

- 최종 웹119개·lint·typecheck·정적 build·git diff --check 통과.
- 문서 버튼 브라우저36개 조건: 320/390/520/521/768/1440px 배치·36px 높이·가로 넘침·삭제 확인·포커스 복원·미저장 이동 보호·터치44px 확인.
- 전송 초기화 브라우저49개 조건: 지연·422/429/502/503·네트워크 실패·중복 전송·재시도·이동 및 모바일 검사. 이 단계의 읽기 전용 정책은 다음 단계에서 변경했다.
- 최종 대기 중 작성 브라우저22개 조건: 편집·실제 clipboard 붙여넣기·줄바꿈·합성 IME·중복 차단·성공 후 명시적 전송·422 오류/포커스·실패 복원·공백 보존·이동 초안·터치 입력.
- timeout은 테스트용10ms와 모의 fetch로 중단·복원을 확인했다. 실제 브라우저 대기 한도240초는 변경하지 않았다.

근거는 로컬 `tmp/document-maintenance-2026-10-15/toolbar-*` 및 `tmp/chat-submit-review-2026-10-15/`에 보존한다. 최종 상태는 editable-* 로그와 캡처를 따른다. 실기기·실제 한글 키보드·스크린리더·운영 배포는 미검증이다. 모든 브라우저 API를 대체했으며 실제 LLM·문서 쓰기는 호출하지 않았다.

## 게시 범위

문서 버튼·채팅 입력·문서 기록을 기능별로 나눈다. 원격의 병행 RAG 변경은 별도 게시 작업 트리에서 보존해 합치고 현재 작업 폴더의 서버 미커밋 변경은 제외한다. 원본 데이터·가중치·실험 자료·환경 파일은 게시하지 않는다. 새 개인 일지에는 사용자 결정과 AI 수행을 구분한다.

## 게시·일지 확인

문서 버튼 `3c60682`, 채팅 `af98b6c`, 문서 `603256e`를 기능별 커밋으로 만들고, 별도 게시 작업 트리에서 원격 RAG main과 통합한 `5f949f3`을 게시했다. 통합 작업 트리에서도 웹119개·lint·typecheck·build를 재실행해 통과했고 게시 링크 HTTP200과 원격 SHA를 확인했다.

Notion 프로젝트 문서 안내·운영 개발 규칙의 현재 정책 요약을 갱신하고 링크와 본문을 재조회했다. 중복 제목 조회 후 [개인 일지](https://www.notion.so/3fa05a3cdadc81a68112c125ca7c35a4)를 생성하고 최재선·포털·로그인·저장·2026-10-15·완료 및 본문·산출물 링크를 확인했다.

현재 원래 작업 폴더의 서버 수정2파일은 원격 RAG 변경과 겹치므로 자동 덮어쓰기나 재적용을 하지 않았다. 해당 폴더의 main은 기능 커밋까지 유지하며, 원격 통합은 게시용 작업 트리에서 완료했다. 후속 서버 작업에서 원격과 합칠 때 별도 조정이 필요하다.
