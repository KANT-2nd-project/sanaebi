# 초기화 공통 처리·QA 정정·운영 검증 — 2026-10-16

## 판정 정정과 작업 범위

이전 `tmp/server-rag-stability-qa-2026-10-16` QA의 ‘로컬 예약 초기화가 RAG 잠금·색인을 우회한다’는 결함 판정을 철회한다. 당시 재현은 `app.documents.reset.reset_demo_documents`라는 하위 저장소 함수를 직접 호출했고 실제 CLI를 호출하지 않았다. 기준 커밋 `38d2f4c`의 일반 초기화 CLI에는 이미 RAG writer lock·잠금 안 재검증·새 revision 벡터 연결이 있었다. 실제 CLI 재확인에서 잠금 시 문서가 변하지 않았고 정상 실행 후 ready=true였다. 원본 재현 코드·로그와 당시 보고서는 보존하고 정정 이력을 덧붙였다. 독립 AI 검토도 같은 잘못된 재현 범위를 승인했던 한계가 있다.

이번 변경은 없는 결함을 새로 고쳤다는 주장이 아니라, 두 실제 CLI의 중복 처리 통합·명시적 원본과 기본 묶음 경로 일치·서버와 로컬 예약 환경 정렬·진입점 회귀 검증이다. 사용자가 범위·구현·게시·배포를 승인했고 AI가 구현·실행·별도 AI 검토·기록을 수행했다. 사용자의 독립 학습 실적으로 기록하지 않는다.

## 구현과 복구 계약

- `app.retrieval.reset.reset_with_retrieval`: 원본/묶음 확인 → writer lock → 재확인 → 기존 백업/문서 초기화 → 최신 게시 revision에 벡터 연결 → ready 확인. 모델 다운로드·추론 없음.
- 일반 CLI의 rag `--apply`와 전용 CLI가 공통 함수를 호출한다. full·dry-run·`--check`와 기존 인자/종료 코드/결과 필드는 유지한다. `restored_count`·준비 상태 및 부분 실패의 `recovery_environment`는 추가 정보다.
- 일반 CLI에서 명시한 `--source`로 기본 묶음 경로도 계산한다. 원본 기본값은 full/rag 모두 `SANAEBI_RETRIEVAL_SOURCE`를 사용하고 미설정이면 기존 기본 JSONL을 사용한다. 독립 AI 검토에서 발견한 full 모드의 사용자 지정 원본 무시 문제를 이 경로와 실제 본문 검사로 수정했다. 명시적 묶음 불일치는 문서 변경 전에 거부한다.
- 문서 변경 후 색인 실패는 `documents_reset=true`, `retrieval_ready=false`, 비정상 종료다. 출력에 기록한 source/DB/root/bundle 환경으로 `scripts.index_documents --restore-baseline`만 실행한다. 문서 초기화를 자동 반복하지 않는다.
- 로컬 systemd 템플릿은 절대 실행 계정·프로젝트·uv·서버 환경 파일을 지정하고 `uv run --no-sync --env-file`을 사용한다. 실행 중 의존성 설치·자동 재시도·로컬 타이머 활성화 없음.
- 하위 DB 함수와 HTTP 멱등성·초안/게시·중단 이력 계약은 변경하지 않았다. 공개 API·생성 설정도 유지했다.
