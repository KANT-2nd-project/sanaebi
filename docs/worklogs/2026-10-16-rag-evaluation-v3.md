# RAG 평가 기준 보완·검색 최적화와 기본 모드 확인

사용자는 평가 기준을 먼저 보완하고, 필수 근거 손실 없이 문맥을 줄이는 후보를 비교한 뒤 한 구성만 활성화하도록 결정했다. AI가 구현·실험·독립 AI 검토·문서 작성을 수행했다. 사용자 독립 구현 성취나 사람 검수로 기록하지 않는다.

## 결과와 판단

[정식 보고서](../../retrieval/reports/2026-10-15-retrieval-v3/README.md)가 비교와 선정의 기준 위치다. qrel v2·과거 응답·점수는 보존하고 v3와 정정 사유를 추가했다. 과거 A/B/C는 v3에서 모두37/38이다.

인접 확장 top12는 개발38/38·평균4,554자로 C37/38·25,766자보다 근거 포함과 전달량이 나았다. CPU2 동시1/2 warm p95도37/70ms 수준으로 기준을 통과했다. 그러나 신규 확인에서34/35로 C35/35의 V14를 잃어 채택을 보류했다. BGE는 공통40쌍 재정렬 단계가3초 조건을 초과해 제외했다. 상세 관련도·순위·원점수는 보고서에 둔다.

서버는 C 하나를 유지한다. rag 기본값은 선행 PR #11에서 이미 적용됐으므로 이번에 새로 바꿨다고 기록하지 않는다. 명시적 full 복구·과거 릴리스·환경변수 우선·생성 설정을 유지한다. 새 색인·자정 벡터를 만들지 않았다. 코드 기본값과 운영 활성화는 별개다.

## 검증과 보존

전체 Python911개, Ruff check·format534파일, 실제Tiny48문항 서버/실험 근거 일치와 실제Tiny·모의 생성 HTTP를 확인했다. [검증 범위](../../retrieval/reports/2026-10-15-retrieval-v3/verification.md), [독립 검토·수정](../../retrieval/reports/2026-10-15-retrieval-v3/code-review.md).

판정 초안에서 질문·청크 ID 연결 오류와 다른 조건의 절차를 직접 근거로 과대평가한 사례를 발견했다. 원본 초안을 보존하고 명시적ID 재검수·읽기 전용 추가 검토로 수정했다. 모든 관련도 판정이 사람 정답인 것은 아니며 낮은 등급의 추가 검토 범위도 별도로 기록했다.

기존 미게시 범위를 확인한 결과 이전 인자·문맥 실험과 C 기본값은 이미 PR #11로 게시돼 있었다. 중복 게시하지 않고 당시 tmp 원인 진단을 원본 SHA와 함께 정식 보고서에 보존했다. 모델·DB·가상환경·실제 환경 파일·tmp 전체는 커밋 대상에서 제외한다.

별도 작업 공간 `feat/rag-evaluation-v3-20261015`에서 진행했다. 원래 작업 폴더와 다른 변경은 보존했다. 유료 API·답변 생성 평가·자동 질문 재작성·운영 접속·배포는 하지 않았다. 실제 운영2vCPU·사람 검수·운영 전환은 후속이다.
