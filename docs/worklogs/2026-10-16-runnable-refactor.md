# RAG Runnable 구조 개선

2026-10-16. 사용자 승인 계획에 따른 로컬 구현이며 커밋·푸시·Notion 게시·운영 배포는 수행하지 않았다.

핵심 질문·생성 흐름을 명명된 Runnable로 연결했다. 공통 AnswerInput으로 full/rag 조립을 통합하고 검색·색인·baseline·점수 선택 책임을 분리했다. 청크 설정 실제 적용, KURE 정책의 잘못된 Tiny fallback, 중복 색인 읽기, trace 상태 누락과 전체 snapshot 기록 범위를 수정했다. strict JSON은 공개 SDK adapter를 사용한다. 기본 RAG/KURE/advisory/v5/prompt_json, 공개 HTTP 계약, 예산·취소·잠금 경계는 유지한다.

다른 세션의 후보 RAG 프로필 작업과 동시 편집이 발생하여 사용자 확인 후 공유 파일 편집을 조율했다. 정확한 인계 원문을 복원하고 후보의 명시 선택 경로를 보존했다. 기본값 채택이나 근거 확장 활성화, 해당 실험 재개는 하지 않았다.

고정 5문항의 전후 실제 생성은 10/10 성공했고 라벨·검색 근거/점수/span·system/user hash가 모두 일치했다. 별도 로컬 모델 시험에서 순차/동시/게시 병행과 취소 후 worker 종료까지 slot 유지도 확인했다. 작은 표본이므로 품질 향상·운영 성능 근거로 일반화하지 않는다.

초기 회귀 테스트의 오래된 patch 위치로 `test-key` 인증 실패 요청 2건이 추가 발생했다. 실제 키는 사용하지 않았고 두 요청 모두 401로 종료됐으며 재시도하지 않았다. patch 위치를 수정해 재검증했다. 계획된 스모크 10회와 이 예외 2회를 분리해 기록하며 총 외부 요청 10회 이하를 달성했다고 주장하지 않는다.

구현 반영표, 전후 원자료, 호출 ledger, 회귀 로그는 Git 제외 `tmp/rag-architecture-review-20261016/implementation/`에 보존한다. 원격 게시 증거로 사용하지 않는다. 구조 기준은 [서버 규약](../server-conventions.md#runnable-조립과-내부-입력), 실행 계약은 [RAG 실행](../rag-runtime.md#검색-실행과-색인-책임)과 [생성 실행](../generation-runtime.md#생성-체인과-제공자-경계)을 따른다.

최종 전체 Python 테스트 1,040개(79.494초), Ruff check, format check 599파일, diff 검사와 변경 문서 상대 파일 링크 확인을 통과했다. 독립 리뷰의 strict 입력 변환·검색 정책 ID·trace metadata·평가 예산 프롬프트 지적을 수정했고 미해결 중대 지적은 없다. 원격 main과 로컬 HEAD는 최종 조회 시 `2e3866ebc4d6d85392a59ff5e098a581e92212a7`로 같았으며 이 구현은 미커밋 변경이다.

## 후속 커밋·푸시 범위

사용자가 커밋·푸시를 추가 요청했다. main 푸시가 자동 배포를 시작하므로 `refactor/rag-runnable-20261016` 브랜치로 게시한다. 원격 기준 `2e3866e`의 별도 작업트리에 구현·필수 후보 호환 코드 59파일만 모았다. 다른 세션의 CI 커밋·근거 확장 모듈·실험 보고서·로컬 실행 작업일지는 포함하지 않는다. 원본 작업트리와 해당 변경은 보존한다.

게시할 파일만 포함한 격리 작업트리에서 전체 1033개 테스트(81.470초), Ruff check·format 595파일, staged diff 검사를 통과했다. 제외된 다른 작업의 테스트 때문에 공유 작업트리의 1,040개와 개수가 다르다.
