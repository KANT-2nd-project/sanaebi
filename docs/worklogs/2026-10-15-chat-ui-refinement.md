# 채팅 UI·UX 정리와 문서 이동 확인 — 2026-10-15

## 사용자 결정과 적용

사용자는 `/chat`의 버튼 크기·헤더 정렬·모서리 규칙과 문서 등록 배치를 검토하도록 요청했다. 독립 검수 후 질문 전송 중심 정리와 문서 관리 이동 전 확인을 채택하고 AI에 구현·검증·게시·기록을 위임했다. 사용자의 독립 구현·숙달이나 사람 품질 승인을 주장하지 않는다.

- 작성 중 입력은 앱 layout 메모리로 보존한다. 대화 기록은 현재 화면에서만 유지하며 이동·새로고침·새 대화로 사라진다. 입력도 새로고침·새 대화·해당 질문 전송 성공 시 지운다.
- 입력창의 문서 등록과 전용 모달·상태·스타일을 제거했다. 문서 작성은 기존 관리 페이지의 새 초안에서 수행한다. 공유 편집기·문서 API·게시 동작은 유지한다.
- 대화나 진행 요청이 있을 때 문서 관리로 일반 같은 탭 이동하면 기록 소실·요청 취소를 확인한다. 취소는 대화·요청을 유지하고 확인은 기존 unmount 정리를 사용한다. 입력만 있으면 바로 이동한다. Ctrl/Cmd 등 수정 클릭은 기본 동작을 유지한다.
- 전송 최소 높이44px·좌우padding12px, 입력창padding16px, 컨트롤radius10px·표면18px·칩pill을 적용했다. 헤더 링크/버튼 내부 정렬·상태 피드백을 통일하고 말풍선 비대칭은 예외로 유지한다.

## 검증 근거와 한계

- 이동 정책 RED에서 취소 관련2개 assertion 실패를 확인한 뒤 구현했다. 집중4개 및 기존 테스트를 합쳐 웹63개 통과.
- 웹 lint·typecheck·정적 build·git diff 검사 통과.5개 화면 크기와31개 브라우저 assertion을 확인했다.
- 모의 질문5회·문서 쓰기0회로 빈 입력·대기·실패·재시도·긴 대화·IME·줄바꿈·이동 확인·새 대화·입력 보존을 검사했다. 별도 터치 에뮬레이션에서 Enter 줄바꿈·전송 tap 모의1회, reduced-motion0s를 확인했다.
- 비활성 새 대화의 기본/hover/active 배경 유지, 전송 hover/active의 전용색을 실측했다.
- 실제 네이티브 확인창 출현을 확인했으며 반복 자동 검사는 confirm 응답을 대체했다. 테스트가 실제 Next 이동·상태 처리를 통과하는지 확인했다.
- 별도 기능·시각 검토자가 재검수했다. 전송 색상 지적을 수정하고 disabled/reduced-motion 증거를 보완한 뒤 추가 중대 발견 없음 확인.
- 실모델·문서 쓰기·실기기 가상 키보드·스크린리더는 미검증이다. 모의 응답과 터치 에뮬레이션을 실제 품질·실기기 검증으로 표현하지 않는다.

## 게시 범위

입력 보존은 이번 UI의 선행 의존성이므로 별도 기능 커밋으로 포함했다. 채팅 반응형 헤더도 함께 게시한다. 기존 문서 모달 공통 스타일·홈페이지·문서 초기화·생성 실험·서버 수정은 제외했다. 제거한 등록창의 미커밋 원문은 로컬 검증 폴더에 보존했다. 데이터·모델·실제 환경 파일은 게시하지 않는다. 과거 일지는 유지하고 새 개인 일지로 기록한다.
