# TPS 기록 정리와 GPT-6 Luna 비교

2026-10-15. 사용자가 TPS 개선 문서·일지 작성과 GPT-6 Luna 설정, 실제 응답 비교를 통한 프롬프트 원인 판별을 요청했다. AI가 설정·실험·검증·문서화를 위임받았다.

## TPS 기록

재현 가능한 설정은 [생성 실행 설정](../generation-runtime.md)을 기준으로 정리했다. [이전 실측 일지](2026-10-15-generation-tps-quality.md)와 로컬 `tmp/generation-tps-quality-20261015/`에 F16/Q4 조건, 생성TPS 약1.2~1.3→18.5, 첫 입력 지연·GPU배치·품질 한계를 보존한다. Notion 개인 일지의 이전 기록도 유지한다.

## GPT 설정과 검증 경계

공식 문서에서 실제 모델 ID `gpt-6-luna`, Chat Completions 지원, reasoning none과 temperature 조합을 확인했다. 기존 출력 한도 미연결을 max_completion_tokens 전달로 연결하고 reasoning_effort·temperature를 설정·CLI·기록 복원에 추가했다. 구버전 기록의 누락 필드는 None으로 복원한다. OpenAI context_window 요청은 계속 거부한다. Ollama의 reasoning_effort 및 명시적 추론 활성화+temperature 조합은 입력 검증에서 거부한다.

초기 로컬 `.env` 키는 모델 조회에서401 invalid_api_key였다. 키 값·원문 오류는 저장하지 않았고, 사용자가 로컬 키를 교체한 뒤 같은 모델 접근 성공을 확인했다. 인증 성공은 답변 품질 성공과 구분한다.

프로필은 timeout180초, 출력1024, reasoning_effort=none, temperature0다. Qwen 비추론 baseline과 먼저 비교하려는 조건이며 GPT의 추론 활성화 성능 전체를 대표하지 않는다. 프롬프트만의 JSON 계약을 비교하므로 JSON 강제 응답 형식은 추가하지 않았다.

## 비교 설계

로컬 `tmp/generation-openai-comparison-20261015/compare.py`에서 기존 Qwen5문항과 2문항×4조건의8건, 총13개 입력을 재구성한다. 문서 목록 SHA-256, system/user SHA-256이 이전 기록과 정확히 같은지 확인한 뒤 API를 호출한다. 원문·상태·사용량·제공자 메타데이터·시간을 보존하고 구조 상태와 품질 판정을 분리한다.

질문은 급여계좌, VPN 승인 확인, 거래처 계좌 정정, 영수증 분실, 보안 신고다. 조건은 전체71문서/수동 관련subset과 기존/강화 system의 교차다. 기존 Qwen은 seed42를 지정했지만 OpenAI에는 seed를 강제하지 않았다. 모델별 토크나이저·런타임이 다르므로 동일 문자열이 동일 토큰 수는 아니다. 단일 작은 표본으로 전체 정확도나 프롬프트의 보편적 적합성을 판정하지 않는다.

GPT가 기존 prompt에서 Qwen의 오류를 피한다면 prompt만이 원인이라는 설명은 약해진다. GPT에서도 같은 오류가 반복되면 문서 범위·지시·평가 기준을 함께 점검한다. GPT의 기존/강화 비교로 강화 규칙의 이득과 퇴행을 확인한다. 두 모델 모두 답변이 좋아져도 입력에 필요한 정책이 없는 사실은 바뀌지 않는다.

## 실제 응답 비교 결과

13회 모두 completed/stop이며 추론 토큰은0이었다. 고유 질문은5개이고, 나머지8회는 그중2개 질문의 조건 비교다. 전체 호출 시간 합37.52초, 중앙값2.71초, 첫5건 합16.06초였다. Qwen의 대응 첫5건은149.58초였다. 출력 길이·토크나이저·API 캐시·런타임이 달라 이를 순수 생성TPS 개선 배수로 해석하지 않는다. GPT API에서는 Ollama의 eval_duration에 해당하는 순수 생성 시간을 확인하지 않았다.

| 질문 | Qwen 관측 | GPT 기존 프롬프트 관측 |
|---|---|---|
| 급여 계좌 | 없는 수정 메뉴, 퇴사 정책 전용 | 변경 메뉴·마감은 문서에 없다고 유보, 일반 인사 문의 안내 |
| VPN 승인 | 자료 부족 유보 | 유보하면서 IT팀에 조회 경로 존재 여부 문의 안내 |
| 거래처 계좌 | 자료 부족 안내, 실행 한계 안내 부족 | 직접 조회·변경 불가 명시. 다만 경비 신청 번호 절차를 거래처 지급으로 확장 |
| 출장 영수증 | 지출 불명으로 해석, 반려 요청으로 절차 반전 | 분실 사실 표시·대체 증빙·같은 신청 건 보완을 연결 |
| 보안 신고 | 인지 후30분을 신고 후30분으로 변경 | 해당 시간 오류 없음. 조회 권한·비상경로 조건·목표의 수식 범위는 여전히 부정확 |

독립 AI 검토와 통합 검토에서 다음 잔여 문제를 확인했다. 사람 승인이나 자동 정확도 점수는 아니다.

- RQ0006: ieum-019의 기존 신청 번호 문의는 개인 선결제 경비 정산 범위다. 거래처 재지급에도 같은 구조가 있다고 확정할 수 없다. 해당 절차를 안내하려면 “경비 정산 신청의 계좌 오류라면”이라는 적용 조건이 필요하다.
- RQ0009: ieum-035/058의 담당자 기록 의무를 신고자의 조회 가능 화면으로 확장했다. 기록이 있다는 것과 사용자 접근 권한은 다르다. 비상연락카드는 Slack과 포털 **모두** 실패한 조건을 보존해야 한다. 목표는15분 내 인수 시간이며 담당자·연락 경로·시각 기록 자체를 목표로 완화하면 안 된다.
- RQ0001 oracle-strong: 메뉴·기한 유보는 적절하지만 People팀의 퇴사 정산 개인 기록 안내를 일반 급여·정산 전체로 넓혔다. 일반 인사 문의 창구 제안과 확정된 업무 책임을 구분해야 한다.
- RQ0007 oracle-strong: 일반 제출목록의 영수증은 분실 상황에서 대체 증빙과 연결해 표현하면 더 명확하다. 중요한 절차 반전은 관측되지 않았다.

## 판별과 다음 설계

**프롬프트만의 문제라는 설명은 지지되지 않는다.** 동일한 기존 프롬프트·전체71문서에서도 GPT가 Qwen의 핵심 오류를 피했다. 현재 Qwen 모델·실행 구성의 근거 해석 및 지시 준수 차이가 중요한 원인 후보다. 다만 모델 크기, 가중치 양자화, KV 양자화, 토크나이저와 실행 환경의 영향을 각각 분리한 실험은 아니다.

강화 프롬프트가 항상 개선을 보장하지도 않았다. GPT oracle-strong에도 업무 범위 확장이 남았다. 따라서 LangChain 구조를 새로 만들거나 프롬프트를 길게 추가하는 것을 우선하지 않는다. 현재 공통 프롬프트와 경로는 유지한다. 다음 제안은 다음과 같다.

1. 질문별 답변 가능성, 필수 주장, 금지 추론, 업무 적용 범위를 고정한 평가 기준을 만든다. GPT 출력도 정답으로 자동 채택하지 않는다.
2. 업무 범위·목표/의무·기록/조회 권한·대체 경로 조건을 정확히 보존하는 최소 프롬프트 수정안을 별도 비교한다.
3. 문서 선택이나 근거 추출을 붙일 때 이 기준으로 검색 누락과 생성 오류를 분리한다. 새 문서 추가는 새 snapshot/hash와 입력 예산·품질 회귀 검사를 수반한다.

## 검증과 보존

생성 관련149개 테스트, 전체 Ruff check,197개 파일 format check를 통과했다. 정규 `python -m generation` CLI도 별도로71문서를 입력해 exit0/completed/stop을 확인했다. 이 추가 호출은13건 비교 집계에 넣지 않았다. 키 값은 기록하지 않았다.

`tmp/generation-openai-comparison-20261015/summary.json`에 집계, `comparison.md`에13쌍 원문, `quality-review.md`에 근거별 검토, `run-01/runs.jsonl`에 원응답·사용량·시간·해시, `cli-result.json`에 실제 CLI 결과를 보존한다. 새 변경의 커밋·푸시는 이번 요청에 포함하지 않았다.

[Notion 개인 일지](https://www.notion.so/3f905a3cdadc8146a9bbedb690ab5ecf)의 현재 다음 단계·상세 비교 기록·요약 속성을 갱신한 뒤 재조회했다.13회 비교, 첫5건16.06초, 잔여 근거 오류,149개 테스트와 로컬 산출물 경로가 저장됐음을 확인했다. 기존 학습 기록·게시 링크·진행 중 상태를 보존했다. 관련 문서 상대 링크35개와 변경 범위의 diff 공백 검사도 통과했다.
