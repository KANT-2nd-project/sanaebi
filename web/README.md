# 사내비 프런트엔드

Next.js App Router·TypeScript·Tailwind CSS 4를 사용합니다. 서비스 소개(`/`)와 질문 화면(`/chat`)을 정적 HTML로 생성합니다. 첫 화면은 인사말·입력창·예시 질문이며, 전송 후 질문과 답변을 대화 목록에 누적하고 입력창을 하단에 유지합니다. 같은 출처의 `/api/ask`에 현재 질문 하나를 전송합니다. 현재 서버는 질문을 분류해 안내를 반환하거나, 검색 경로에 게시 문서가 있을 때 LangChain의 선택된 모델로 답변을 생성합니다. 로컬 분류 모델·답변 모델 준비가 필요하며 새 경로의 브라우저 종단 검증은 별도입니다. 개발에서는 Next 개발 서버, 정적 배포에서는 프로젝트 nginx를 통해 FastAPI에 연결합니다.

## 개발

저장소 루트에서 Python·루트 실행 도구·웹 의존성을 각각 설치합니다. 루트와 `web/`의 npm 잠금 파일은 독립적으로 관리합니다. Turbopack의 root는 `web/`으로 명시해 루트 잠금 파일 추가가 웹의 모듈 탐색 범위를 바꾸지 않게 합니다.

```bash
uv sync --locked
npm ci
npm --prefix web ci
npm run dev
```

http://127.0.0.1:3000/chat 에 접속합니다. 통합 명령은 FastAPI(8000, app 변경 시 재시작)와 기존 Next 개발 실행기(3000, HMR)를 각각 실행하고 로그에 `[api]`·`[web]`을 표시합니다. Ctrl+C 또는 한쪽 프로세스 종료 시 나머지도 종료합니다. 둘 다 loopback에 바인딩합니다.

개별 개발은 저장소 루트에서 `npm run dev:api` 또는 `npm run dev:web`으로 실행합니다. 기존 `web/`의 `npm run dev -- --hostname 127.0.0.1 --port 3000`도 유지합니다. 웹 실행기는 API 캐시 처리를 포함하므로 `npx next dev`로 우회하지 않습니다.

웹의 `/api/*` 요청은 FastAPI로 중계하므로 개발에는 nginx가 필요하지 않습니다. 화면과 정적 빌드는 FastAPI 없이 사용할 수 있습니다. 실제 질문 답변에는 저장된 분류 모델과 선택한 답변 모델이 필요합니다. 생성은 최종 GPT-6 Luna이며 실행 환경에 OPENAI_API_KEY가 필요합니다. 통합 명령은 의존성 설치·학습·모델 다운로드를 수행하지 않습니다. 모델 준비 기준은 [서버 준비 안내](../app/README.md#실행-준비와-api-확인)를 확인합니다. 새 환경의 문서 DB는 [초기 구성](../docs/document-management.md#새-환경의-db-최초-구성) 절차로 준비합니다. 폰트는 시스템 한국어 글꼴을 사용합니다.

### 실행 문제 확인

- 3000·8000 포트가 사용 중이면 해당 서버를 실행한 터미널에서 종료한 뒤 다시 실행합니다. 통합 명령은 기존 프로세스를 임의로 종료하거나 포트를 자동 변경하지 않습니다.
- 웹은 열리지만 초기 API 요청이 실패하면 `[api]` 시작 완료를 확인합니다. 동시 실행이 두 서버의 준비 완료를 보장하지는 않습니다.
- `uv`·`npm`을 찾지 못하거나 의존성이 없으면 도구 설치와 위 최초 설치 명령을 확인합니다.
- API 503은 분류 모델 누락, 502는 답변 모델 호출 실패일 수 있습니다. 포트가 열렸다는 사실과 실제 모델 답변 성공을 구분합니다.

## 검증과 빌드

아래 명령은 `web/` 디렉터리에서 실행합니다.

```bash
npm run lint
npm run typecheck
npm test
npm run build
```

타입 검사는 `next typegen`으로 라우트 타입을 생성한 뒤 `tsc --noEmit`을 실행합니다. 빌드는 `output: "export"` 설정으로 `out/`에 정적 파일을 생성합니다.

- `out/index.html`: 소개 화면
- `out/chat.html`: 질문 화면
- `out/404.html`: 없는 페이지 안내
- `out/_next/`: CSS·JavaScript 등 정적 자산

`out/` 전체를 정적 웹 서버에 전달합니다. 운영에 `next dev`나 `next start`를 사용하지 않으며 start 스크립트는 제공하지 않습니다. 프로젝트 nginx 설정은 `/chat`을 `chat.html`에 연결하고 존재하지 않는 경로는 404로 처리합니다. 설치·실행·종료·장애 확인은 [로컬 nginx 안내](../deployment/local-nginx.md)를 따릅니다.

개발·시연 단계이므로 소개·채팅·문서 관리 화면 모두 noindex를 유지합니다. noindex는 인증이나 접근 권한 검사를 대신하지 않습니다. 자세한 방향은 [프런트엔드 설계](../docs/frontend-architecture.md)를 참고하세요.

## 질문 요청과 테스트

성공 답변은 Markdown으로 표시합니다. 강조·제목(h3 이하)·문단·목록·인용·코드·표·취소선·읽기 전용 체크 목록을 지원하고 일반 줄바꿈도 유지합니다. 사용자 질문·오류·대기 안내는 일반 텍스트입니다. 표와 코드 블록은 내부 가로 스크롤 및 키보드 접근을 제공합니다. 원시 HTML은 무시하고 이미지는 대체 텍스트만 표시합니다. 절대 HTTP/HTTPS 링크만 새 탭으로 열며 다른 링크는 텍스트로 남깁니다. 새 탭 안내와 `noopener noreferrer`를 적용합니다. Markdown은 표시 규칙이며 링크나 답변 내용의 사실성을 보증하지 않습니다. 서버 응답·저장 문자열은 변경하지 않습니다.


헤더의 **사용 안내**는 대화 영역과 분리된 모달을 엽니다. 질문 가능한 내용·질문 예시·대화와 입력의 유지 범위를 안내하며 닫기 버튼·Esc 또는 모달 바깥 배경 클릭으로 닫습니다. 모달 내부 클릭이나 내부에서 시작한 드래그로는 닫히지 않습니다. 이전 메시지 미반영과 입력 보존 안내는 모달에 통합하며 입력창 하단에 중복 표시하지 않습니다. 열면 제목에 포커스를 두고 Tab 탐색을 모달 안에 유지하며, 닫으면 사용 안내 버튼으로 돌아갑니다. 안내를 여닫아도 대화·작성 입력·진행 요청은 유지됩니다. 안내가 열린 동안 도착한 응답은 정상 반영하고 기존 응답 스크롤 정책을 따릅니다. 별도 `/guide` 페이지는 추가하지 않습니다.


대화는 현재 화면의 메모리에서만 유지됩니다. 새로고침·새 대화 시 초기화되며 서버는 이전 메시지를 참조하지 않습니다. 실제 신청·승인·개인 기록 조회는 지원하지 않습니다.

- 데스크톱: Enter 전송, Shift+Enter 줄바꿈. IME 조합 중 Enter·키 반복은 전송하지 않습니다.
- 모바일 주 입력 장치(`hover:none`과 `pointer:coarse`): Enter 줄바꿈, 버튼 전송.
- 예시 선택은 입력과 포커스만 옮깁니다. 입력창은 2행부터 200px까지 늘어납니다.
- 요청 중 입력을 읽기 전용으로 보존합니다. 성공 시 제출 입력을 비우고, 실패 시 보존합니다. 수정하지 않은 실패 질문은 같은 턴에서 재시도하고 수정한 질문은 새 턴으로 추가합니다. 메시지 재시도 버튼은 다른 작성 중 입력을 지우지 않습니다.
- 새 대화는 요청을 취소하며 늦은 응답을 무시합니다. 위쪽 기록을 읽고 있으면 응답 도착 시 스크롤을 강제로 옮기지 않습니다.

입력 앞뒤 공백을 제거한 `{question}`만 POST로 전송합니다. 브라우저 답변 대기는 240초이며 자동 재시도하지 않습니다. 개발 프록시 제한은 210초입니다. 정적 배포의 nginx 연결 제한은 5초, 읽기 제한은 210초입니다. 개발 프록시 자체 연결 실패·시간 초과는 500, nginx는 502/504일 수 있으며 화면은 안전한 오류 안내와 입력 보존으로 처리합니다. 모델 호출 timeout은 180초입니다. 이 값들은 전체 요청 시간의 보장이 아닙니다. 503은 서버의 안전한 분류·문서 장애 안내를 표시합니다. 취소·입력 보존·늦은 응답 무시·수동 재시도는 유지하며 브라우저 취소가 서버의 모델 실행 종료를 보장하지는 않습니다.

`npm test`는 기존 TypeScript 컴파일러로 API 경계와 대화 상태 코드를 저장소의 `tmp/frontend-unit-tests/`에 컴파일한 뒤 Node 내장 테스트 러너를 실행합니다. 별도 패키지를 추가하지 않으며 Node 22 이상을 사용합니다. 테스트는 fetch/전송 함수를 대체하여 오류·timeout·취소·메시지 누적·재시도·늦은 응답 무시를 검증합니다. 실제 통합은 빌드 후 nginx→FastAPI에서 별도로 확인합니다.

`web/`의 `npm run dev`는 개발 전용 실행기 `scripts/dev.mjs`를 사용합니다. Next의 외부 rewrite에서는 설정의 headers가 누락되는 설치 버전 동작 때문에 실행기가 `/api/` 응답의 `Cache-Control: no-store`를 보장합니다. FastAPI의 상태·본문을 유지하고 upstream 캐시 헤더는 덮어씁니다. 운영용 Node 서버로 사용하지 않습니다. `npm run dev -- --hostname 127.0.0.1 --port 3000`으로 바인딩을 지정할 수 있습니다. 기본값은 기존 Next dev와 같은 전체 인터페이스·3000번입니다.

개발 시 오래된 CSS 복원을 막기 위해 Turbopack 개발 파일시스템 캐시를 비활성화합니다. HMR과 정적 빌드 캐시는 유지합니다. Tailwind 로더 앞의 `scripts/tailwind-loader.cjs`는 실제 CSS 입력의 해시를 컴파일 캐시 키에 포함해, 같은 파일에서 수정한 CSS를 이전 결과로 바꾸는 문제를 방지합니다. 설치된 Tailwind 로더와 버전은 그대로 사용합니다. CSS가 갱신되지 않으면 실행 경로와 제공 CSS를 먼저 확인하고, 서버 종료 후 `.next/dev`를 `tmp`로 백업 이동해 재시작합니다. 설정이나 실행기 파일 변경은 개발 서버를 재시작하고, 화면·CSS 변경은 HMR로 확인합니다. `npx next dev`로 실행기를 우회하면 API 응답 캐시 정책이 보장되지 않으므로 `npm run dev`를 사용하세요.

각 실행 터미널에서 Ctrl+C로 개발 서버와 FastAPI를 종료합니다. 정적 nginx 화면은 `npm run build`로 갱신합니다. 8080번 배포 절차는 기존 nginx 안내를 따르며 nginx의 개발 서버/HMR 중계는 추가하지 않습니다.

## 문서 관리

제목과 상태는 검색 버튼 또는 Enter로 함께 적용합니다. 검색 대상은 초안 제목이며 목록은 게시 제목과 변경된 초안 제목을 구분합니다. 적용 조건·결과 수는 목록 위, 페이지 이동은 아래에서 확인합니다. 자세한 기준은 [찾기·읽기·편집](../docs/document-management.md#찾기읽기편집)을 따릅니다.

`/admin/documents`에서 문서 초안·개정·게시·사용 중단을 관리합니다. 문서 작성은 이 페이지의 ‘새 문서 초안’에서 시작합니다. 채팅 입력창은 질문 전송만 제공합니다. 대화가 있거나 답변 요청 중 문서 관리로 이동하면 기록 소실·요청 취소를 확인하며, 취소하면 현재 대화를 유지합니다. 작성 중 질문만 있으면 확인 없이 이동하고 앱 내부 복귀 시 입력을 복원합니다. Ctrl/Cmd 클릭 등 새 탭 열기는 브라우저 기본 동작을 유지합니다. 현재 유효한 게시본은 다음 검색 질문부터 답변 입력에 사용합니다. 초안·중단·미래 시행 문서는 제외합니다. [계약과 제한](../docs/document-management.md)을 확인하세요.

문서 본문은 채팅과 같은 Markdown으로 표시합니다. 작성·편집 화면은 최대 1600px로 넓히고, 1024px 이상에서 제목·원문과 실시간 미리보기를 나란히, 좁은 화면에서 탭으로 제공합니다. 서식 도구로 제목·강조·목록·인용·링크·코드를 넣을 수 있으며 저장되는 내용은 Markdown 원문입니다.

목록 제목은 게시본 우선 읽기 화면으로 이동합니다. ‘초안 편집’ → 저장 → 저장된 초안 검토 → 게시 순서로 사용합니다. 읽을 개정의 본문과 검수 상태를 함께 표시하며 수정 중에도 기존 게시본은 유지됩니다. URL에 검색·필터·페이지·선택 문서·읽기/편집 상태를 보존합니다. 모바일은 세로 목록이며 저장 버튼은 일반 문서 흐름에 둡니다. 충돌 시 내 입력을 복사·보존하고 서버 최신본을 별도로 확인할 수 있습니다. 최신본 조회에 실패하면 입력을 유지한 채 조회만 다시 시도합니다. 자세한 화면 동작은 [문서 관리 안내](../docs/document-management.md#찾기읽기편집)를 따릅니다.

이 기능은 로컬 시연용입니다. 저장소 루트의 `npm run dev`는 개발 서버와 FastAPI를 모두 loopback에 바인딩합니다. 정적 빌드에는 `out/admin/documents.html`이 포함되지만 실제 본문은 포함하지 않습니다. 문서 API는 `/api/documents`이며 정상·오류 응답은 no-store입니다. 미저장 내용은 새로고침 시 사라집니다.

2026-10-14 SQLite 전환 당시에는 분류 모델 파일 부재로 `/ask`가 503을 반환했고, 독립 Ollama 검사에서는 전체 문서 입력이 설정 한도를 초과했습니다. 이는 당시 환경의 기록입니다. 현재 모델·문서·제공자 준비와 API 확인은 [서버 안내](../app/README.md#실행-준비와-api-확인)를 따르며, 새 환경의 브라우저 답변 성공을 과거 기록으로 대신하지 않습니다. [전환·검증 기록](../docs/worklogs/2026-10-14-sqlite-documents.md)을 참고하세요.

### 문서 전체 관리

문서 목록 아래에서 **모든 문서 삭제** 또는 **기본 문서 세팅 및 초기화**를 실행한다. 검색 결과가 아닌 전체 문서가 대상이며 확인창의 건수·백업 여부를 확인하고 지정 문구를 입력한다. 삭제는 새 백업을 만들지 않고 복원은 백업 후 기본 문서를 게시한다. 처리 중에는 닫기·이동·다른 쓰기를 차단한다. 성공하면 검색 조건과 목록을 초기화하고, 통신 실패는 같은 키로 수동 재확인한다. 자정 예약은 유지되며 임베딩 초기화는 포함하지 않는다. 공개 실행 범위와 API·보존 기준은 [문서 전체 관리](../docs/document-management.md#문서-전체-관리)를 따른다.
