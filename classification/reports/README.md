# 분류 실험 보고서

모델 비교의 목적·조건·결과·해석·결정을 관리하는 공식 기록이다. 실행 방법은 [분류 안내](../README.md), 상세 실행 기록은 로컬 MLflow와 각 실험의 artifact-root에서 확인한다.

## 실험 목록과 현재 판단

| 날짜 | 실험 | 확인한 범위 | 판단 |
|---|---|---|---|
| 2026-10-14 | [로컬 모델 6종 비교](2026-10-14-model-comparison/README.md) | 실제 학습 6회·validation/test 평가 12회 | Validation 최고 3종 동점. 최종 모델 선정 보류 |

최신 비교에서 KoELECTRA base는 개발 test 135건을 모두 맞혔고, validation 동점 모델 중 RoBERTa small은 속도·크기에서 유리했다. 상세 조건과 한계는 위 보고서를 따른다. 현재 test는 이미 열람한 합성 개발 자료이며 독립적인 최종 서비스 평가가 아니다. 실험 결과와 서버에 실제 연결한 모델은 별도로 판단한다.

## 작성 규칙

- 여러 run이 하나의 비교 질문에 답하면 보고서 한 편으로 묶는다. 모든 실행마다 새 문서를 만들지 않는다.
- 폴더는 `YYYY-MM-DD-실험주제/`, 본문은 `README.md`, 작은 비교 수치는 `comparison.csv`로 둔다. 같은 날짜에 다른 실험이면 주제로 구분한다.
- 본문은 목적 → 실행 조건 → 비교 결과 → 라벨별 지표·오분류 → 해석·결정 → 원자료 접근 방법 순서로 쓴다. 사실·원인 가설·미검증 사항을 구분한다.
- 코드 버전·데이터 SHA·분할 ID와 수량·seed·후보/선택 설정·측정 조건을 적는다. 모델별 model_id·학습/평가 run ID와 artifact-root를 연결한다.
- 비교표는 저장된 지표·예측과 대조하고, 서로 다른 데이터·분할·측정 조건을 같은 순위로 묶지 않는다. 기본 비교는 validation이다.
- Git에는 판단에 필요한 요약·작은 표·선별 또는 전체 오분류를 보관한다. 전체 trial·환경·예측 원자료, 가중치·SQLite·로그는 기존 MLflow와 artifacts에 둔다.
- 로컬 경로와 localhost UI는 팀원에게 자동 공유되지 않는다. 공개 다운로드 링크처럼 표시하지 않고 보관 위치·접근 명령을 안내한다.
- 게시된 실험은 새 실험 결과로 덮어쓰지 않는다. 오류 정정 시 정정 내용·근거를 남기고, 후속 실험은 별도 항목으로 연결한다.
- Notion에는 결정·진행 요약과 게시된 Git 보고서 링크를 둔다. 작업 경위는 개인 일지에 남기고 성능 수치를 여러 문서에 반복 관리하지 않는다.
