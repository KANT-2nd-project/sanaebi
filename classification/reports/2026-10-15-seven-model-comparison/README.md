- 데이터 SHA-256: `a7d65d3556899a529278f69d5e4d177722fc73fa71c23bbfc006149b0c551c98`.
- 로컬 모델: train 학습, validation Macro-F1으로 후보·epoch 선택, 동점 첫 상태 유지. test로 후보를 재선택하지 않았다.
- Transformer 5종은 학습률 2e-5·5e-5, 후보당 3 epoch, 길이 256, batch 4. TF-IDF는 char 2~5gram과 C=[0.1, 0.5, 1, 10]. 이 탐색 예산 안의 비교다.
- 중단 전에 완료된 5종은 재학습하지 않았다. 중단된 KoELECTRA base만 처음부터 다시 학습했다. 재개 시 CPU로 시작했으나 GPU가 확보되어 GPU로 재시작했다. 미완료 시도의 로그는 모두 보존했다.
- Jev는 학습 없이 기존 train 예시 12개와 고정 프롬프트로 268회 요청했다. 완료된 응답을 재사용했으며 통합 보고서를 위해 API를 추가 호출하지 않았다. 요청 jev-latest, 응답 버전은 Jev 상세 보고서에 기록했다.
- 모든 데이터는 합성이고 test는 이미 열람한 개발 자료다. Jev 프롬프트 설계에는 전체 데이터 열람 이력도 있어 학습·노출 조건이 완전히 동일한 통제 실험은 아니다.
- 코드·라이브러리·revision·model_id·선택 설정·trial은 [로컬 상세 보고서](../2026-10-15-learning-model-comparison/README.md)와 [Jev 상세 보고서](../2026-10-15-jev-evaluation/README.md)에서 관리한다. 이번 로컬 구현에는 MLflow run이 없고 Jev만 보존된 경로의 MLflow에 기록했다.

## 해석·결정

- 이번 탐색에서 validation 최고는 **roberta_base** (Macro-F1 1.000000)다. 이 점수는 선택에 사용한 자료의 점수다.
- 모델 크기가 크거나 학습률이 높다고 항상 유리하지 않았다. 예를 들어 RoBERTa base의 높은 학습률 후보는 낮은 validation 점수를 기록했으며, 최종 저장본은 앞선 최고 checkpoint다.
- 최종 서비스 모델 선정은 보류한다. 작은 단일 합성 분할의 결과이며 실제 질문·경계 질문의 별도 검수가 필요하다. 모델 간 작은 점수 차이에 통계적 우열을 주장하지 않는다.
- 다음 순서: 오분류·경계 질문 검수 → 별도 평가 자료 확보 → 후보별 추가 실험 → 속도·오류 비용을 포함한 모델 선정 → 서버 연결. 기존 서비스 모델은 교체하지 않았다.
